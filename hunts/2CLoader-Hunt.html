Executive Summary

2CLoader is a credential-theft delivery mechanism, not an end-goal payload. Its entire feature set exists to get Vidar, Remus, and XWorm onto a real victim machine undetected, then get out of the way. The loader stores its configuration and payload inside a Windows PE resource, decrypts that resource only after an eleven-factor environment score and a hard-fail VM/debugger/sandbox check both pass, then executes the decrypted payload via in-memory manual mapping (LoadPE), CLR hosting of a .NET assembly, or process hollowing into a suspended dllhost.exe. It persists under the literal name SecurityHealthService.exe, reused unchanged across the Run key, the RunOnce key, the Startup folder, a logon-triggered scheduled task, the Windows Load registry value, or a logon script, and it reports home over HTTP POST to aware-cr1[.]com/api/beacon with XOR-encrypted JSON status messages.

The highest-value defensive angle is not the evasion logic itself: racing a sandbox-detection scoring model is a contest defenders lose on a long enough timeline, and 2CLoader's indirect-syscall and anti-analysis layers leave no telemetry in standard Falcon event streams. What does leave telemetry, and does so on every single sample regardless of which anti-analysis branch it takes, is the fixed artifact set reporting has already confirmed: the string SecurityHealthService.exe appearing outside its real %SystemRoot%\System32\ location, and a dllhost.exe process missing the COM surrogate's mandatory /Processid: argument. Both are cheap, low-noise, high-fidelity hunts that do not depend on catching the loader's encryption chain or its syscall evasion.

Defender priority: hunt the SecurityHealthService.exe-outside-System32 pattern and the argument-less dllhost.exe pattern first (§8 Q1, Q2, Q4, Q6). These catch 2CLoader regardless of which infostealer or RAT it is staging to deliver that week, and they do not depend on the current, perishable C2 domain or sample hash set.

Decisions and provenance notes

Every technical detail in this pack traces to the Zscaler ThreatLabz primary research post. Cyber Security News and GBHackers both state the report was "shared with" them by Zscaler, meaning they independently fetched and republished Zscaler's own findings rather than performing independent reverse engineering. Strictly speaking, the loader's internal mechanics (config structure, encryption chain, hook targets) and its atomic IOCs have one originating source, not two. This pack ships the 20 SHA-256 hashes and both network indicators at prevent/high-or-critical severity on the practical basis that: (1) two independently-operated outlets each fetched and republished the identical indicator values from Zscaler, reducing transcription-error risk, and (2) Broadcom/Symantec, a fully independent vendor with its own telemetry, confirms the malware family's existence and general behavior (though it publishes no atomic values of its own to cross-check against). This nuance is called out here rather than glossed over; treat the atomic IOCs as single-origin, multiply-confirmed, not as independently discovered by three separate research teams.

All four fetched sources were saved verbatim to 2CLoader-Hunt-sources/ before this pack was built. No fetched source contained instructions directed at the research agent; all four were treated as data.

Native Audit-Log Hunts

These checks cover the parts of the attack chain that Falcon CQL cannot see directly (no raw syscall field, no generic file-create field verified against this skill's Falcon reference set). They require Sysmon or native Windows auditing in addition to the Falcon sensor.

1. Lock-file artifact (Sysmon EventID 11 — FileCreate)

Field: TargetFilename
Pattern: C:\Users\*\AppData\Local\Temp\aw_[0-9a-f]{32}\.lk
Notes: opt_flag 0x100 creates this file with FILE_FLAG_DELETE_ON_CLOSE as a
single-instance mutex. The file is normally gone by the time an analyst
looks, so alert on CREATE, not on current presence.

2. .NET CLR module load into a non-.NET host (Sysmon EventID 7 — ImageLoad)

Field: ImageLoaded
Pattern: ...\mscoree.dll OR ...\clr.dll OR ...\clrjit.dll
Exclude: parent/host process already known to be a .NET application
Cross-reference against CQL Q10 (§8) which performs the same hunt on
Falcon's ImageHash event for hosts where Sysmon is not deployed.

3. Scheduled task creation (Windows Security EventID 4698 / 4702)

Field: TaskName
Pattern: SecurityHealthService.exe (or SecurityHealthService)
Notes: complements Falcon's ScheduledTaskRegistered event (CQL Q2); use
this where Advanced Audit Policy is enabled but the Falcon sensor is not
yet deployed or is in a degraded state.

4. dllhost.exe process creation without /Processid: (Windows Security EventID 4688)

Field: NewProcessName, CommandLine
Pattern: NewProcessName ends \dllhost.exe AND CommandLine does not contain
"/Processid:"
Prerequisite: "Include command line in process creation events" GPO must
be enabled (Computer Configuration > Administrative Templates > System >
Audit Process Creation), or CommandLine will be blank in the event.

Pick your tenant's cloud first — every "Open in Falcon" button below uses this selection.
Q1 · Run/RunOnce Persistence Masquerading as SecurityHealthService.exe
CONF HIGHFP LOWCOST LOW

Looks for: a Run or RunOnce registry value literally named SecurityHealthService.exe pointing somewhere other than the real System32 binary. FP: near zero — the exact value name colliding with an unrelated legitimate application is rare, and the real Windows binary is explicitly excluded.

// HUNT: Run/RunOnce persistence masquerading as SecurityHealthService.exe
// MITRE: T1547.001
// CONF: high
// FP: low
// COST: low
// REQUIRES: AsepValueUpdate or RegGenericValueUpdate telemetry (registry monitoring enabled)
// FALSE POSITIVES: third-party software coincidentally reusing the exact value name (not observed)
#event_simpleName=/AsepValueUpdate|RegGenericValueUpdate/
| RegObjectName = /\\Microsoft\\Windows\\CurrentVersion\\(Run|RunOnce)$/i
| RegValueName = /^SecurityHealthService\.exe$/i
| RegStringValue != /\\Windows\\System32\\SecurityHealthService\.exe$/i
| table([@timestamp, ComputerName, UserName, RegObjectName, RegValueName, RegStringValue])

Q8 · Behavioral C2 Beaconing Cadence (Domain/IP-Agnostic)
CONF MEDIUMFP MEDIUMCOST MEDIUM

Looks for: host/destination pairs connecting on a regular 5-minute cadence for over an hour with a low per-bucket connection count, a shape consistent with 2CLoader's periodic HTTP POST status beacon, regardless of which IP it is currently using. FP: medium — legitimate SaaS sync/telemetry clients poll on similar cadences; tune with the ContextBaseFileName projection.

// HUNT: Periodic beaconing consistent with 2CLoader's HTTP POST status reporting
// MITRE: T1071.001, T1132.002
// CONF: medium
// FP: medium
// COST: medium
// REQUIRES: NetworkConnectIP4 telemetry
// FALSE POSITIVES: legitimate cloud-sync, telemetry, or EDR-agent callback traffic with similar polling cadence
// TUNING: exclude known-benign ContextBaseFileName values (sync clients, update agents, the EDR sensor itself) after baselining; raise BucketsActive / lower AvgConnsPerBucket thresholds to fit environment norms
// LOOKBACK: 7d -- set the window with the console time picker
#event_simpleName=NetworkConnectIP4
| !cidr(RemoteAddressIP4, subnet="10.0.0.0/8")
| !cidr(RemoteAddressIP4, subnet="172.16.0.0/12")
| !cidr(RemoteAddressIP4, subnet="192.168.0.0/16")

Hardening — Tiered

Immediate (this week)
  • Enable the LSASS-credential-theft ASR rule in Block mode (GUID 9E6C4E1F-7D60-472F-BA1A-A39EF669E4B2) — MITRE M1040 (Behavior Prevention on Endpoint). Does not stop 2CLoader itself but blunts the downstream Vidar/Remus credential-theft impact if the loader lands. CIS Microsoft 365 Apps/Windows Benchmark, section 18.9.47, sub-rule 5.1.2 (L1, Block).
  • Enable full command-line process-creation auditing (Event 4688 with command line + Sysmon EventID 1) — MITRE M1047 (Audit). Required for Q5/Q6 hunts and the native EventID 4688 hunt in §7 to return usable data. Microsoft Security Baseline: Computer Configuration > Administrative Templates > System > Audit Process Creation > Include command line in process creation events = Enabled.
  • Set the Falcon prevention policy to full Block (ML + sensor-based detections, not Detect-only) — MITRE M1040. This is the only control in this pack that directly contests 2CLoader's Hell's Gate indirect syscalls and in-memory execution, since neither is independently huntable via CQL (see §15 gaps).
Near Term (1-4 weeks, pilot ring first)
  • AppLocker/WDAC path rule denying execution from %TEMP% and %APPDATA%\Local\Temp for unsigned binaries — MITRE M1038 (Execution Prevention). Reduces the viability of the drop-and-run pattern 2CLoader and its payloads use from temp paths. Microsoft Security Baseline AppLocker guidance; DISA STIG WN11-00-000030 (Application Control) covers the equivalent intent for government environments. Deploy in Audit mode first, confirm no legitimate workflow trips, then flip to Enforce.
  • Restrict registry write permissions on sensitive autostart keys (Run, RunOnce, the Windows NT\CurrentVersion\Windows Load value, HKCU\Environment) for standard users via GPO — MITRE M1024 (Restrict Registry Permissions). ⚠ best-practice, no single CIS benchmark line item covers this exact ACL change; it follows CIS Benchmark intent for restricting user-writable autostart locations (CIS Microsoft Windows Benchmark §18.x autostart hardening family) without a one-to-one control number.
Strategic (1-3 months)
  • Deploy Credential Guard fleet-wide (VBS-isolated LSASS) — MITRE M1025, M1043 (Privileged Process Integrity, Credential Access Protection). Blunts Vidar/Remus's ultimate objective even when 2CLoader itself succeeds in landing. CIS Microsoft Windows Benchmark, section 18.9.45, sub-rule 5.1 (L1, Enabled with UEFI lock). Pilot first: breaks some legacy SSO products and older third-party AV that hooks LSASS.
  • Egress filtering / DNS-layer blocking for newly-registered and unclassified domains — MITRE M1037 (Filter Network Traffic). Reduces C2 callout success for rotated infrastructure not yet IOC-listed, complementing the atomic domain/IP block in §10. ⚠ best-practice, no single CIS/STIG line item; follows NIST SP 800-53 SC-7 (Boundary Protection) intent.
