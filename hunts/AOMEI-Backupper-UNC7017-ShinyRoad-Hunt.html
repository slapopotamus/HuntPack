Executive Summary

Between April and July 2026 an actor tracked by Google Threat Intelligence Group and Mandiant as UNC7017 tampered with the update and notification configuration files that AOMEI Backupper and AnyViewer fetch from AOMEI infrastructure. Each tampering window lasted about 5 to 10 minutes and then reverted to authentic content, so a later check of the vendor URL shows only clean files. Any machine whose AOMEI background services polled during a window was handed a CROSSROAD downloader, which stages the SHINYROAD backdoor (a signed Radmin launcher sideloading a malicious DLL that registers a COM server hosting an embedded PocketPy interpreter). In mid-July the actor also pushed ADAPTAGENT, an Adaptix C2 agent disguised as Nitro PDF software, and added a 1x1 invisible popup that coerces WebDAV/NTLM authentication to an actor server.

No software vulnerability was exploited: the client followed its own update logic against unauthenticated remote configuration. The highest-value defensive angle is therefore endpoint lineage, not the vendor URL: an AOMEI updater process starting an executable from its own html or tmphtml directory (Q1), the two scheduled task names (Q3), the Radmin launcher with --runtimechk (Q4), and user-profile sideload drops (Q5).

Defender priority: vendor-side remediation does not clean endpoints that already ran the payload. Hunt the whole April to July 2026 period on every host that ever ran AOMEI Backupper or AnyViewer, treat WebDAV/NTLM exposure as a credential event even where no binary ran, and do not dismiss an updater-child alert because the vendor URL looks clean now.

Decisions and discrepancies

  • Independence. The Mandiant report credits ManageEngine with the initial discovery and the two vendors coordinated, so their prose overlaps. ManageEngine does carry its own endpoint telemetry and its own hash table. Only indicators that appear in both snapshots (the BlkScrDl.dll hash, the component.zip hash, and 8.218.65.184) were allowed to ship as prevent or critical; everything else is detect.
  • Domain spelling. One ManageEngine table writes the package host without the hyphen (storagedata). The Mandiant report and ManageEngine's own body text use storage-data.com. The hyphenated form is shipped; the unhyphenated variant is not.
  • Radmin location. Mandiant places the components in %LOCALAPPDATA%\Radmin\; ManageEngine records the genuine Radmin Server installer writing to a Program Files (x86) rserver30 folder. Queries match the \Radmin\ folder name and the user-profile path separately rather than assuming one.
  • Guardrails. Mandiant states CROSSROAD aborts when the country code is CN. ManageEngine adds that it also terminates when geolocation cannot be resolved and when specific endpoint security agents are present (agents not named). Only the CN rule is in the Mandiant text.
  • Technique ID. Mandiant maps DLL hijacking to T1574.001; ManageEngine uses T1574.002. This pack follows the Mandiant IDs.
  • Not shipped as indicators: the three legitimate file hashes (WinLpcDl.dll, WinLpcDl2.dll, Nitro_Scan2PDFApp.exe) are listed as context only; the benign decoy file hash is omitted; 96.126.191.98 is the IP found in the actor's allowlist file (a target filter, not shown to be actor infrastructure) and is a hunt pivot, not a block; the two declared MD5 values for the malicious archives are shipped as detect.
  • Radmin never armed. ManageEngine found Radmin Server installed without a configured address or credential and no active listener; remote access in its sample came from the implant's outbound connection. Treat Radmin presence as staging, not proof of an active Radmin session.
  • Attribution confidence. UNC7017 is an uncategorized cluster. Neither source names a nation or sponsor and this pack does not.
