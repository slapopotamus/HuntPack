Executive Summary

FBI FLASH-20261113-001 (TLP:CLEAR, 13 November 2026) describes ARTEX, an open-source, LLM-driven, multi-agent penetration-testing framework written in Go that threat actors have weaponised to automate every phase of an intrusion, from reconnaissance to data exfiltration. Since at least August 2026 a variety of malicious actors have used it against financial services, government, technology, defense, semiconductor, energy, healthcare, manufacturing, telecommunications and legal targets. Some intrusions reached privileged access in under three hours. The FLASH names two notable campaigns: financially motivated attacks on South Korean financial institutions (about 67,000 individuals) and a supply chain compromise of ConnectWise Cloud Backup customers that reached more than 2,250 downstream tenants.

Dual-use, not purpose-built malware. The original developer, "Autumn-27", released ARTEX on GitHub in July 2026 and stated it was for authorised security testing within defined scopes. The repository was made unavailable on 8 October 2026 after reports of abuse, but the framework still circulates through forks, mirrors, archives and a commercial version, ARTEX PRO. As of early November 2026 researchers counted over 1,600 publicly exposed ARTEX consoles. This pack is strictly defensive: it hunts, detects and hardens. It contains no guidance on obtaining or running ARTEX.

Scope: the net-new half. The South Korean financial campaign is already hunted in the published pack ARTEX-AI-Pentest-KoreanFinance-Hunt. This pack does not repeat it and ships none of that pack's eleven indicators. It covers the rest of the FLASH: the 14 Microsoft-sourced addresses, the FLASH's TTP table, and its Information Requested and Recommendations sections.

Honest telemetry. Most of what the FLASH describes happens in web applications, Entra and Microsoft 365, Azure and AWS control planes. The Falcon endpoint sensor sees the footprint left on hosts. This pack ships 11 endpoint hunts, 3 cloud and identity hunts that only run if those logs are ingested into NG-SIEM, and 17 native audit-log hunts for what no Falcon query can see. The most Falcon-relevant item in the whole FLASH is Q1: ARTEX agents inventoried sensor coverage to find Windows machines without CrowdStrike Falcon.

Posture. All 14 indicators ship as detect. The FLASH says to vet indicators before blocking and warns that cloud and virtualised addresses are reassigned to benign services. Nothing in this pack is set to prevent or block. api.anthropic.com, api.deepseek.com, open.bigmodel.cn and api.x.ai are legitimate vendor services, not indicators of compromise: their unexpected appearance in egress is the signal, not their existence.

Defender priority: confirm Falcon is installed on every Windows host (the framework went looking for hosts without it), review every Microsoft 365 tenant where a ConnectWise application is or was authorised (search by application ID) from 1 October 2026, restrict Kudu/SCM and other management surfaces, then run Q1, Q4, Q5 and the native hunts in section 7. Do not delete enterprise applications as a first response: preserve configuration and evidence first.

CrowdStrike LogScale CQL Hunt Queries

Fourteen CQL hunts in two groups. Every query is a hunt or a detect candidate; none is a blocking rule. Where false positives run medium or higher, the exclusion is written into the card as a // TUNING: line so it travels with the query when you copy it. Windows are set with the console time picker; each card records the intended // LOOKBACK:.

Pick your tenant's cloud first: every "Open in Falcon" button below uses this selection.

Group A: Endpoint sensor hunts (Falcon telemetry, Q1 to Q11)

Q1 · Security-software discovery: queries for the Falcon sensor or its services
CONF MEDIUMFP MEDIUMCOST LOW

Looks for: A command that names the CrowdStrike sensor or its services while using a service, WMI, registry or process enumeration verb. The FLASH says ARTEX agents inventoried endpoint sensor coverage to find Windows machines without CrowdStrike Falcon, so the footprint on a protected host is a lookup for the very thing that protects it. A repeat across many hosts from one parent is the stronger signal. FP: IT inventory and RMM scripts, sensor health checks and your own Falcon deployment audits query the same service names.

// HUNT: Security-software discovery, commands that look for the Falcon sensor or its services
// MITRE: T1518.001
// CONF: medium  FP: medium  COST: low | REQUIRES: ProcessRollup2 (process creation with command line)
// WHY: the FLASH reports ARTEX inventoried endpoint sensor coverage to find Windows machines without CrowdStrike Falcon
// FALSE POSITIVES: IT inventory, RMM scripts, sensor health checks and Falcon deployment audits query the same service names
// TUNING: exclude your RMM, SCCM, Tanium and audit-script parents; a rare parent (cmd, powershell, wsmprovhost, a web worker) querying many hosts is the signal
// LOOKBACK: 30d
#event_simpleName=/^(ProcessRollup2|SyntheticProcessRollup2)$/
| CommandLine=/(csagent|csfalconservice|csfalconcontainer|csfalcon|crowdstrike|falcon-sensor|falconsensor)/i
| CommandLine=/(\bsc(\.exe)?\s+(\\\\\S+\s+)?(query|queryex|qc)\b|Get-Service|Get-CimInstance|Get-WmiObject|\bgwmi\b|\btasklist\b|\bwmic\b|reg(\.exe)?\s+query|\bfltmc\b|Get-Process|Get-ItemProperty|Test-Path|Win32_Service|Win32_Product|AntiVirusProduct|SecurityCenter2)/i
| ParentBaseFileName!=/^(CSFalconService|CSFalconContainer|CcmExec|TaniumClient|NinjaRMMAgent)(\.exe)?$/i
| groupBy([aid, ComputerName, UserName, ParentBaseFileName], function=[count(as=Lookups), count(CommandLine, distinct=true, as=DistinctCommands), min(@timestamp, as=FirstSeen), max(@timestamp, as=LastSeen), collect([CommandLine], limit=5)], limit=5000)
| sort(Lookups, order=desc, limit=100)
Q2 · Iterative PowerShell and LDAP enumeration of Active Directory in bursts
CONF MEDIUMFP MEDIUMCOST MEDIUM

Looks for: Many distinct AD enumeration commands from one account on one host inside a five-minute bucket. The FLASH reports iterative PowerShell enumeration against domain controllers and over 110,000 AD objects enumerated. Agentic tooling produces compressed bursts of small, incrementally changing commands, so velocity separates it from a one-off admin query. FP: Directory-sync tooling, identity governance products, audit scripts and administrators running reports.

// HUNT: Iterative AD enumeration in compressed bursts (volume and velocity, not any single command)
// MITRE: T1087.002, T1059.001
// CONF: medium  FP: medium  COST: medium | REQUIRES: ProcessRollup2 (process creation with command line)
// WHY: the FLASH reports iterative PowerShell enumeration against domain controllers, over 110,000 AD objects enumerated
// FALSE POSITIVES: directory-sync and identity-governance tooling, scheduled audit scripts, administrators running reports
// TUNING: exclude known automation accounts and approved audit hosts; raise the threshold on hosts that already show a high baseline
// THRESHOLD: 15 enumeration commands in 5 minutes is a starting value; baseline over 14 days before alerting
// GAP: cmdlets run from a script file leave only the file name on the command line
// LOOKBACK: 14d
#event_simpleName=/^(ProcessRollup2|SyntheticProcessRollup2)$/
| CommandLine=/(Get-AD(User|Computer|Group|GroupMember|Object|Domain|DomainController|Trust|OrganizationalUnit|PrincipalGroupMembership)|Get-Domain(User|Computer|Group|Controller|GPO|Trust)|DirectorySearcher|System\.DirectoryServices|ADSISearcher|\[adsi\]|Search-ADAccount|-LDAPFilter|\bdsquery\b|\badfind\b|\bnltest\b|ldapsearch|net1?\s+(user|group|accounts)\s+\/domain)/i
| Bucket5m := @timestamp - (@timestamp % 300000)
| groupBy([aid, ComputerName, UserName, Bucket5m], function=[count(as=Invocations), count(CommandLine, distinct=true, as=DistinctCommands), collect([CommandLine], limit=3)], limit=20000)
| Invocations >= 15
| Window := formatTime("%Y-%m-%d %H:%M", field=Bucket5m)
| sort(Invocations, order=desc, limit=100)
Q3 · LAPS password reads and Group Policy Preferences credential hunting
CONF MEDIUMFP MEDIUMCOST LOW

Looks for: Command lines that read LAPS attributes or cmdlets, or that search SYSVOL for Group Policy Preferences files and the cpassword attribute. The FLASH lists reading LAPS passwords under internal recon, mapped to T1555 and T1552.006. FP: Help desk staff legitimately read LAPS passwords, and GPO administrators open the same SYSVOL files.

Hardening: Tiered

ARTEX compresses the time from first probe to privileged access to hours, so hardening that removes the entry points and the cheap pivots matters more than detection speed. Controls below are mined from the FLASH's own Recommendations section and the TTP table, each tied to a MITRE mitigation and a platform authority. Where no formal benchmark item exists the item says so.

Immediate (this week)
  • Confirm the Falcon sensor is on every Windows host (MITRE M1049 Antivirus/Antimalware, M1047 Audit; FLASH internal recon). ARTEX inventoried sensor coverage to find hosts without it. Reconcile AD computer objects against the Falcon host list. Verify by Q1 baseline plus the reconcile gate in section 11.
  • Restrict Kudu/SCM and deployment credentials (MITRE M1035 Limit Access to Resource Over Network, M1042 Disable or Remove Feature or Program; FLASH Reduce External Attack Surface; Microsoft App Service guidance on disabling basic authentication; CIS Microsoft Azure Foundations Benchmark, App Service section). Playbook step 1. Verify by checking that the SCM site refuses requests from outside the approved network.
  • Inventory internet-facing applications, including peripheral ones (MITRE M1056 Pre-compromise; FLASH). Partner and supplier portals, mobile backends, sales-support systems, legacy services and per-business-unit apps are the soft targets the framework goes for. Verify with an external attack-surface scan reconciled to an owner for every hit.
  • Review every M365 tenant with a ConnectWise application, by application ID (MITRE M1018 User Account Management, M1047 Audit; FLASH). Keep affected connections disabled until ConnectWise issues formal restoration instructions. Do not delete the enterprise application first. Playbook step 4 lists credentials; the FLASH gives no application ID, so obtain it from ConnectWise.
  • Preserve evidence (MITRE M1047 Audit; FLASH Preserve Evidence and Respond). Export Entra sign-in and audit, Purview audit and SIEM data from 1 October 2026 without delaying urgent containment.
  • Require IMDSv2 on EC2 (MITRE M1035; AWS instance metadata guidance; CIS AWS Foundations Benchmark, EC2 metadata item). The framework queried cloud metadata via XXE. Playbook step 2. Verify the describe-instances query returns no instance with tokens optional.
Near term (1 to 4 weeks)
  • Least privilege on multi-tenant application permissions and consent grants; monitor credential additions (MITRE M1026 Privileged Account Management, M1018; FLASH Harden Identity and Access; CIS Microsoft 365 Foundations and CIS Entra ID benchmarks). Verify with Q13 returning only expected change-window events.
  • Deploy LAPS and limit who can read it; remove GPP passwords (MITRE M1015 Active Directory Configuration, M1026; Microsoft Windows LAPS documentation). Playbook step 5 finds cpassword values. Verify with Q3 showing reads only from named accounts.
  • Kerberoasting resistance: gMSAs, long service-account secrets, AES (MITRE M1015, M1027 Password Policies, M1026; mitigation guidance for T1558.003). Verify the service-account inventory in playbook step 5.
  • Protect against DCSync and delegation abuse (MITRE M1015, M1026, M1018). Limit directory replication rights to domain controllers; set MachineAccountQuota to 0 and audit msDS-AllowedToActOnBehalfOfOtherIdentity (playbook step 5). Verify with the N8 domain controller log hunt.
  • PowerShell visibility (MITRE M1038 Execution Prevention, M1042, M1047; CIS Windows benchmark, Turn on PowerShell Script Block Logging). Playbook step 6. Verify event 4104 is generated.
  • Egress allowlist for servers (MITRE M1037 Filter Network Traffic; CIS Controls v8 network monitoring and defense). Servers reach only named destinations, which also removes LLM API endpoints, webhook services and anonymisers from reach. Verify with Q9 and Q10 returning no new destinations.
  • Guardrails on high-impact business APIs (FLASH Strengthen Application Protections; OWASP API Security Top 10, unrestricted resource consumption and broken authorization). Rate and recipient limits, transaction thresholds, server-side authorization, minimal response fields, no stack traces to unauthenticated users. Verify with a scripted burst in a test tenant and a 429.
  • Scan for embedded secrets and rotate (MITRE M1022 Restrict File and Directory Permissions, M1027, M1041 Encrypt Sensitive Information; FLASH). Repositories, images, build artifacts, pipelines, IaC and databases. Rotate exposed credentials promptly.
  • Certificate services (MITRE M1015, M1035; FLASH). Manager or CA approval for higher-risk enrolment, Extended Protection for Authentication on CA web interfaces, monitoring of unusual enrolment.
Strategic (1 to 3 months)
  • Move enterprise applications behind zero-trust access (MITRE M1035; NIST SP 800-207; FLASH). Removes external exposure where feasible.
  • Govern public IP allocation and management interfaces (MITRE M1030 Network Segmentation; FLASH). Architecture review before workloads or management interfaces face the internet; hypervisors, backup platforms and cloud administration on dedicated administrative paths.
  • Reduce direct modification of deployed code (MITRE M1022; FLASH run-from-package; Microsoft App Service guidance). Read-only deployed content makes web shell writes fail.
  • Tiered administration and just-in-time cloud roles (MITRE M1026, M1018; Microsoft enterprise access model; CIS Azure and AWS foundations benchmarks, privileged access items). Limits what a stolen service principal or instance role can reach.
  • Application allow-listing for server fleets (MITRE M1038, M1033 Limit Software Installation). Unapproved Go binaries and tunnelling tools do not run. Best-practice, no formal benchmark item cited.
  • AI egress governance: an approved gateway, per-key billing alerts and an inventory of sanctioned LLM tooling, so unexpected LLM API calls stand out (FLASH item 4). Best-practice, no formal benchmark.
  • Deception: honey accounts and canary credentials on lookup services and in cloud storage to catch machine-speed enumeration. Best-practice, no formal benchmark.

Step 1: Azure App Service: disable basic publishing authentication and restrict the SCM (Kudu) site

Prerequisites: Azure CLI signed in with rights on the app. Move deployments to Entra-based authentication first and test on a staging slot. Replace every REPLACE_WITH_* value.
Reboot required: No

# Azure CLI
az resource update --resource-group REPLACE_WITH_RG --name scm --namespace Microsoft.Web --resource-type basicPublishingCredentialsPolicies --parent sites/REPLACE_WITH_APP --set properties.allow=false
az resource update --resource-group REPLACE_WITH_RG --name ftp --namespace Microsoft.Web --resource-type basicPublishingCredentialsPolicies --parent sites/REPLACE_WITH_APP --set properties.allow=false
# Restrict the SCM site to the approved management network
az webapp config access-restriction add --resource-group REPLACE_WITH_RG --name REPLACE_WITH_APP --rule-name allow-admin-net --action Allow --ip-address REPLACE_WITH_ADMIN_CIDR --priority 100 --scm-site true
# Verify
az resource show --resource-group REPLACE_WITH_RG --name scm --namespace Microsoft.Web --resource-type basicPublishingCredentialsPolicies --parent sites/REPLACE_WITH_APP --query properties.allow

Rollback: Set properties.allow=true with the same az resource update commands, and run az webapp config access-restriction remove with --rule-name allow-admin-net --scm-site true.

Step 2: AWS: require IMDSv2 (instance metadata tokens)

Prerequisites: AWS CLI with EC2 modify rights. Confirm workloads use an SDK that supports IMDSv2 and test on one instance. The defaults command applies per region to new launches only.
Reboot required: No

aws ec2 modify-instance-metadata-defaults --http-tokens required --region REPLACE_WITH_REGION
# Verify: instances that still allow IMDSv1
aws ec2 describe-instances --region REPLACE_WITH_REGION --query "Reservations[].Instances[?MetadataOptions.HttpTokens!='required'].InstanceId" --output text

Rollback: aws ec2 modify-instance-metadata-options --instance-id REPLACE_WITH_INSTANCE_ID --http-tokens optional, and set the region default back with modify-instance-metadata-defaults --http-tokens no-preference.

Step 3: AWS: read-only audit of the staging calls the FLASH lists

Prerequisites: Read access to EC2 and IAM. Nothing is changed.
Reboot required: No

Step 4: Entra: inventory application and service principal credentials, and find a ConnectWise application by ID

Prerequisites: Microsoft Graph PowerShell with Application.Read.All. The FLASH gives no ConnectWise application ID: obtain it from ConnectWise and search by ID, not display name. Nothing is changed.
Reboot required: No

# PowerShell, read-only
Connect-MgGraph -Scopes "Application.Read.All"
Get-MgServicePrincipal -All -Property Id,AppId,DisplayName,PasswordCredentials,KeyCredentials |
  Where-Object { $_.PasswordCredentials.Count -gt 0 -or $_.KeyCredentials.Count -gt 0 } |
  Select-Object AppId, DisplayName, @{n='Secrets';e={$_.PasswordCredentials.Count}}, @{n='Certs';e={$_.KeyCredentials.Count}}
# Find a specific application by ID
Get-MgServicePrincipal -Filter "appId eq 'REPLACE_WITH_CONNECTWISE_APP_ID'"

Rollback: None required: the step is read-only. Do not delete an enterprise application as a first response.

Step 5: Active Directory: read-only audits, then set MachineAccountQuota to 0

Prerequisites: Domain-joined admin host with the ActiveDirectory module. The first four commands only read. Test the quota change in a lab first: some provisioning workflows rely on users joining machines.
Reboot required: No

# PowerShell
# 1. Delegation attribute set on any object (RBCD)
Get-ADObject -LDAPFilter '(msDS-AllowedToActOnBehalfOfOtherIdentity=*)' -Properties msDS-AllowedToActOnBehalfOfOtherIdentity | Select-Object DistinguishedName
# 2. User accounts with SPNs, password age and encryption types (Kerberoasting exposure)
Get-ADUser -LDAPFilter '(servicePrincipalName=*)' -Properties ServicePrincipalName,PasswordLastSet,'msDS-SupportedEncryptionTypes' | Select-Object SamAccountName,PasswordLastSet,'msDS-SupportedEncryptionTypes'
# 3. Current MachineAccountQuota
(Get-ADObject (Get-ADDomain).DistinguishedName -Properties 'ms-DS-MachineAccountQuota').'ms-DS-MachineAccountQuota'
# 4. GPP passwords left in SYSVOL
Get-ChildItem "\\$env:USERDNSDOMAIN\SYSVOL" -Recurse -Include Groups.xml,Services.xml,ScheduledTasks.xml,DataSources.xml,Printers.xml,Drives.xml -ErrorAction SilentlyContinue | Select-String -Pattern 'cpassword' | Select-Object Path
# 5. Change: set MachineAccountQuota to 0
Set-ADDomain -Identity (Get-ADDomain).DNSRoot -Replace @{'ms-DS-MachineAccountQuota'='0'}

Rollback: Set the quota back with Set-ADDomain -Identity (Get-ADDomain).DNSRoot -Replace @{'ms-DS-MachineAccountQuota'='10'} (the default). Commands 1 to 4 are read-only.

Step 6: Windows: turn on PowerShell script block logging (CIS Windows benchmark)

Prerequisites: Local administrator, or deliver the same value by GPO. Increases Operational log volume; size the PowerShell Operational log accordingly.
Reboot required: No

reg add "HKLM\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging" /v EnableScriptBlockLogging /t REG_DWORD /d 1 /f
# Verify
reg query "HKLM\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging" /v EnableScriptBlockLogging

Rollback: reg delete "HKLM\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging" /v EnableScriptBlockLogging /f

Step 7: Web servers: read-only audit of recent script files and MySQL log paths

Prerequisites: Read access to web roots and the database. Nothing is changed. Replace REPLACE_WITH_WEBROOT.
Reboot required: No

# Linux, read-only
find REPLACE_WITH_WEBROOT -type f \( -name '*.jsp' -o -name '*.php' -o -name '*.aspx' \) -mtime -30 -ls
mysql -e "SHOW VARIABLES LIKE 'general_log%'; SHOW VARIABLES LIKE 'slow_query_log_file';"
# Windows, read-only
Get-ChildItem -Path REPLACE_WITH_WEBROOT -Recurse -Include *.aspx,*.ashx,*.jsp,*.php -ErrorAction SilentlyContinue |
  Where-Object { $_.LastWriteTime -gt (Get-Date).AddDays(-30) } | Select-Object FullName, LastWriteTime, Length

Rollback: None required: the step is read-only.
