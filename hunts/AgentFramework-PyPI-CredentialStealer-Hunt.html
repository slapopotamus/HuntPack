Executive Summary

On 2026-11-17 two malicious releases of Microsoft’s agent-framework PyPI package, 1.26.1 (20:35 UTC) and 1.26.2 (~21:08 UTC), were published 33 minutes apart. Both were quarantined by roughly 21:30 UTC; 1.26.0 (2026-11-12 18:25 UTC) is the last clean release. Wiz puts the package at about 41,000 downloads a week, SecurityWeek and Aikido at about 190,000 a month.

Both releases drop a .pth file into the site-packages root (agent_framework_meta.pth in 1.26.1, af_runtime_diag.pth in 1.26.2). CPython executes any import line in a .pth file on every interpreter start, so the stealer runs on any Python launch in that environment, pip itself included, whether or not anything imports agent_framework. The victim never has to use the library.

The stealer forks into a detached background process, sets _AF_TEL=1 as a run-once marker (a marker, not a credential), and harvests environment variables by substring (TOKEN, SECRET, PASSWORD, KEY, AZURE, AWS, GITHUB, OPENAI and more), up to 300 /proc/*/environ files, and up to 60 (1.26.1) or 80 (1.26.2) credential files: Azure CLI state, Azure DevOps agent .credentials, pip.conf, .npmrc, .netrc, .git-credentials, .docker/config.json, Hugging Face tokens and .env files. It also requests Azure managed-identity tokens from IMDS for 12 resources and, in 1.26.2, GitHub Actions OIDC tokens for api://AzureADTokenExchange and https://management.azure.com/. Everything is zlib-compressed, base64-encoded and sent in one HTTPS POST to a webhook.site endpoint.

Attacker objective: steal cloud, CI/CD and registry credentials from developer and build environments and mint fresh Azure identities from them. Root cause is unconfirmed. Candidates in the reporting are a stolen PyPI upload token, a misconfigured Trusted Publisher or a compromised maintainer account; none is established. Attribution to a named actor is also unestablished and this pack does not assert one.

Honest scope: the releases are quarantined, so the window of exposure is closed. The value of this pack is retro-hunting install evidence (builds, images and caches from 2026-11-17 onward) and treating every hit as a credential-compromise event requiring rotation. It is not live prevention.

Defender priority: build agents (Azure DevOps, GitHub Actions runners, container builds) and Azure-hosted workloads are the highest-value scope. Find every environment that resolved 1.26.1 or 1.26.2, run Q1 to Q4, search proxy logs for the webhook UUID (Q5), and rotate every secret and identity reachable from any hit before anything else.

Native Audit-Log Hunts (non-CQL)

Do not start Python in a suspect environment to investigate it. The stealer runs on every interpreter launch there, pip and pytest included. Use the shell-only checks below, or python3 -S -I (the -S flag skips site processing, so .pth hooks do not run), or inspect from a clean host against a mounted image.

Host and image inventory (no interpreter)

# Linux / macOS: find the hooks and stealer modules
find / -xdev \( -name 'agent_framework_meta.pth' -o -name 'af_runtime_diag.pth' \
  -o -name 'af_runtime_diag.py' -o -path '*/agent_framework_meta/_telemetry.py' \) 2>/dev/null

# Any .pth with an executable import line in site-packages (broader, will show benign hooks too)
find / -xdev -path '*/site-packages/*.pth' -exec grep -l '^import ' {} + 2>/dev/null

# Containers: scan an image without running Python
docker run --rm --entrypoint sh IMAGE -c "find / -xdev \( -name 'agent_framework_meta.pth' -o -name 'af_runtime_diag.pth' \) 2>/dev/null"

# Is the run-once marker present in any running process?
for p in /proc/[0-9]*/environ; do tr '\0' '\n' < "$p" 2>/dev/null | grep -q '^_AF_TEL=' && echo "$p"; done

# Windows (PowerShell): hooks under every site-packages
Get-ChildItem -Path C:\ -Recurse -Include agent_framework_meta.pth,af_runtime_diag.pth,af_runtime_diag.py -ErrorAction SilentlyContinue | Select FullName,Length,LastWriteTime

Strategic (1 to 3 months)

  • Ephemeral runners with no standing secrets. CIS Azure Foundations, Microsoft Cloud Security Benchmark.
  • Inventory and review of .pth files in base images. Add a build-time check that fails an image containing an unexpected .pth with an import line. MITRE M1047. Best-practice, no formal benchmark.

Honest read: the malicious releases are quarantined, so live prevention value is low and the exposure window has closed. The pack’s job is to find installs that already happened and to drive credential rotation. The decisive scoping tools are the lockfile, image and registry audit and the Entra and provider logs, not endpoint CQL. The _AF_TEL marker and the credential file reads are visible only by inspecting running processes or the filesystem. Hosted CI runners are usually outside endpoint telemetry entirely.

File-write detection was deliberately not built.
