Executive Summary

Attacker objective. Aoki (also written Aokigahara; Symantec detects it as Infostealer.Aoki) is a Windows infostealer that collects whatever it finds on a victim machine and sends it to a command-and-control server. Its newest builds add a module Check Point calls aisessions that targets the credential, session and configuration files of AI coding assistants and the cloud credentials next to them: Claude Code and Claude Desktop, Codex, ChatGPT Desktop, Cursor, Windsurf, Kiro, GitHub Copilot, Gemini CLI, JetBrains AI Assistant, Amazon Q and AWS CLI and SSO caches. [#1] [#2]

Why it matters. A stolen API key or session token acts under the developer's identity and quota, and can expose the repositories, cloud services and CI/CD pipelines tied to that account. Symantec calls the quota-abuse case LLMjacking. Check Point adds that conversation histories and uploaded files could be used for extortion, and that it could not confirm how the operators monetise the data. The rest of the target list (more than 40 browser families, about 70 wallet extensions, about 20 desktop wallets, Discord, Telegram, game clients, password managers, FTP and VPN clients, Outlook and Thunderbird) points to a financial motive. [#1] [#2]

What is not known. The initial delivery vector is not established in either report, so this pack does not assume one. Symantec states that it does not know which group is behind the malware. Neither report attributes it. There is no backdoor command set: the stealer collects, packages and uploads, then cleans up locally. [#1] [#2]

Highest-value defensive angle. Detection of the stealer itself is thin: the C2 names and hashes are published, but new builds will not match them, and Falcon does not log most file reads. The reliable win is on the credential side: shorten the life of AI and cloud tokens, keep long-lived keys out of plaintext config files and .env, and be ready to revoke every AI, cloud, Git and browser session on any host that hits.

Defender priority. Any hit on Q1 to Q4 or Q7 is a credential-exposure incident, not a malware cleanup. Rotate AI provider keys and sessions, AWS keys and SSO sessions, Git tokens and browser sessions before or alongside reimaging. Cleaning the host leaves every stolen session valid.

Hunt Brief & Attack Chain

Seven hypotheses, ordered by fidelity. Telemetry is named in plain terms first, then by platform where the name is certain.

  1. H1 (high): an endpoint resolved or connected to Aoki C2 infrastructure (Q1, Q2). T1071.001, T1041. FP: none expected. DNS lookup with the requesting process (CrowdStrike: DnsRequest. SentinelOne: DNS Resolved. Defender: DeviceEvents DnsQueryResponse) and outbound connection (CrowdStrike: NetworkConnectIP4. SentinelOne: IP Connect. Defender: DeviceNetworkEvents).
  2. H2 (high): a published Aoki sample ran or was written to disk (Q3, Q4). T1204.002. FP: none expected. Process creation with hash (CrowdStrike: ProcessRollup2. SentinelOne: Process Creation. Defender: DeviceProcessEvents) and executable write (CrowdStrike: PeFileWritten, NewExecutableWritten. SentinelOne: File Creation. Defender: DeviceFileEvents).
  3. H3 (medium): one process opened files from three or more AI-assistant or cloud-credential families (Q5). T1552.001, T1528, T1539. FP: backup, indexing and DLP agents. File open on a named path (CrowdStrike: FileOpenInfo, sensor and policy dependent; no confirmed equivalent named here for the other platforms).
  4. H4 (medium): the clipper component was dropped under a volume-root Microsoft\Vault folder (Q7). T1115. FP: near none. Executable write and process creation as in H2.
  5. H5 (low): an older build sent cleartext HTTP to a raw IP on port 8080 (Q6). T1071.001. FP: developer tools. Process creation joined to outbound connection.
  6. H6 (native): proxy or firewall logs show a POST to /gate/handshake, /gate/chunk or /gate/complete with user agent Microsoft-CryptoAPI/10.0 to a host that is not a Microsoft service (N1). Outside endpoint telemetry.
  7. H7 (native): stolen credentials are being used: AWS, AI provider, Git and identity-provider sessions from new addresses (N4 to N6). Outside endpoint telemetry.

P1 · Sinkhole the corroborated C2 domains

Playbook P1: sinkhole the three corroborated C2 domains (Windows DNS Server)
Prerequisites: a Windows DNS Server that your clients use; DNS admin rights. Clients that use DoH or an external resolver bypass this.
Reboot required: no
1. Create an empty primary zone for each name. Names under it then answer as non-existent.
   $names = @('dobeqnesmot.cc','hjazfioe.surf','neihite.cc')
   foreach ($n in $names) {
     if (-not (Get-DnsServerZone -Name $n -ErrorAction SilentlyContinue)) {
       Add-DnsServerPrimaryZone -Name $n -ZoneFile "$n.dns" -DynamicUpdate None
     }
   }
2. Verify from a client:
   foreach ($n in $names) { Resolve-DnsName $n -ErrorAction SilentlyContinue }
   # Expect: no A record returned
3. Do NOT add the four Check Point-only domains or the IP to a block list yet. Add them to an alert-only list.
Rollback:
   foreach ($n in $names) { Remove-DnsServerZone -Name $n -Force }
   # Removes the sinkhole zones. Run only if a name turns out to be legitimate for your business.

P2 · Browser password and card storage policy

Playbook P2: stop managed Chrome and Edge from saving passwords and cards
Prerequisites: an enterprise password manager is rolled out first, so users are not left without storage; local admin or GPO rights. Test on a pilot ring.
Reboot required: no (browsers read policy at next start)
1. Set policy values (registry form of the GPO settings):
   $targets = @('HKLM:\SOFTWARE\Policies\Google\Chrome','HKLM:\SOFTWARE\Policies\Microsoft\Edge')
   foreach ($t in $targets) {
     if (-not (Test-Path $t)) { New-Item -Path $t -Force | Out-Null }
     New-ItemProperty -Path $t -Name PasswordManagerEnabled -Value 0 -PropertyType DWord -Force | Out-Null
     New-ItemProperty -Path $t -Name AutofillCreditCardEnabled -Value 0 -PropertyType DWord -Force | Out-Null
   }
2. Verify: open chrome://policy and edge://policy and confirm both values show as set.
   Get-ItemProperty 'HKLM:\SOFTWARE\Policies\Google\Chrome' | Select-Object PasswordManagerEnabled, AutofillCreditCardEnabled
3. Note: this does not remove passwords already saved. Export or migrate, then clear stored logins, as a separate planned step.
Rollback:
   foreach ($t in $targets) {
     Remove-ItemProperty -Path $t -Name PasswordManagerEnabled -ErrorAction SilentlyContinue
     Remove-ItemProperty -Path $t -Name AutofillCreditCardEnabled -ErrorAction SilentlyContinue
   }

P3 · Audit plaintext secrets in AI tool and cloud folders

Playbook P3: find key-shaped secrets left in AI tool and cloud config folders (read-only audit)
Prerequisites: run as the user being checked, or as admin against each profile; PowerShell 5.1 or later. This script only reads and prints file names, never file contents.
Reboot required: no
1. List the files the stealer reads that exist on this profile:
   $roots = @("$env:USERPROFILE\.claude.json","$env:USERPROFILE\.claude","$env:USERPROFILE\.codex","$env:USERPROFILE\.gemini","$env:USERPROFILE\.codeium","$env:USERPROFILE\.copilot","$env:USERPROFILE\.aws","$env:USERPROFILE\.ssh")
   foreach ($r in $roots) { if (Test-Path $r) { Get-ChildItem -Path $r -Recurse -Force -File -ErrorAction SilentlyContinue | Select-Object FullName, Length, LastWriteTime } }
2. Flag stray dotenv files in those folders:
   Get-ChildItem -Path $env:USERPROFILE -Recurse -Force -File -Filter '.env' -Depth 3 -ErrorAction SilentlyContinue | Select-Object FullName
3. For each hit: move the secret to the OS credential store or a secrets manager, rotate it, then delete the plaintext file.
Rollback: none required. The script is read-only. Deleting a plaintext secret in step 3 cannot be undone, so rotate the secret first and keep a copy only in the secrets manager.

P4 · Retire long-lived AWS keys

Playbook P4: inventory and retire long-lived AWS access keys
Prerequisites: AWS CLI v2 with IAM read access, and IAM write access for the deactivation step. Confirm with each key owner before deactivating.
Reboot required: no
1. Report credential age and use for every user:
   aws iam generate-credential-report
   aws iam get-credential-report --query Content --output text | base64 --decode > credential-report.csv
2. List keys for a user and when each was last used:
   aws iam list-access-keys --user-name <USER_NAME>
   aws iam get-access-key-last-used --access-key-id <ACCESS_KEY_ID>
3. Deactivate (do not delete) a key that is unused or exposed:
   aws iam update-access-key --user-name <USER_NAME> --access-key-id <ACCESS_KEY_ID> --status Inactive
4. Move people to IAM Identity Center sessions and set a short session duration for the permission set.
Rollback:
   aws iam update-access-key --user-name <USER_NAME> --access-key-id <ACCESS_KEY_ID> --status Active
   # Reactivates a key that turned out to be needed. Do not reactivate a key that was exposed.
