Executive Summary

AvisLoader is a Windows malware loader that Varonis Threat Labs found on an exposed staging server together with a ClickFix lure, supporting tools and an operator web panel. Its command channel runs over Tox, an encrypted peer-to-peer messaging network, so there is no fixed C2 domain or server address to take down. The lure seen with it posed as a DocuSign signing request, hosted on Cloudflare Workers, and told the visitor to paste a command that pulls code from a Cloudflare Quick Tunnel (trycloudflare.com).

The recovered Windows client is a 3.4 MB 64-bit executable that statically links c-toxcore. Alongside it were auto.exe, a helper that references UACMe method 41, and hmn_hook.dll, a library that hooks NtQuerySystemInformation to filter a process name from results. Persistence code targets desktop and taskbar-pinned shortcuts and a VBScript launcher tied to the name VLCAssistant. Varonis stresses that successful elevation, process hiding and file transfers were not confirmed, and no victim counts were reported.

Defensive angle: detect the host behaviour (the pasted command, script hosts and shells touching a tunnel host, shortcut and launcher artifacts, a dllhost-spawned elevated shell) and treat network indicators as weak, because Tox traffic is encrypted and decentralised. The three published hashes ship at detect, not prevent, because they have a single origin.

Defender priority: run Q3, Q6 and Q1 over 30 days first, then review any workstation that pasted a command from a document-signing page. Do not block trycloudflare.com or workers.dev wholesale: both host legitimate services.

Native Audit-Log Hunts

Read-only checks that work without a Falcon sensor.

Shortcut and backup sweep (PowerShell, read-only)

# Lists desktop and taskbar-pinned shortcuts with their targets, plus any .backup files beside them.
$paths = @("$env:USERPROFILE\Desktop","$env:PUBLIC\Desktop","$env:APPDATA\Microsoft\Internet Explorer\Quick Launch\User Pinned\TaskBar")
$ws = New-Object -ComObject WScript.Shell
foreach ($p in $paths) { if (Test-Path $p) {
  Get-ChildItem $p -Filter *.lnk -ErrorAction SilentlyContinue | ForEach-Object {
    $l = $ws.CreateShortcut($_.FullName)
    [pscustomobject]@{Shortcut=$_.FullName; Target=$l.TargetPath; Args=$l.Arguments; Modified=$_.LastWriteTime}
  }
  Get-ChildItem $p -Filter *.backup -ErrorAction SilentlyContinue | Select-Object FullName, LastWriteTime
}}
# Review: targets that are wscript.exe/cscript.exe, a .vbs, or any argument mentioning VLCAssistant.

Other checks

  • RunMRU: inspect HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\RunMRU on a suspect host; it records commands typed or pasted into the Run dialog.
  • Process creation auditing (Event ID 4688 with command line) and PowerShell Script Block Logging (4104): search for trycloudflare.com and VLCAssistant.
  • Sysmon (if deployed): Event ID 1 (process), 11 (file create for .lnk, .vbs, .backup), 22 (DNS query for trycloudflare.com).
  • Proxy, DNS filter and secure web gateway: hunt for workers.dev pages that resemble document-signing requests and for trycloudflare.com requests from non-browser user agents.
  • Network: if egress logs exist, look for workstation UDP traffic to many external hosts. Tox is encrypted; do not expect payload visibility.

Hardening - Tiered & Deployable

Immediate (this week)
  • Block script and obfuscation abuse with ASR rules, audit first. Rules: Block JavaScript or VBScript from launching downloaded executable content; Block execution of potentially obfuscated scripts. MITRE M1049 (Antivirus/Antimalware), M1038 (Execution Prevention). Authority: Microsoft attack surface reduction rules reference. Verify: Get-MpPreference | Select AttackSurfaceReductionRules_Ids,AttackSurfaceReductionRules_Actions
  • Turn on PowerShell Script Block Logging and process-creation command-line auditing. M1047 (Audit). Authority: CIS Microsoft Windows benchmarks, Microsoft security baseline. Verify: Event ID 4104 and 4688 appear.
  • User training for ClickFix. M1017 (User Training): legitimate signing and verification pages never ask for a pasted command. Report, do not run. Best-practice, no formal benchmark.
Near term (1 to 4 weeks, pilot first)
  • Disable Windows Script Host for users who do not need it. M1042 (Disable or Remove Feature). Counters the VBScript launcher. Authority: Microsoft guidance; not in every CIS profile. Verify: Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows Script Host\Settings"
  • Harden UAC. Set ConsentPromptBehaviorAdmin to prompt for consent on the secure desktop and keep EnableLUA on; remove standing local admin (M1026 Privileged Account Management, M1052 UAC). Authority: CIS Windows benchmark UAC settings. Counters UAC-bypass helpers, which also need a split-token admin user.
  • Restrict the Run dialog where policy allows (NoRun) for standard users. M1038. Blunt control that breaks Win+R; pilot it. Best-practice, no formal benchmark. Does not stop a pasted command in a terminal.
  • Application control for user-writable paths (WDAC or AppLocker, audit mode first). M1038. Authority: Microsoft WDAC guidance; CIS AppLocker recommendations.
Strategic (1 to 3 months)
  • Egress control for tunnel services: allow-list trycloudflare.com and workers.dev by role at the proxy or DNS filter instead of allowing everything. M1037 (Filter Network Traffic). Do not block wholesale: both host legitimate services.
  • Default-deny outbound for workstations on non-standard UDP, so Tox-style peer traffic cannot leave. M1031 (Network Intrusion Prevention), M1037. Best-practice, no formal benchmark.
  • Protect shortcut locations: audit writes to Desktop and the pinned-taskbar folder (SACL) and baseline shortcut targets. M1022 (Restrict File and Directory Permissions). Best-practice, no formal benchmark.
  • PowerShell Constrained Language Mode with WDAC. M1045 (Code Signing), M1038.

Reboot required: No (applies at next elevation; a sign-out is advisable)

$k='HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System'

Rollback: Set ConsentPromptBehaviorAdmin back to its previous value (record it first with the Get-ItemProperty line; the Windows default is 5).

Step 4: Restrict the Run dialog for standard users (optional, blunt)

Prerequisites: Confirm users do not rely on Win+R; pilot with a small group.

# Deploy to users through GPO: User Configuration > Administrative Templates > Start Menu and Taskbar > Remove Run menu from Start Menu

Step 5: Audit writes to the pinned-taskbar and desktop shortcut folders

Prerequisites: Local admin; Audit File System policy enabled.
Reboot required: No

# Events appear as Security 4663 once "Audit File System" (Success) is enabled.

Rollback: $acl.RemoveAuditRule($rule) | Out-Null; Set-Acl $t $acl
