Executive Summary

BlackX is a UEFI bootkit that Kaspersky GReAT found in early 2026 on the networks of diplomatic agencies in Tajikistan, Uzbekistan and Turkmenistan. It closely copies the BlackLotus bootkit, exploits Baton Drop (CVE-2022-21894) to enrol attacker Machine Owner Keys and bypass Secure Boot, and then loads a kernel driver that blinds security products. Kaspersky attributes it to APT41 with medium confidence. The report was published 2026-10-22.

The twist is that the victims were fully patched. Microsoft's Baton Drop fix only revokes the vulnerable "Windows Production PCA 2011" signer after an administrator sets a registry flag and runs the Secure-Boot-Update task, and the automatic Enforcement Phase that would do it for everyone has not shipped. The pack therefore has two jobs: hunt the BlackX tradecraft that is visible to endpoint telemetry, and find the hosts where the revocation was never activated.

The strongest endpoint angles are the installer command line, the googleupdate.exe sideload host, the C2 lookups and the cloud-storage channel. The bootkit and kernel driver themselves act before or beneath the sensor, so the pack states plainly what it cannot see and routes those checks to native hunts.

Defender priority: BlackX needs administrator rights first, so the cheapest control is keeping them scarce. Then pilot Microsoft's revocation sequence on one device per hardware class and track which hosts have actually triggered it (Q9). Mitigations are preventive. Microsoft says a device already compromised needs the security provider, not another patch.

Decisions and limits

  • Dropped source. The SecurityBrief Asia URL in the request returned an older article about the MoonBounce firmware bootkit, not BlackX. It contains no BlackX content, so it is neither cited nor snapshotted.
  • Microsoft's page is filed under CVE-2023-24932 (the BlackLotus boot manager revocation). It describes the exact registry flag and task that Kaspersky calls the Baton Drop activation step, but the CVE number on Microsoft's page is 2023-24932, not 2022-21894. The pack keeps both numbers and does not merge them.
  • No IOC appendix. The Securelist page carries its indicators in the text only: one C2 host, one file hash, one certificate serial. No installer, driver or Rust payload hash is published, so those ship as labelled placeholders, never as invented values.
  • Single-source indicators ship detect. SecurityOnline restates Securelist rather than corroborating it, so nothing here qualifies for prevent. The MD5 belongs to a legitimate helper and is never prevent in any case.
  • Not obtained. Microsoft's April 2023 BlackLotus investigation blog (the CDN returned HTTP 403) and ESET's June 2026 report that Kaspersky cites. Related-cluster indicators from ESET's reporting are deliberately not imported.
  • Attribution is Kaspersky's, medium confidence. Basis: the identifier "xdd" appearing in BlackX payloads and in a PDB path from ESET's report, sideloading plus an encrypted file, and OLLVM obfuscation. All three are patterns shared by several Chinese-speaking actors.
