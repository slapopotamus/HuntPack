Executive Summary

Attacker objective: long-term espionage access to people inside Middle Eastern telecommunications, aviation and critical-infrastructure organizations. Palo Alto Networks Unit 42 tracks the actor as CL-STA-1178, assessed with high confidence as Iranian state-aligned, and the March 2026 operation against Iraqi critical infrastructure as the Blinder Tunnel campaign. Infrastructure staging was observed as early as November 2025. Unit 42 published the findings on 2026-10-06 and reports that GitHub has taken down the malicious infrastructure it identified.

The victim is a software engineer, not a server. The lure impersonates the Dubai Airports IT department, walks the target through a fake careers portal, then hands over a Visual Studio coding challenge (DubaiAirport_Carrers_IT_Test.zip) with a planted bug to fix. Opening the project is enough: a weaponized .csproj overrides the GetFrameworkPaths target that Visual Studio runs during its background design-time build, so code runs before anything is compiled. That launches a signed Visual Studio host binary renamed RuntimeBroker.exe, whose RuntimeBroker.exe.config performs AppDomainManager hijacking and turns off .NET event tracing with <etwEnable enabled="false"/>. The host then sideloads RuntimeBroker.dll (ShelbyLoader V2), which decrypts RuntimeBrokerApi.dll (ShelbyC2 V2) in memory.

Command and control runs entirely through the GitHub API with a hard-coded personal access token, with a fallback that searches GitHub Issues for AES-256-CBC ciphertext hidden in HTML comments. PowerShell commands execute through PsProxy.dll inside the implant process, so powershell.exe never starts. Blackwood wraps the open-source Chisel tool to open a reverse SOCKS proxy to 91.107.156[.]29.

Defender angle: the durable signals are process lineage and paths, not indicators. A RuntimeBroker.exe outside System32, anything running from %LOCALAPPDATA%\Microsoft\RuntimeBrokers, a vshost32.exe outside Program Files, and the MicrosoftRuntime Run value are near-zero false positive and survive every hash and IP rotation. The hardest parts are blind to a host sensor: the ETW-disabling config file content, the in-process PowerShell engine, and the memory-resident RAT. The Coverage Map flags each as a gap rather than hiding it.

Attribution and scope: this pack names only what the saved sources name. Unit 42 reports low-confidence tradecraft overlaps with Screening Serpens and Agent Serpens and explicitly states none is strong enough to attribute CL-STA-1178 to either group, so this pack does not. Dubai Airports was impersonated, not compromised; Unit 42 is not aware of any breach of its systems. The Google Drive and Google Workspace lookalike domains are attacker-registered; Google reports its own systems were not compromised.

Defender priority: run Q1, Q2 and Q5 across 30 days on developer endpoints first (near-zero FP). Then sweep developer source and download folders for .csproj files that define a GetFrameworkPaths target (section 7, N1). Turn on the Visual Studio "Always require a trust decision" setting for anyone who opens third-party projects (section 12, I1).

Web Hunter decisions and discrepancies

  • Delivery channel is not stated. Unit 42 says the attackers approached the target with a job offer and later "sent" the project archive. It does not say the archive arrived by email. This pack therefore says "recruitment lure" and does not claim spear-phishing email.
  • Two different IPs carry the Iran link. 87.248.129[.]239 is the address on the Iranian ISP TOSE'EH ERTEBATAT NOVIN ARIA and the older Blackwood server. 91.107.156[.]29, the current tunneling endpoint, is Hetzner in Germany; Unit 42 only suspects it was bought from an Iranian reseller based on Persian-language passive DNS.
  • Page date oddity. The article shows "Published October 6, 2026" and a footer reading "Updated 1 October, 2026". The update stamp precedes the publication date. The pack uses 2026-10-06 and treats the content as unverified for later edits.
  • Perishable infrastructure. GitHub removed the infrastructure Unit 42 identified, so the GitHub account indicators are historical. The behavior (GitHub API from a masqueraded .NET host) is the durable signal.
  • Related-cluster indicators excluded. The Elastic report's file names and accounts, and the Screening Serpens indicators, belong to adjacent reporting and are not shipped. Only Unit 42's Blinder Tunnel indicator table is used.
  • Unit 42 hashes cover non-PE files. The project file, config and archive hashes are valid for IOC Management but cannot appear in a PE write event, so only the three DLL hashes go into the hash query.
  • No injected instructions. Every fetched page was scanned for text addressed to an agent or asking for commands, extra fetches or changed output paths. None was found.

Native Audit-Log Hunts

Hunts that do not need CQL. Several are the only way to see the stages the Falcon sensor cannot.

N1 · Filesystem sweep for the weaponized project and the ETW-disabling config

Run on developer endpoints and any share holding downloaded projects. Read-only. Legitimate projects do not define a target called GetFrameworkPaths (Microsoft's own targets files do), and a .exe.config that disables ETW is rare.

$roots = @("$env:USERPROFILE", 'C:\src', 'D:\src')   # adjust to your developer paths
# 1) Project files that override the design-time GetFrameworkPaths target
Get-ChildItem -Path $roots -Recurse -File -Include *.csproj,*.vbproj,*.targets,*.props -ErrorAction SilentlyContinue |
  Select-String -Pattern '<Target\s+Name\s*=\s*"GetFrameworkPaths"' |
  Select-Object Path, LineNumber, Line

# 2) Config files that disable ETW or force local assembly probing
Get-ChildItem -Path $roots -Recurse -File -Include *.exe.config -ErrorAction SilentlyContinue |
  Select-String -Pattern 'etwEnable\s+enabled\s*=\s*"false"|probing\s+privatePath|publisherPolicy\s+apply\s*=\s*"no"|appDomainManager' |
  Select-Object Path, LineNumber, Line

N2 · Sysmon cross-reference (if deployed)

  • Event ID 1 (process create): image RuntimeBroker.exe outside System32; parent MSBuild.exe or devenv.exe with an AppData\Local image.
  • Event ID 11 (file create): *.exe.config created beside an executable in a user-writable folder; any file under \Microsoft\RuntimeBrokers\.
  • Event ID 13 (registry value set): ...\CurrentVersion\Run\MicrosoftRuntime.
  • Event ID 7 (image load): System.Management.Automation.dll loaded by an image that is not powershell.exe, pwsh.exe or an approved host. This is the best native signal for PsProxy.dll. Validate in your environment; if the config disables ETW, confirm which of your sensors still see the load.

N3 · Proxy or TLS-inspection hunt for the GitHub C2 path shapes

Where the egress proxy decrypts traffic, search for requests to api.github.com whose path matches /repos/<owner>/<repo>/contents/<16 hex characters>/Lic.txt or .../Inf.txt, and for the repository peakyblinders-tm/myLic. Also look for a fixed 63-second request cadence from one client to api.github.com, and a one-hour silence after HTTP 403 responses (the loader's rate-limit sleep). The Issues Search fallback uses the same host; its exact path is not quoted in the source, so treat a search-API pattern as an inference to validate.

N4 · PowerShell host-application hunt

PsProxy.dll runs a custom runspace inside the implant process. In the PowerShell event logs, look for engine start events and script block events (4104) whose host application or process is not powershell.exe or pwsh.exe. This depends on logging being enabled (playbook P5) and on the logging pipeline surviving the ETW change; validate on a test host before relying on it.

N5 · Defender audit telemetry for the ASR rule

After enabling the untrusted-executable ASR rule in audit mode (P3), search Defender advanced hunting for the action types AsrUntrustedExecutableAudited and AsrUntrustedExecutableBlocked originating from the RuntimeBrokers folder. Expect developer-build noise.

N6 · Visual Studio trust audit

On developer endpoints, open Tools > Options > Environment > Security > Trust and record whether "Always require a trust decision" is set and which Trusted Locations exist. Broad entries such as a whole user profile or Downloads folder defeat the control.
