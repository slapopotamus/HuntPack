Executive Summary

Sophos Counter Threat Unit and SophosLabs published research on 2026-10-20 on BRONZE SANDCASTLE, a threat group Sophos treats as China-based and distinct from BRONZE PRESIDENT and BRONZE ATLAS [#1]. Sophos observed victims in the Philippines, Taiwan, Afghanistan, Namibia and likely the Republic of Korea between August 2025 and August 2026, with activity concentrated in UTC+8 working hours [#1]. The group's most distinctive technical marker is Sandboxie DLL sideloading: a legitimate Sandboxie executable is placed beside a malicious sbiedll.dll, and the trusted process loads attacker code [#1].

The sideloaded DLL reads an encrypted config.ini, decodes it in memory and runs a Meterpreter-style backdoor (payload versions 1.1.5 and 1.1.7) that profiles the host, enumerates local network and accounts, and can collect keystrokes and screenshots [#1] [#2]. Operators were then seen running Windows net commands, creating Volume Shadow Copies with vssadmin.exe and copying ntds.dit, the Active Directory credential database [#1].

The highest-value defensive angle is behavioral, not file-based. Sophos states that the encrypted payloads are decoded at runtime, so static file detections may be ineffective [#1]. This pack therefore leads with host-executable-in-wrong-folder, sideload DLL staging, child processes of the hosts, the credential-theft sequence, and keeps the vendor hashes and C2 domains as a retro-hunt layer.

Defender priority: hunt Q2, Q3 and Q8 first, then Q9 and Q10 on domain controllers. If ntds.dit was copied anywhere in your estate, treat every domain credential as exposed. All shipped indicators are detect only: every hash and domain traces to Sophos alone, so none meets the two-independent-source bar for prevent.

Native Audit-Log Hunts

  • Sysmon Event ID 7 (image loaded): sbiedll.dll, jli.dll, Krita.dll, NvdaHelperRemote.dll, Libcef.dll, version.dll, msvcp140.dll, snmpapi.dll loaded from the same folder as the host and not from the product install path or System32. Look for unsigned or invalidly signed images.
  • Sysmon Event ID 11 (file create): DLL and config.ini created together in a user-writable folder, or an archive such as aez.zip extracted there [#1] [#4].
  • Sysmon Event ID 22 or DNS server analytic log: queries for the two C2 domains, and for file.io, gofile.io, ably.net, ably.io from the nine host process names.
  • Security 4688 with command line (needs the audit and command-line policy, Playbook step 1): vssadmin create shadow, net user, net group, net view, and any command naming ntds.dit.
  • Security 8222 on domain controllers: "A shadow copy was created" where audit policy provides it. Compare against backup windows.
  • Proxy or firewall logs: sessions to file.io, gofile.io, ably.net, ably.io and the GitHub API from servers, or from workstation processes that are not browsers.
  • Memory triage on a suspect host: dump the host process and look for a PE header in a non-image memory region, which matches Sophos's guidance on reflective loading and anomalous PE headers in memory [#1].

Hardening: Tiered

Platform in scope: Windows endpoints, servers and Active Directory domain controllers. The sources describe no Linux, macOS, cloud or appliance activity.

Immediate (this week)
  • 1. Command-line process auditing. Record command lines in Security 4688 so net, vssadmin and ntds.dit activity is visible without EDR. MITRE M1047 (Audit). Authority: Microsoft Learn, "Command line process auditing" (best-practice; no formal CIS item cited here).
  • 2. Refuse DLL loads from the current working directory. Set CWDIllegalInDllSearch to 0xFFFFFFFF per Microsoft KB 2264107. MITRE M1044 (Restrict Library Loading). Does not stop a DLL beside the executable, which is this group's technique, so treat it as a partial control (flagged: best-practice, no formal benchmark).
  • 3. Review who can create shadow copies on domain controllers. Audit Backup Operators and local Administrators membership on DCs. MITRE M1026 (Privileged Account Management), M1018 (User Account Management).
Near term (1 to 4 weeks, pilot first)
  • 4. Attack Surface Reduction in audit mode. Enable the rule "Block executable files from running unless they meet a prevalence, age, or trusted list criterion" in AuditMode on a pilot ring. MITRE M1038 (Execution Prevention). Authority: Microsoft Defender ASR rules reference. Requires Microsoft Defender Antivirus active.
  • 5. Application control for user-writable paths. Author a WDAC or AppLocker policy in audit mode that flags executables and DLLs loading from ProgramData, Public, Temp and Downloads. MITRE M1038, M1045 (Code Signing). Authority: Microsoft WDAC deployment guide, CIS Windows Benchmark application-control guidance.
  • 6. Retire unsanctioned Sandboxie, Krita, NVDA, Sysinternals copies. If the product is not approved in your estate, add it to the unsanctioned-software inventory and remove stray copies found by Q2 and Q5. MITRE M1047.
Strategic (1 to 3 months)
  • 7. Tiered administration for domain controllers. Limit interactive and remote admin logon to DCs to dedicated Tier 0 accounts and hosts, which limits who can run vssadmin and read ntds.dit. MITRE M1026, M1030 (Network Segmentation). Authority: Microsoft enterprise access model, Microsoft Security Baseline for Windows Server.
  • 8. Enforced application control with signed policy. Move step 5 from audit to enforce for servers first. MITRE M1038.
  • 9. Server egress filtering. Deny anonymous file-sharing and messaging APIs from servers by proxy category, keeping the audit log. MITRE M1031 (Network Intrusion Prevention). Best-practice, no formal benchmark.

Verify after deployment

Use the Hardening audit block in section 10. For control 1, Security 4688 events must now carry a Process Command Line field. For controls 4 and 5, review audit events for 14 days before any enforcement.

Deployable Playbooks

Step 1: Enable command-line capture in process-creation events

Prerequisites: local admin or GPO write; the "Audit Process Creation" subcategory must also be enabled for 4688 to be generated. Reboot required: No. Rollback: run the rollback lines at the end of the block; the setting returns to its default.

$k = 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\Audit'
New-Item -Path $k -Force | Out-Null
Set-ItemProperty -Path $k -Name ProcessCreationIncludeCmdLine_Enabled -Type DWord -Value 1
auditpol /set /subcategory:"Process Creation" /success:enable
# Verify
Get-ItemProperty $k -Name ProcessCreationIncludeCmdLine_Enabled
# Rollback
Remove-ItemProperty -Path $k -Name ProcessCreationIncludeCmdLine_Enabled
auditpol /set /subcategory:"Process Creation" /success:disable

Step 2: Refuse DLL loads from the current working directory

Prerequisites: test legacy line-of-business apps that rely on loading DLLs from the working directory. Reboot required: No for new processes; restart long-running services. Rollback: remove the value.

$k = 'HKLM:\SYSTEM\CurrentControlSet\Control\Session Manager'
Set-ItemProperty -Path $k -Name CWDIllegalInDllSearch -Type DWord -Value 0xFFFFFFFF
# Verify
Get-ItemProperty $k -Name CWDIllegalInDllSearch
# Rollback
Remove-ItemProperty -Path $k -Name CWDIllegalInDllSearch

Remove-MpPreference -AttackSurfaceReductionRules_Ids $id
