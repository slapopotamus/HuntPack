Executive Summary

CikaBika Bot is a Rust-based remote access trojan that Darktrace malware researchers (Tara Gould) documented on 2026-10-14. The infection starts with a disk image, Proposition_Projet.img, holding a decoy PDF and a Windows shortcut disguised as a Word document. Opening the shortcut runs hidden PowerShell that decodes an executable embedded in the PDF, writes it to %TEMP%\IfyuUapz.txt and runs it. That file is a Nim loader carrying a Rust DLL and a PowerShell deployer. The deployer stages the DLL at C:\Windows\Temp\dbghelp.tmp, hijacks the per-user ms-settings shell open command and launches computerdefaults.exe so an auto-elevated command moves the DLL into the Microsoft Edge Application directory as dbghelp.dll, a DLL search-order hijack of Edge.

The RAT registers each victim with a dedicated Discord channel and takes operator commands there: shell execution, process listing, file upload and download, plus strings for screenshots, camera, streaming and broadcast. In the observed activity the operator zipped a directory and exfiltrated it with ngrok. Darktrace names no actor, no motive and no victim sector, and says the initial delivery method is unconfirmed. This pack does not supply any of those.

Detection strategy: Darktrace published four MD5 hashes and a handful of filenames but no network indicators, because Discord and ngrok are shared legitimate services. The durable detections are behavioral: the ms-settings registry hijack, a child of computerdefaults.exe, the dbghelp.tmp staging file, and a dbghelp.dll written beside msedge.exe. The DLL name is stock Windows, so every rule keys on path and writer, never on the name, and nothing here is a prevent action.

Defender priority: run Q6, Q7, Q8 and Q10 over 30 days to find the elevation and sideload steps, and Q2 and Q4 for the published artifacts. On any confirmed host treat the user's desktop and documents as exposed (the operator has a file-download command) and the Discord and ngrok traffic as outside endpoint telemetry. Network-indicator coverage is genuinely weak, see section 15.

Native Audit-Log Hunts

Checks that do not need CQL. Event IDs below are standard Windows and Sysmon identifiers; confirm they are collected before relying on them.

  • Sysmon Event 7 (image load): msedge.exe loading dbghelp.dll from its own Application directory instead of System32, especially when unsigned. This closes the main gap the CQL set cannot see.
  • Sysmon Event 11 (file create) and Event 13 (registry value set): dbghelp.tmp in Windows\Temp; writes under \Software\Classes\ms-settings\shell\open\command.
  • Security 4688 with command line and PowerShell 4104 script block logs: PowerShell reading a PDF as bytes, XOR operations, Base64 decode, and Add-Type compiling a small C# helper that calls ShowWindow (Darktrace describes this helper).
  • Disk image mounts: the Windows virtual-disk operational log records image attach events on most builds; confirm the exact log and IDs on your build and look for .img or .iso files mounted from Downloads or mail cache followed by a shortcut launch from the new drive letter.
  • Proxy and DNS logs: Discord API hosts and ngrok service names from hosts that never use them; a short burst of both from one host.
  • File-system sweep: look for a dbghelp.dll directly in the Edge Application folder, a dbghelp.tmp in Windows\Temp, and an IfyuUapz.txt in user Temp folders (the read-only audit script in section 13 does this).

Hardening: Tiered & Deployable

Controls are anchored to MITRE mitigations (M-numbers) plus a platform authority. Controls with no formal benchmark are marked.

Immediate (this week)
  • Secure-desktop UAC consent for admin accounts (T1548.002, M1052 User Account Control; CIS Windows benchmark UAC settings). Setting ConsentPromptBehaviorAdmin to 2 removes silent auto-elevation of the class used here. Playbook step 1.
  • PowerShell script block logging (T1059.001, M1047 Audit; CIS Windows benchmark). Makes the decode-and-drop script visible. Playbook step 2.
  • Remove standing local admin from daily-driver accounts (T1548.002, M1026 Privileged Account Management; Microsoft security baseline guidance). Darktrace notes the bypass depends on Windows configuration; a standard user does not auto-elevate.
  • Block disk-image attachments at the mail and web gateway (T1204.002, M1017 User Training and gateway filtering; vendor gateway guidance). Quarantine .iso, .img, .vhd and .vhdx from external senders unless a business owner exists.
Near term (1 to 4 weeks, pilot first)
  • Disable double-click mounting of ISO and IMG for standard users (T1204.002, M1038 Execution Prevention; ⚠ best-practice, no formal benchmark). Playbook step 3; confirm the .img association on your build before rollout.
  • ASR rule: block execution of potentially obfuscated scripts in audit mode, then block (T1027, T1059.001, M1038; Microsoft Defender ASR reference). Playbook step 4.

Long term (1 to 3 months)
