Executive Summary

Citrus is a previously undocumented, Russian-speaking group that attacks Russian companies. It gets in through compromised contractors: credentials stolen from a contractor's staff are used on the corporate VPN or directly against internet-facing terminal servers over RDP. From a low-privilege contractor account it escalates, maps Active Directory, dumps credentials, tunnels out with Xray, and finally encrypts with a Go-based Sn00py ransomware (RSA-2048 plus ChaCha20, extension .citrus, note CITRUS_README.txt).

The distinctive step is mass deployment by Group Policy. A self-extracting archive builds a malicious GPO, copies the encryptor to the domain's SYSVOL share, and links the policy to the domain. The GPO drops the archive on every machine, creates a scheduled task that runs it with /quiet /norestart, enables WinRM, disables Volume Shadow Copy and Windows Defender, and sets a ransom wallpaper. The encryptor's host_blacklist skips four domain controllers so the policy keeps propagating. Operators also use LLMs to write scripts, and they name their tooling after Kaspersky products to blend in.

Scope note: the report says the group tried CVE-2026-54121 (Certighost, an AD CS authentication bypass) to escalate. That step is covered by the dedicated Certighost pack and is not rebuilt here. This pack covers the ransomware campaign itself.

⚠ Defender priority: the GPO is the blast radius. Alert on any new GPO or gPLink change made outside change control, on executables written to SYSVOL (Q14), and on Defender or VSS registry changes by policy (Q6). Once the GPO is linked, encryption follows on the next policy refresh, which is minutes.
Earliest signals: a contractor account logging on from a new location, atexec-style scheduled tasks (Q5), tool execution from C:\ProgramData (Q8), and outbound 443 from an unknown ProgramData executable (Q11). Published C2 addresses and hashes are in Q9 and Q10.

Hunt Brief & Attack Chain

Hypotheses (highest fidelity first)

  1. H1, GPO staging: an executable lands in SYSVOL or a Kaspersky-named archive runs outside a Kaspersky install, then a GPO is created and linked. Confidence high. (Q14, Q1, Q2)
  2. H2, known infrastructure: a host executes a published hash or contacts a published IPv4. Confidence high. (Q9, Q10)
  3. H3, tool staging: executables run from the listed ProgramData paths (Xray aliases, keylogger, recon tools). Confidence high. (Q8)
  4. H4, policy-driven defense impairment: Defender, VSS and WinRM values change by policy on many hosts at once. Confidence medium. (Q6, Q7)
  5. H5, silent archive execution: an archive runs with /quiet /norestart from a staging path, often via a scheduled task with a Citrus name. Confidence medium-high. (Q3, Q4)
  6. H6, tunneling: an unknown ProgramData executable holds external 443 sessions. Confidence medium. (Q11)
  7. H7, remote execution and remote access: atexec-style tasks and unsanctioned AnyDesk. Confidence medium. (Q5, Q12)
  8. H8, pre-encryption exfiltration: Telegram tdata packing. Confidence high. (Q13)

  • Immutable, offline backups with tested restore, because Citrus disables VSS and encrypts domain-wide. MITRE M1053. CIS Controls v8 11.
  • Tiered administration so no daily-use or contractor credential reaches Tier 0, with privileged access management for vendors. MITRE M1026, M1018. Microsoft Enterprise Access Model.
  • Segment 1C:Enterprise and database servers from user networks and fix insecure 1C configurations. MITRE M1030. Best practice, no formal benchmark.
  • Credential Guard and LSA protection on servers to blunt mimikatz. MITRE M1043, M1025. Microsoft security baseline.

# Reboot required: No.

# Prerequisites: Windows Enterprise/Server with AppLocker; the Application Identity service must run.
# Reboot required: No (policy applies after the service starts).
# Rollback: Set-AppLockerPolicy -XmlPolicy .\empty.xml, where empty.xml holds only

Playbook 5: Restrict WinRM to admin jump hosts

# Prerequisites: know your jump-host subnet; test on one server first so you keep a console path.
# Reboot required: No.
# Rollback: Remove-NetFirewallRule -DisplayName "HuntPack-WinRM-AdminOnly"

# 1. Record the existing WinRM rules.
Get-NetFirewallRule -DisplayGroup "Windows Remote Management" | Select-Object DisplayName,Enabled,Profile,Direction

# 2. Scope the built-in allow rules to the admin subnet. Replace REPLACE_WITH_ADMIN_SUBNET (CIDR).
Get-NetFirewallRule -DisplayGroup "Windows Remote Management" |
  Where-Object Direction -eq Inbound |
  Set-NetFirewallRule -RemoteAddress REPLACE_WITH_ADMIN_SUBNET

# 3. Verify from a non-admin host that WinRM is refused and from a jump host that it works.
Test-WSMan -ComputerName REPLACE_WITH_SERVER

Playbook 6: Remove a malicious GPO link (response)

# Prerequisites: scoped and approved by the IR lead. Back up first so the policy is preserved as evidence.
# Reboot required: No. Clients need a policy refresh to pick up the removal.
# Rollback: New-GPLink -Name REPLACE_WITH_GPO -Target REPLACE_WITH_TARGET_DN restores the link;
#           Import-GPO restores contents from the backup in step 1.

# 1. Back up and report before changing anything.
Backup-GPO -Name REPLACE_WITH_GPO -Path .\gpo-evidence
Get-GPOReport -Name REPLACE_WITH_GPO -ReportType Html -Path .\gpo-evidence\report.html

# 2. Remove the link from the domain (stops new policy refreshes applying it).
Remove-GPLink -Name REPLACE_WITH_GPO -Target "DC=REPLACE_WITH_DOMAIN,DC=REPLACE_WITH_TLD"

# 3. Disable the GPO so it cannot be relinked silently, and remove the staged archive from SYSVOL after imaging.
Set-GPO -Name REPLACE_WITH_GPO -Status AllSettingsDisabled
