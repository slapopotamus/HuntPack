Executive Summary

Attacker objective: sell access. CyberXero is the forum alias of an initial access broker that SOCRadar's Threat Research Unit documented on 2026-10-06. It runs two pipelines from one workstation: a global automated campaign that mass-compromises WordPress and e-commerce sites for access and payment data, and a curated manual campaign against Ukrainian energy and utilities. Confirmed exfiltration covers four Ukrainian organisations and more than 628,000 records on individuals, including 564,073 subscriber records and 213,340 access-log entries from a Kharkiv district heating provider.

What is different: an AI orchestration layer on the actor's own infrastructure. SOCRadar reports up to 51 specialised Claude Code agent definitions on the primary workstation and a PentAGI deployment wired into a Cobalt Strike team server through an AI provider API for payload generation. One recorded run scanned 4,708 targets, reached 429 WordPress admin panels and deployed 32 shells in 61 seconds. The whole operation became visible because the actor exposed an open directory with its live working directory, AI session logs and plaintext tokens.

Scope of this pack: the actor, not the vulnerability. The WordPress REST API batch flaws (CVE-2026-63030, CVE-2026-60137) are only the delivery vector for the mass pipeline and are covered by a separate pack in this library; nothing here hunts the vulnerability itself, and no indicator is borrowed from another pack. This pack hunts what CyberXero does after and around that entry: Cobalt Strike PowerShell stagers, the UpdSvc service, remote WMI, Redis abuse with SSH key injection, webshell execution on sensored web servers, and the machine-speed tempo.

Honest coverage: the mass scanning and panel compromise happen against internet-facing web applications. Most of that is web-server-log and database territory, not endpoint telemetry. The strong endpoint surfaces are the PowerShell stager and beacon on sensored Windows hosts, UpdSvc service creation, remote WMI, shell-driven authorized_keys edits and Redis abuse on sensored Linux hosts, and webshell command execution on sensored web servers. Section 15 states the blind spots as gaps.

Defender priority: run Q1, Q3, Q6, Q12 and Q17 across 30 days first (near-zero false positives). Then Q15 and Q16 on every sensored web server, and Q14 to find Redis reachable from the internet. Run the section 7 native checks for the parts no sensor sees: rogue wp2_ administrators, wp2shell_ plugin directories, and authorized_keys on Redis hosts. Nothing in this pack ships at prevent: the whole indicator set originates from one report.

Web Hunter decisions and discrepancies

  • One originating report. Every indicator comes from SOCRadar. The four secondary outlets restate it. GBHackers repeats five IPs verbatim, but it credits SOCRadar throughout, so it is not independent corroboration. Result: every indicator ships as detect, nothing at prevent, and confidence is MEDIUM for indicators and HIGH for the behavioural description.
  • Record count correction. The task brief gave 628,073 heating-provider records. SOCRadar and the secondary coverage say 564,073 subscriber records plus 213,340 access-log entries at that provider, and more than 628,000 records across four organisations. This pack uses the SOCRadar figures.
  • Hash descriptions. SOCRadar lists 71e21094... as 1.bin and 59c535f4... as config.bin, both Chinese-cluster staging payloads. The stager hash is a cracked Cobalt Strike 4.9.1 build attributed by SOCRadar to Pwn3rs Team.
  • Scope held to the actor. The CVE list in the source (CVE-2026-63030, CVE-2026-60137, CVE-2026-4815, CVE-2015-1397) is mentioned only as delivery. No detection here targets the REST API flaw.
  • Behavioural patterns are not atomic IOCs. wp2_ plus eight hex, wp2shell_ plus eight hex and the 13-character stager path are shipped as patterns and queries, not as CSV rows.
  • Not in the endpoint's view. The Telegram bot notification, the AI session logs, the VLESS/Xray proxy layer and the CryptoPay gateway are actor-side. The pack lists them for context and builds nothing on them.
  • Untrusted source content. SOCRadar describes material recovered from the actor's own directory. The pack treats all of it as data: nothing quoted from that directory was executed or fetched, and no value from it reaches an action column.
