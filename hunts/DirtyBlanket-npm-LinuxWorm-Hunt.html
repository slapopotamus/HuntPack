Executive Summary

On 2026-09-29 the npm account dirtyblanket published nine packages in 33 minutes: eight impersonate Express and one impersonates React. All nine carry the same preinstall hook, which pipes a script fetched through the Internet Archive Wayback Machine from a Codeberg repository into node. On Linux that script fetches linux.sh from Codeberg and runs it with bash. linux.sh is a self-spreading worm.

The worm installs the open-source CHAOS remote access tool as a fake systemd font service, so the operator gets a shell, file access and screenshots over a Tor hidden service. It then uses every readable SSH private key to log in to hosts in known_hosts and rerun itself, edits Arch User Repository packages those keys can push to, and republishes npm projects it finds on disk using any .npmrc publish token. Each new host, AUR package or npm version restarts the chain.

Highest-value defensive angle. Stage one runs on every operating system, because only the second stage checks for Linux. A command line naming hellscripter (Q1) or an install of one of the nine package names (Q2) therefore finds exposed macOS and Windows developer machines as well as Linux. On Linux hosts the fake unit and binary names (Q4, Q5, Q6) are specific to this campaign and give low-noise detection after the fact.

Defender priority. Treat any Linux host or CI runner that installed one of the nine packages as fully compromised, as SafeDep advises. Rotate every SSH key, npm token and secret readable by the installing user, and check the npm and AUR packages you maintain for versions you did not publish.

Commodity versus campaign. CHAOS is a public open-source tool. Codeberg, the Wayback Machine and the Tor Expert Bundle are legitimate services and software. They appear here as hunt and scoping signals only. Nothing in this pack blocks codeberg.org or web.archive.org wholesale, and nothing that is commodity ships at prevent or critical severity.

Decisions

  • Independence. The worm analysis, the hashes, the onion address and the persistence paths come from one origin, SafeDep. The OpenSSF PR and The Hacker News repeat SafeDep. Only the package names and the preinstall hook with the hellscripter URL have a second, independent reporter (Amazon Inspector, through the OSV records). No indicator in this pack therefore ships at prevent or critical severity, and the Falcon import CSV contains detect rows only.
  • Versions. SafeDep analysed version 5.2.1 (and react-nodejs 19.3.0). OSV lists later versions for several names, so hunts match package names, not versions.
  • Snapshots. The text of all four sources was saved verbatim to DirtyBlanket-npm-LinuxWorm-Hunt-sources/ and every atomic indicator is traced against them by the provenance gate. The SafeDep page shows per-version dist.shasum values, but its text hides the package-name column behind an email-protection placeholder, so the values are not mapped to packages here. Look them up at the source if you need them.
  • Naming. The pack uses only names the sources use: DirtyBlanket (the SafeDep title), the dirtyblanket npm account, the hellscripter Codeberg account, CHAOS, systemd-fontd.
  • Untrusted content. No fetched page contained instructions addressed to an automated reader.

Native Audit-Log Hunts

Non-CQL checks for the parts of the chain Falcon does not see. Replace the angle-bracket placeholder before running.

N1 Lockfile and manifest sweep

grep -rEwl --include=package.json --include=package-lock.json --include=yarn.lock --include=pnpm-lock.yaml -e '(xeprews|express-javascript|express-nodejs|react-nodejs|exprdd|exprrdd|exptrdd|exptred|exptredd)' /srv /opt /home 2>/dev/null
# Review each hit: -w treats a hyphen as a word break, so 'my-exprdd-lib' also matches.

N2 npm logs and cache

grep -rlE 'hellscripter|install-scripts' ~/.npm/_logs 2>/dev/null
ls ~/.npm/_cacache 2>/dev/null | head   # then search index entries for the nine package names

N3 Host sweep for the fake units and files

ls -la /usr/lib/systemd/systemd-font* /etc/systemd/system/systemd-font* 2>/dev/null
lsattr /usr/lib/systemd/systemd-font* /etc/systemd/system/systemd-font* 2>/dev/null   # an i flag is the worm's chattr +i
find / -xdev \( -name 'systemd-fontrenderd*' -o -name 'systemd-fontcached*' -o -name 'systemd-fontd' \) 2>/dev/null
for h in /home/* /root; do ls -la "$h/.config/systemd" "$h/.config/systemd/user" 2>/dev/null; done
systemctl list-units --all --no-pager | grep -iE 'Font (Rendering|Caching) Service'
sha256sum /usr/lib/systemd/systemd-fontrenderd /home/*/.config/systemd/systemd-fontcached 2>/dev/null   # compare with the Falcon CSV hash

N4 sshd authentication logs

journalctl -u ssh -u sshd --since '7 days ago' | grep -E 'Accepted publickey' | awk '{print $9, $11}' | sort | uniq -c | sort -rn | head
# A single internal source key-logging into many hosts in a short window, especially as root, matches the SSH spread step.

N5 Registry history of packages you maintain

npm view <your-package> time --json    # compare each published version time with your release log and git tags
git tag --list --sort=-creatordate | head   # a registry version with no matching tag or commit is suspect

N6 AUR packages you maintain

git log -p -n 5 -- PKGBUILD '*.install'
# Look for a pkgrel bump with an 'upgpkg:' message you did not write, and for a curl line added to the .install file.

N7 Worm output on reached hosts

ls -la /tmp/log 2>/dev/null && head -50 /tmp/log

CrowdStrike LogScale CQL Hunt Queries

Pick your tenant's cloud first: every "Open in Falcon" button below uses this selection.
Q1 · Stage-one and stage-two fetches from the hellscripter Codeberg repository
CONF HIGHFP LOWCOST LOW

Looks for: Any process whose command line names the hellscripter Codeberg account, or a Wayback Machine URL wrapping a Codeberg URL. This covers the npm preinstall hook, the Node.js loader, the SSH-pushed copy of the worm on remote hosts, and the line the worm appends to AUR .install files. No platform filter: the hook runs on macOS and Windows too and only the payload is Linux-only, so a non-Linux hit still means the package was installed. 

// HUNT: DirtyBlanket fetches from the hellscripter Codeberg repository
// MITRE: T1195.002, T1105, T1059.004
// CONF: high  FP: low  COST: low
// REQUIRES: Falcon process telemetry (ProcessRollup2) on developer hosts, CI runners and Linux servers
// FALSE POSITIVES: an analyst or ticketing tool that merely quotes the account name in a command line. The Wayback-wrapped Codeberg branch is broader than this campaign, so review any hit that lacks the hellscripter string.
// LOOKBACK: 30d (set with the console time picker)
#event_simpleName=/ProcessRollup2|SyntheticProcessRollup2/
| CommandLine=/hellscripter|web\.archive\.org\/web\/https?:\/\/codeberg\.org/i
| table([@timestamp, aid, ComputerName, UserName, FileName, ParentBaseFileName, CommandLine])
Q2 · Install of one of the nine malicious packages
CONF HIGHFP LOWCOST LOW

Looks for: npm, pnpm, yarn, bun or node command lines that install any of the nine package names. Matching is by name, not version, because the OSV records list later versions for several of the names (for example 5.2.2) beyond the 5.2.1 builds SafeDep analysed. 

// HUNT: DirtyBlanket malicious package install
// MITRE: T1195.002, T1204.005
// CONF: high  FP: low  COST: low
// REQUIRES: Falcon process telemetry (ProcessRollup2) on developer hosts and CI runners
// FALSE POSITIVES: a security tool or ticket search that passes a package name on its command line without installing it.
// LOOKBACK: 30d (set with the console time picker)
#event_simpleName=/ProcessRollup2|SyntheticProcessRollup2/
| FileName=/^(npm|npx|pnpm|yarn|bun|node)$/i
| CommandLine=/\b(install|add|i)\b.*\b(xeprews|express-javascript|express-nodejs|react-nodejs|exprdd|exprrdd|exptrdd|exptred|exptredd)\b/i
| table([@timestamp, aid, ComputerName, UserName, FileName, ParentBaseFileName, CommandLine])
Q3 · Known-bad SHA-256 executing: CHAOS client and linux.sh
CONF MEDIUMFP LOWCOST LOW

Looks for: A process whose image hash is the SafeDep-reported hash of the systemd-fontd CHAOS client, or the hash of linux.sh. linux.sh runs as a bash script, so Falcon will normally record the interpreter hash rather than the script hash. Treat the second value as a record for file scanners and a hit here as unlikely. Both hashes come from one analysis (SafeDep) and are held at detect. 

// HUNT: DirtyBlanket known-bad hashes executing
// MITRE: T1219, T1105
// CONF: medium  FP: low  COST: low
// REQUIRES: Falcon process telemetry (ProcessRollup2) with SHA256HashData
// FALSE POSITIVES: none expected for the binary hash. The script hash will rarely appear as a process image.
// LOOKBACK: 90d (set with the console time picker)
#event_simpleName=/ProcessRollup2|SyntheticProcessRollup2/
| SHA256HashData=/^(2c9dbc14809f1e1aebda114194368b002acf74c8760b88fc101f625d179793c2|65f0a95b24e30305146346cbc2452cfabadab9e1ca35053e1134b67c38919577)$/i
| table([@timestamp, aid, ComputerName, UserName, ImageFileName, SHA256HashData, ParentBaseFileName, CommandLine])
Q4 · Fake systemd font service processes and the bundled Tor
CONF HIGHFP LOWCOST LOW

Looks for: Linux processes whose image name is systemd-fontrenderd, systemd-fontcached or systemd-fontd, or whose image is the Tor Expert Bundle extracted under systemd-fontrenderd in the user's ~/.config/systemd/. Names are matched on the image basename, so the install path does not matter.

Q8 · Local Tor SOCKS proxy used by a non-Tor process
CONF MEDIUMFP MEDIUMCOST MEDIUM

Looks for: Connections to 127.0.0.1:9050, the local Tor SOCKS port the worm exports as HTTP_PROXY, grouped by the initiating process. The CHAOS client reaches its onion C2 only this way, so the process name is the signal. Tor is legitimate software and the bundle is hunt-only, never a block. FP: Developers running Tor Browser tooling, torsocks, privacy-focused apps and some research hosts connect to 9050 legitimately. Exclude known process names and approved hosts.

Q10 · SSH fan-out with BatchMode and a temporary known_hosts file
CONF MEDIUMFP MEDIUMCOST MEDIUM

Looks for: linux.sh runs ssh -o BatchMode=yes -o UserKnownHostsFile=<mktemp file> against every host in the collected known_hosts, once per key and per ssh_config path, so one infected host produces a burst of such processes. The query counts them per host. FP: Ansible control nodes, backup jobs and CI deploy steps also use BatchMode=yes. The temporary known_hosts file narrows this, but automation that does the same will still match.

// HUNT: DirtyBlanket SSH fan-out with BatchMode and a temp known_hosts file
// MITRE: T1021.004, T1552.004
// CONF: medium  FP: medium  COST: medium
// REQUIRES: Falcon Linux sensor process telemetry (ProcessRollup2)
// FALSE POSITIVES: configuration-management and deploy automation that uses BatchMode with a temporary known_hosts file.
// TUNING: exclude approved automation hosts by ComputerName, or raise the threshold above the largest legitimate fan-out in your fleet.
// LOOKBACK: 7d (set with the console time picker)
#event_simpleName=/ProcessRollup2|SyntheticProcessRollup2/
| event_platform=Lin
| FileName=/^ssh$/i

Hardening: Tiered

Immediate (this week)
  • Disable npm lifecycle scripts by default on developer machines and in CI (ignore-scripts=true), then allow-list the few packages that need a build step. Stops the preinstall hook that starts this chain. MITRE M1038 Execution Prevention, M1033 Limit Software Installation (T1195.002, T1204.005). Authority: npm CLI documentation for ignore-scripts. ⚠ best-practice, no formal benchmark. Verify: npm config get ignore-scripts. Playbook PB1.
  • Block the nine package names in your registry proxy or artifact manager and fail builds whose lockfiles name them. M1033. ⚠ best-practice, no formal benchmark. Verify: a test install through the proxy is refused; native hunt N1 returns nothing.
  • Protect SSH private keys with passphrases and hash known_hosts so a stolen key is not directly usable and a copied known_hosts does not list targets. MITRE M1027, M1026 (T1552.004, T1021.004). Authority: OpenSSH ssh_config(5) HashKnownHosts; hashed entries cannot be used by this worm per SafeDep. ⚠ best-practice, no formal benchmark for HashKnownHosts. Verify: ssh -G example.test | grep -i hashknownhosts. Playbook PB2.
  • Disable direct root SSH login (PermitRootLogin no), since the worm tries -l root with every key. MITRE M1018, M1042. Authority: CIS Linux distribution benchmarks, SSH Server Configuration section (control numbers differ per distro and version). Verify: sshd -T | grep -i permitrootlogin. Playbook PB2.
  • Revoke classic npm tokens and remove plaintext tokens from developer .npmrc files. MITRE M1032, M1026 (T1552.001). Authority: npm documentation on granular access tokens. ⚠ best-practice, no formal benchmark. Verify: npm token list shows none that you do not expect. Playbook PB3.
Near term (1 to 4 weeks, pilot first)
  • Publish from CI only, using trusted publishing with provenance, so no long-lived publish token sits on a workstation for the worm to find. MITRE M1032, M1026, M1048. Authority: npm trusted publishing documentation. Playbook PB3.
  • auditd rules for systemd unit directories and chattr to cover the unit-file write that Falcon queries in this pack do not. MITRE M1047 Audit. Authority: CIS Linux benchmarks, Logging and Auditing section; DISA Linux STIG audit rules. Verify: auditctl -l | grep sysd. Playbook PB4.
  • Scoped egress control for build hosts and servers: allow-list the package registries, alert on Tor relay and Tor bundle downloads, and alert (do not block) on Wayback Machine web/ fetches from CI runners. Do not block codeberg.org or web.archive.org organisation-wide. MITRE M1037 Filter Network Traffic. ⚠ best-practice, no formal benchmark. Verify: Q8 and Q9 results from a pilot server group.
  • AUR hygiene: on Arch hosts, review PKGBUILD and .install diffs before every build; for maintainers, hardware-backed SSH keys. MITRE M1033, M1018. Authority: Arch Linux wiki guidance on AUR packages. Playbook PB5.
Strategic (1 to 3 months)
  • Ephemeral, secretless CI runners that hold no ~/.ssh keys and no .npmrc tokens during dependency install. MITRE M1048 Application Isolation and Sandboxing, M1026. ⚠ best-practice, no formal benchmark.
  • Dependency cooldown policy: where your package manager supports a minimum release age (pnpm minimumReleaseAge, Yarn npmMinimalAgeGate), set it so newly published versions are not installed immediately. This does not stop a typosquat that you type by name, so it complements the controls above. Verify the setting exists in your version. M1051 Update Software, M1033.
  • Retire shared deploy keys in favour of short-lived SSH certificates, so a stolen key expires. MITRE M1026, M1032. ⚠ best-practice, no formal benchmark.

PB1 npm lifecycle script lockdown (T1195.002, M1038, M1033)

PB1.1 Disable install scripts for the user and for CI

Prerequisites: npm 7 or newer; shell access to the developer account or the CI image.
Reboot required: No

npm config set ignore-scripts true --location=user
# CI: install with scripts off, then rebuild only what needs it
npm ci --ignore-scripts
npm rebuild <package-that-needs-a-build>
# Verify
npm config get ignore-scripts

Rollback: npm config delete ignore-scripts --location=user. Packages with native build steps (for example those using node-gyp) will fail to build until you rebuild them explicitly.

PB1.2 Sweep lockfiles for the nine names and block them at the registry

Prerequisites: Read access to repositories and build caches; admin access to the registry proxy.
Reboot required: No

grep -rEwl --include=package.json --include=package-lock.json --include=yarn.lock --include=pnpm-lock.yaml -e '(xeprews|express-javascript|express-nodejs|react-nodejs|exprdd|exprrdd|exptrdd|exptred|exptredd)' /srv /opt /home 2>/dev/null
# Registry proxy: add the nine package names to the block or exclude list in your product's own configuration.

Rollback: Remove the block-list entries. The sweep is read-only, so Rollback: none required.

PB2 SSH hardening (T1552.004, T1021.004, M1027, M1018)

PB2.1 Hash known_hosts and require it for new entries

Prerequisites: OpenSSH client; root for the system-wide file.
Reboot required: No

echo 'HashKnownHosts yes' | sudo tee /etc/ssh/ssh_config.d/90-hashknownhosts.conf
# Convert an existing file (keeps known_hosts.old with the clear-text names)
ssh-keygen -H -f ~/.ssh/known_hosts
# Verify
ssh -G example.test | grep -i hashknownhosts

Rollback: Delete /etc/ssh/ssh_config.d/90-hashknownhosts.conf and restore ~/.ssh/known_hosts.old. Delete the .old file securely afterwards, because it lists every host in clear text.

PB2.2 Find and protect private keys that have no passphrase

Prerequisites: Shell access as the key owner; an agent or secrets process for any key used by automation.
Reboot required: No

for k in ~/.ssh/id_*; do case "$k" in *.pub) continue;; esac
  ssh-keygen -y -P '' -f "$k" >/dev/null 2>&1 && echo "NO PASSPHRASE: $k"
done
# Add a passphrase to a flagged key
ssh-keygen -p -f <path-to-key>

Rollback: ssh-keygen -p -N '' -f <path-to-key> removes the passphrase again. Do this only where an unattended service depends on the key, and prefer a short-lived certificate instead.

PB2.3 Disable direct root login over SSH

Prerequisites: A tested non-root account with sudo and working key login; console access in case of lockout.
Reboot required: No

echo 'PermitRootLogin no' | sudo tee /etc/ssh/sshd_config.d/90-noroot.conf
sudo sshd -t && sudo systemctl reload sshd   # the unit is named ssh on Debian and Ubuntu
# Verify
sudo sshd -T | grep -i permitrootlogin

Rollback: Delete /etc/ssh/sshd_config.d/90-noroot.conf and reload sshd.

PB3 npm credential hygiene (T1552.001, M1032, M1026)

PB3.1 Inventory and revoke publish tokens

Prerequisites: npm account access on the machine being cleaned.
Reboot required: No

grep -n '_authToken' ~/.npmrc /root/.npmrc 2>/dev/null | sed 's/=.*/=<redacted>/'
npm token list
npm token revoke <token-id>

Rollback: A revoked token cannot be restored. Issue a replacement scoped to a single package with the shortest lifetime that works, and store it in the CI secret store rather than on disk.

PB3.2 Publish from CI with provenance instead of a stored token

Prerequisites: The package is configured for trusted publishing in the npm package settings; a CI platform that issues OIDC tokens.
Reboot required: No

# GitHub Actions workflow excerpt
permissions:
  contents: read
  id-token: write
steps:
  - run: npm publish --provenance --access public

Rollback: Restore the previous publish step and its token secret. Keep the token revoked until the trusted-publishing setup is verified.

PB4 auditd coverage for systemd persistence (T1543.002, T1222.002, M1047)

PB4.1 Watch unit directories and chattr

Prerequisites: auditd installed and running; confirm the path of chattr with command -v chattr.
Reboot required: Only if the audit configuration is locked with -e 2

sudo tee /etc/audit/rules.d/90-systemd-persistence.rules >/dev/null <<'EOF'
-w /etc/systemd/system -p wa -k sysd_unit_write
-w /usr/lib/systemd -p wa -k sysd_lib_write
-a always,exit -F arch=b64 -S execve -F exe=/usr/bin/chattr -k chattr_exec
EOF
sudo augenrules --load
# Verify
sudo auditctl -l | grep -E 'sysd_|chattr_'
sudo ausearch -k sysd_unit_write -ts today

Rollback: sudo rm /etc/audit/rules.d/90-systemd-persistence.rules && sudo augenrules --load. Expect extra audit volume during package upgrades.

PB5 AUR hygiene (T1195.002, M1033, M1018)

PB5.1 Check local AUR build caches and your maintained packages

Prerequisites: Arch Linux host; read access to the AUR helper cache directories (paths vary by helper).
Reboot required: No
