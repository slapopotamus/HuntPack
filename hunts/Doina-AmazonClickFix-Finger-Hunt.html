Executive Summary

Attacker objective: run code on a Windows (and, per the report, macOS) machine and leave behind credential theft and remote access. Huntress investigated the campaign across multiple incidents and states it hit at least three of its customers. A sponsored Google result for the search term "amazon business" led to a spoofed Amazon sign-in page. After the victim types an email or phone number, a fake "I'm not a robot" CAPTCHA copies a command to the clipboard and instructs the victim to paste it into the Windows Run dialog.

The distinctive first stage is the built-in finger.exe client. The pasted command is obfuscated with commas, carets, hyphens and underscores, and it makes finger talk to a user account on an attacker domain over 79/tcp. The returned .plan text is a Windows script, hidden below the console height with 68 extra carriage returns. That script uses curl to fetch the real IronPython 3.4.2 release into the user Temp directory under a .pdf name, unpacks it with tar, and runs ipyw32.exe from the net462 folder with a Base64 and zlib-compressed Python blob.

The IronPython stage downloads timer6, a Cyrillic-substituted Base64 Python loader around XOR-protected shellcode. It decodes to a PE loader that finds an .ini file holding a URL, downloads from it and RC4-decrypts the body (v6), which is injected into memory. Huntress reports the vendor consensus is that v6 is Doina, a modular loader and RAT. Doina then pulls a ZIP with a portable Node.js runtime and an obfuscated index.js into C:\ProgramData\NodeView. The script decrypts two high-entropy files with AES-256-GCM: a shellcode reflective DLL injector and a larger payload that Huntress describes as "allegedly" Lumma Stealer, injected by process hollowing. A pirated NetSupport Client is also deployed to C:\ProgramData\Prodclear and talks to 167.148.201[.]106 on 725/tcp.

Attribution and persistence: no threat actor is named by any source, and this pack does not name one. Huntress reports no scheduled task or other persistence mechanism, so none is claimed here. The Lumma Stealer identification is hedged by Huntress and is hedged here.

Highest-value defensive angle: the chain is built from legitimate binaries (finger, curl, tar, IronPython, Node.js, NetSupport), so hash blocking alone fails. Hunt the behavior: finger.exe execution and TCP/79 egress (near-zero false positives on a modern fleet), IronPython running from a user-writable folder, node.exe running index.js from ProgramData, and Client32.exe in ProgramData. The pack ships 14 CQL queries, none of which recommends blocking a stock binary.

Defender priority: any host where finger.exe ran or connected out on port 79 should be treated as a credential-theft incident, not a malware cleanup. The final payload is an infostealer targeting browsers, crypto wallets, password managers and email clients, and a remote-management client was installed alongside it. Isolate the host, then reset credentials and sessions for the user and move any crypto holdings, without waiting for host forensics.

Hunter notes & deliberate omissions

  • Indicators are single-lineage. Every campaign domain, IP and hash comes from the Huntress report alone; Security Online relays it without adding values. Per the pack rule that blocking needs two independent sources, all 18 imported indicators are detect, none is prevent, and none is critical severity. The finger.exe, IronPython and port 79 behaviors do have two independent sources.
  • The sibling finger/IronPython campaign is not this pack's campaign. The BlueTeamCoolTeam post documents separate infrastructure. Its domains, campaign UUID, build marker, XOR key and YARA are deliberately not shipped here, because a pack carries only its own campaign's indicators.
  • Doina identification. Huntress says the "security vendor consensus" is that v6 is Doina and cites a 2024 Halcyon report tying Doina to pre-ransomware activity. The Halcyon report was not retrieved, so no Doina detail beyond what Huntress states is claimed.
  • Lumma Stealer is hedged. Huntress calls the larger payload "allegedly Lumma Stealer" and says the stealer is "suspected" elsewhere. Query names and IOC descriptions here say attributed or suspected, never confirmed.
  • Domain spelling discrepancy. The ad landing host is written orders-amazon[.]com[.]advancedfences[.]com in the article body and orders-amazon-com[.]advancedfences[.]com in the IOC table. Both are in the snapshot; the pack imports the IOC-table form and notes the other.
  • The ClickFix command is not reproduced. The article does not print the obfuscated string and this pack does not invent one. Q2 and Q12 hunt its shape (finger-letters with separator padding and a user@host argument).
  • Searched but unavailable: Dark Reading, BleepingComputer and Petri coverage returned HTTP 403 to automated fetch, so none is cited.
  • macOS variant: the report says macOS users received Terminal instructions and the destination was offline during research. No macOS payload analysis exists, so no macOS detection is claimed.

Q2 · Obfuscated finger command line inside cmd.exe (comma, caret, hyphen, underscore padding)
CONF HIGH FP LOW COST LOW

Looks for: The ClickFix command breaks the word finger apart with commas, carets, hyphens and underscores that cmd ignores. This regex tolerates those separators between letters and requires a user@host argument. It is a behavioral shape, not the real command (the article does not reproduce the obfuscated string).

Hardening: Tiered

Controls are ordered by leverage against this chain. It needs a Run dialog, an open path to 79/tcp, a user-writable place to run an interpreter, and no one watching ProgramData. Authority is MITRE mitigations plus the platform source named in each control. These are organization-level hardening controls and are separate from any Falcon prevent policy.

Immediate: deploy this week

I1 · Block outbound 79/tcp (and 725/tcp) at the host and perimeter firewall

Finger has no business use on modern endpoints and the stage-1 fetch needs it. The NetSupport C2 used 725/tcp.
Authority: MITRE M1037 (Filter Network Traffic); advice to block outbound finger on port 79 appears in the Security Online and BlueTeamCoolTeam write-ups. Windows Defender Firewall outbound rule. Verify: Get-NetFirewallRule (P1). Risk: low; inventory any legacy finger use first.

I2 · Remove the Run dialog for users who do not need it

ClickFix needs the victim to paste into Run. Huntress notes it does not stop variants that use PowerShell, a command prompt or the Explorer address bar, so treat this as partial.
Authority: MITRE M1042 (Disable or Remove Feature or Program). GPO Remove Run menu from Start Menu (NoRun). Verify: P2. Risk: medium; exempt IT and power users.

I3 · Turn on command-line process auditing

Without it, native 4688 hunts and many SIEM detections see no command line.
Authority: MS Security Baseline (Audit Process Creation, include command line). Verify: P3. Risk: low; raises log volume and may log secrets passed on command lines.

Near term: 1 to 4 weeks, pilot first

N1 · Application control in audit mode for finger.exe and ProgramData executables

Audit, then enforce, execution of finger.exe, executables under ProgramData and IronPython folders under user profiles.
Authority: MITRE M1038 (Execution Prevention); ASD Essential Eight application control; AppLocker or WDAC. Verify: P4 plus AppLocker audit events. Risk: medium; software installed under ProgramData needs allow rules.

N2 · Egress filtering: default-deny on nonstandard outbound ports for user workstations

Catches finger (79), NetSupport (725) and similar one-offs together. Authority: MITRE M1037. Risk: medium; needs an application port inventory.

N3 · Web filtering for IronPython release downloads from non-developer groups

The chain fetches IronPython.3.4.2.zip from the public GitHub release URL. Alert or block that path for users who do not develop on .NET. Authority: MITRE M1021 (Restrict Web-Based Content). Risk: low for non-developers.

Strategic: 1 to 3 months

S1 · Allow-list based application control (WDAC) for standard users

Removes the entire class of unsigned and user-writable interpreters and unexpected node.exe or Client32.exe copies. Authority: MITRE M1038; Microsoft WDAC guidance; CIS Controls v8 2.5 and 2.7. Risk: high effort.

S2 · Paid-search and malvertising controls plus ClickFix user awareness

No legitimate CAPTCHA asks anyone to paste text into an operating system command prompt. Teach that rule, and where a managed browser policy exists, funnel brand logins through bookmarks or a password manager rather than search ads. Report ad-click identifiers (aclk, gclid) to the ad platform. Authority: MITRE M1017 (User Training). ⚠ best-practice, no formal benchmark for the browser-policy half.

S3 · Credential hygiene for stealer exposure

Phishing-resistant MFA, no browser-stored passwords or wallets on managed endpoints, and short session lifetimes limit what an infostealer takes. Authority: MITRE M1032 (Multi-factor Authentication), M1027 (Password Policies).
