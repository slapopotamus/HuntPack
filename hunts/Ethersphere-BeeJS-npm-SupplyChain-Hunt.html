Executive Summary

On 2026-11-08/09, unsigned commits made under the bee-worker release-bot identity were added to ethersphere/bee-js (commit de2f74e) and ethersphere/swarm-desktop (commit 2de7270). In bee-js the commit moved node scripts/generate-version.cjs from prepare to postinstall and shipped the scripts folder, so the loader runs on every install. A published GitHub release started the project's own npm workflow, which pushed @ethersphere/bee-js 13.3.0 to npm with valid provenance. About 30 minutes later the same loader was released in swarm-desktop 0.56.2, where it runs when the app starts.

The loader requests a platform-specific JavaScript payload from api.frameworkmetrics.xyz (a domain registered about two days earlier) and runs it with Node's require and process. The payload reads the Swarm Desktop config.yaml and data-dir/keys/swarm.key and POSTs both to /v1/swarm/report. Because Swarm Desktop keeps the keystore password in plain text in the config, both files together expose the wallet. Each platform then installs a backdoor: a hidden ConnectWise ScreenConnect client on Windows (relay 185.232.84.169:8041), and the evjawbreaker Go remote shell on Linux and macOS (hub 193.57.9.155:4912, read from an Ethereum contract so the operator can move it with one transaction).

Evidence status: OX Security, SafeDep and StepSecurity all published on the same day, and the swarm-desktop maintainers' issue confirms the 0.56.2 release is malicious. Every indicator in this pack ships at detect; nothing is prevent and nothing is graded critical. The Windows backdoor is ScreenConnect, which is legitimate software, so its binaries and hashes are never prevent-grade. See section 15 for why.

Defender priority: npm removed 13.3.0 and 13.2.0 is clean, but the 0.56.2 GitHub release was still live at the time of the reports. Any host that installed bee-js 13.3.0 with scripts enabled, or ran Swarm Desktop 0.56.2, should be treated as compromised: the persistence (~/.solidity, a systemd user unit, a LaunchAgent, or the ScreenConnect service) survives removal of the package. Highest-fidelity catches are Q2 (DNS), Q1 (relay and hub egress), Q4/Q5 (Windows) and Q7 (Linux, macOS). Move any Swarm wallet funds to a new key from a clean machine.

Native Audit-Log Hunts

These checks need no EDR query. The lockfile sweep is the authoritative exposure test, because the endpoint cannot see which version a lockfile resolved.

  • Lockfile and SBOM sweep: run the grep in the "Lockfile Sweep" block of section 10 across all repos, CI caches and container images. Also check npm ls @ethersphere/bee-js --all on build agents.
  • CI install logs: search for @ethersphere/bee-js@13.3.0. A clean-looking log does not clear the host, because the loader swallows network errors.
  • Proxy, DNS and firewall logs: search 2026-11-08 onward for frameworkmetrics.xyz, 185.232.84.169 and 193.57.9.155, and for requests carrying X-Ethersphere: 1.
  • Windows event log: System event 7045 for a service named ScreenConnect Client (5cbe79c9c25524df); Microsoft-Windows-Windows Defender/Operational event 5007 (configuration changed) for an exclusion path containing a dotted 32-hex directory; Application event log for MsiInstaller entries around the same time.
  • Linux: systemctl --user list-unit-files | grep -i solidity, ls -la ~/.solidity, and journalctl --user -u solidity-langsupport-runner for each user.
  • macOS: ls ~/Library/LaunchAgents | grep -i solidity, launchctl list | grep -i solidity, ls -la ~/.solidity.
  • GitHub audit log (org owners): release, tag and workflow-run events by the release bot around 2026-11-08 23:59 UTC to 2026-11-09 00:40 UTC; commits that are on no branch; releases not preceded by a merged release pull request.
  • Swarm wallet files: modification time and access on config.yaml and data-dir/keys/swarm.key under the Swarm Desktop data folder (Linux ~/.local/share/Swarm Desktop, macOS ~/Library/Application Support/Swarm Desktop, Windows %LOCALAPPDATA%\Swarm Desktop\Data). Treat the wallet as exposed regardless.
