Executive Summary

Attacker objective. Operation FlashHole is a Lazarus cyberespionage campaign against South Korean organisations, with the earliest evidence dating to July 2025. Kaspersky GReAT confirmed at least three victims in software, construction and wired communication equipment manufacturing, and assesses that the software sector is targeted to steal source code. [#1] [#2]

How it gets in. Targets receive spear-phishing links to AI-assisted lure sites on GitHub Pages: a fake résumé page and later an interior design portfolio. Each site loads an external JavaScript file from an attacker-controlled host. Visiting the site most likely starts an infection involving the mandatory South Korean financial security product CrossWeb EX. Securelist could not establish the exact abuse method, and no CVE is assigned. [#1] [#2]

What runs. The legitimate fsquirt.exe is executed under the CrossWeb EX process and injected with shellcode holding the TechHub DLL. TechHub uses a private GitHub repository and a Personal Access Token as its C2 channel and pulls TouchHub, which installs a service that side-loads TouchShift as mscoree.dll. A second TechHub then deploys ClientHub and LPEClient, and LPEClient fetches the Cubridge orchestrator. LPEClient protects payload delivery with ML-KEM-1024 post-quantum key encapsulation. Most of the chain lives only in memory. [#1]

Why this pack. The disk and network footprint is small, so the pack hunts the seams that Securelist documents: a CrossWeb EX parent starting fsquirt.exe, a service running from System32\RasConv, a mscoree.dll in the wrong folder, GitHub lookups from processes that should never make them, and the seven published hashes and seven published hosts. Queries are written for Windows endpoint telemetry.

Defender priority: where CrossWeb EX or other mandatory Korean security software is installed, alert on any fsquirt.exe child of the CrossWeb EX service (Q1), any process or service running from RasConv or DrvConh (Q3, Q4) and mscoree.dll outside the system folders (Q5). Then sweep the Section 10 hashes and hosts, and block fsquirt.exe outbound traffic (Playbook 2).

Web Hunter decisions

  • Atomic indicators come from the raw Securelist page only. The snapshot was saved from the fetched HTML, not a summary. A summarised fetch dropped two file paths (the qorestor and Dell mscoree.dll entries), which is why the raw page was used. Every hash and host in Section 10 appears in snapshot 01.
  • No independent corroboration was found. Searches returned only Securelist, the press release and derivative aggregators. The pack is single-vendor intelligence, so nothing ships at prevent or critical.
  • Hashes are MD5. Securelist publishes MD5 only. Falcon IOC Management takes MD5, and Q6 sweeps the same values.
  • Five of seven hosts are compromised legitimate sites. They ship at detect with medium severity and a shorter expiry. Blocking at the network edge can be done, but expect the legitimate owners to clean up and the indicator to age out.
  • Not included. The COPPERHEDGE cluster, SyncHole indicators, and the Dream Job MISTPEN and ForestTiger chain are discussed in Securelist as related activity. Their indicators are not shipped here. A separate Lazarus pack in the library covers other tooling.
  • Names. Every family, campaign and alias in this pack appears in the Securelist snapshot: TechHub (CLOUDBURST, NickelLoader), Cubridge (SIDESHOW, LightlessCan), TouchHub, TouchShift, ClientHub (CookiePlus overlap) and LPEClient.

Contradictions and gaps

  • Delivery wording. Securelist describes both a watering-hole strategy and spear-phishing links to GitHub Pages sites. It says it could not determine precisely what triggered the chain, and the press release says a potential CrossWeb EX vulnerability may be the entry. No CVE is named.
  • Unpublished infrastructure. The GitHub account and repository names, the Dropbox account and the PAT are not published, so GitHub C2 is hunted by behavior only. The Cubridge authentication token and ZipCrypto password in the report are not imported.
  • Telemetry limits. Most of the chain is in memory. Disk artifacts such as ActivationStore.dat, msadc.inc and desktops.ini are not PE files, so Falcon PE write events will not see them; use the native check N1.
  • Hash coverage. Only seven hashes are published, six of them for one component. Treat them as a floor, not a boundary.

Overall confidence: Medium-high. The vendor of record documents the chain in detail and the press release agrees. There is no independent confirmation and some mechanism details are acknowledged as unknown.

Hardening: Tiered & Deployable

Immediate (this week)
  • Inventory and patch CrossWeb EX and sibling security software. Securelist traced the chain to INISAFE CrossWeb EX V3 version 3.4.1.2 and says the abuse method is unknown, while the press release says a vulnerability may be involved. Verify: Playbook 1.
  • Stop fsquirt.exe reaching the network. The Bluetooth file transfer wizard has no need to reach the internet, and it is the TechHub injection host.   • Audit service creation. Persistence is a new service. Turn on Security 4697 and keep System 7045 forwarded so Q4 and N2 have a second source. Framework: MITRE M1047 (Audit); CIS Controls v8 safeguard 8.5. Verify: Playbook 3.
Near term (1 to 4 weeks)
  • Restrict GitHub API access to the hosts that need it. Allow api.github.com and raw.githubusercontent.com only for developer and CI groups at the proxy. Framework: MITRE M1037; NIST SP 800-53 SC-7. Verify: native hunt N4.

Playbook 1 · CrossWeb EX inventory (T1189; M1051)

Step 1.1 · Inventory CrossWeb EX and INISAFE products (read-only)

What it does: Lists installed INISAFE and CrossWeb products with versions and finds the service binary the report names.

Prerequisites: Local administrator or an endpoint management tool to run it fleet-wide.

Reboot required: No. These commands only read state.

Configuration

Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*','HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*' |
  Where-Object { $_.DisplayName -match 'INISAFE|CrossWeb' } | Select-Object DisplayName, DisplayVersion, InstallDate
Get-CimInstance Win32_Service | Where-Object { $_.PathName -match 'INISAFE' } | Select-Object Name, State, StartMode, PathName

Verify

# Expected: a list of hosts with the product. Compare each version to the vendor's current release.

Rollback

none required: read-only inventory.

Playbook 2 · Block fsquirt.exe outbound (T1055, T1102; M1037)

Step 2.1 · Add an outbound block rule for fsquirt.exe

What it does: Stops the TechHub injection host from reaching the internet. fsquirt.exe is the local Bluetooth file transfer wizard.

Prerequisites: Windows Defender Firewall enabled; a pilot group; confirm the group does not rely on internet-reachable Bluetooth transfer (it does not use IP).

Reboot required: No.

Configuration

New-NetFirewallRule -DisplayName 'HuntPack block fsquirt.exe outbound' -Direction Outbound -Action Block -Program "$env:SystemRoot\System32\fsquirt.exe" -Profile Any

Verify

Get-NetFirewallRule -DisplayName 'HuntPack block fsquirt.exe outbound' | Get-NetFirewallApplicationFilter | Select-Object Program
# Expected: the System32 fsquirt.exe path

Rollback

Remove-NetFirewallRule -DisplayName 'HuntPack block fsquirt.exe outbound'

Playbook 3 · Service creation auditing (T1543.003; M1047)

Step 3.1 · Enable security system extension auditing

What it does: Records Security event 4697 when a service is installed, a second source for Q4 and N2.

Prerequisites: Administrator rights; log forwarding capacity for the extra events; Group Policy if you manage audit policy centrally, since a local setting may be overwritten.

Reboot required: No.

Configuration

auditpol /set /subcategory:"Security System Extension" /success:enable /failure:enable

Verify

auditpol /get /subcategory:"Security System Extension"
# Expected: Success and Failure

Rollback

auditpol /set /subcategory:"Security System Extension" /success:disable /failure:disable

Playbook 4 · Compromise check (T1574.002, T1543.003; M1047)

Step 4.1 · Hash and locate TouchShift candidates (read-only)

What it does: Finds mscoree.dll outside the system folders and hashes it so it can be compared with the Section 10 MD5 list.

Prerequisites: Administrator rights; the Section 10 CSV.

Reboot required: No.

Configuration

Get-ChildItem -Path 'C:\ProgramData','C:\Windows\System32' -Filter mscoree.dll -Recurse -Force -ErrorAction SilentlyContinue |
  Where-Object { $_.DirectoryName -ne 'C:\Windows\System32' } |
  ForEach-Object { [pscustomobject]@{ Path = $_.FullName; MD5 = (Get-FileHash -Algorithm MD5 -LiteralPath $_.FullName).Hash } }

Verify

# Any result is an investigation lead. A match to a Section 10 MD5 is a confirmed hit.

Rollback

none required: read-only search.
