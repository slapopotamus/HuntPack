Executive Summary

Socket Threat Research tied a cluster of VS Code and Open VSX color theme extensions to the GlassWorm supply-chain campaign. A theme only needs declarative JSON, yet VS Code lets it ship JavaScript, and the editor has no fine-grained permission model for what that code does. Two extensions were confirmed malicious: Aurora Nocturne Night Theme (Windows downloader) and the Visual Studio Marketplace build of Cosmic Nebula Themes (GlassWorm loader). Socket linked six cluster identities in Open VSX, including versions of Coca-Cola Christmas, Aurora Borealis Studio Theme and Cosmic Nebula Themes. The reporting is dated 2026-10-03 to 2026-10-05.

Aurora Nocturne ran at editor start, carried a roughly 59 KB obfuscated out/extension.js with part of its payload hidden in zero-width Unicode characters, contacted fingercakes4sale[.]store, wrote the response to %TEMP%\temp_batch.cmd and launched it through cmd.exe with a hidden window. Cosmic Nebula declared a JavaScript entry point with activation on every session, decrypted an embedded stage with AES-256-CBC, ran it via eval(), skipped Russian-language and Russian-timezone hosts, then read a Solana transaction memo as a dead drop to resolve rotating next-stage infrastructure, so operators can change servers without publishing a new extension version. Socket rates the Cosmic Nebula build GlassWorm with high confidence and the wider cluster only as GlassWorm-associated.

This pack is built on developer-endpoint behavior, not on file hashes: the editor as the parent of cmd.exe or a shell, the temp_batch.cmd write and execution, DNS to the named payload host, Solana lookups from an editor process, and executables run out of extension folders. Earlier GlassWorm waves (for example the extension-dependency abuse reported in March 2026) appear only as background, and none of their indicators ship here.

Defender priority: run Q1 to Q4 now across all developer endpoints (zero tuning needed), inventory extensions on every VS Code-family editor including themes, and if a malicious theme ran, treat the host as compromised and rotate every credential, token and key that developer could reach. Removing the extension is not enough.

Native Audit-Log Hunts

  • Extension inventory: code --list-extensions --show-versions per editor, and for Cursor and other forks their equivalent CLI. Run Playbook A to flag themes that ship a JavaScript entry point.
  • Package inspection: in each installed extension folder read package.json: main or browser set on a theme, activationEvents containing "*", and any out/extension.js near 59 KB on a theme. Inspect the installed package, not the public repo; Socket reports they diverged.
  • Marketplace removal status: Microsoft removed the reported Marketplace themes; confirm installed copies are gone and that the editor blocked the removed IDs.
  • Network and proxy logs: search for fingercakes4sale[.]store and for editor user-agents calling Solana RPC endpoints.
  • Version drift: re-run inventory after every extension update; Socket notes clean themes can turn malicious later.

CrowdStrike LogScale CQL Hunt Queries

Pick your tenant's cloud first — every "Open in Falcon" button below uses this selection.
Q1 · Editor process spawns cmd.exe that runs temp_batch.cmd (Aurora Nocturne execution)
CONF HIGHFP LOWCOST LOW

Looks for: A VS Code-family editor (Code, Cursor, Windsurf, VSCodium) as the parent of cmd.exe where the command line references temp_batch.cmd, the exact drop-and-run behavior reported for the Aurora Nocturne Night Theme downloader.

// HUNT: Editor spawns cmd.exe running temp_batch.cmd (GlassWorm theme downloader)
// MITRE: T1059.003, T1195.002, T1105
// CONF: high
// FP: low
// COST: low
// REQUIRES: ProcessRollup2 on Windows developer endpoints
// FALSE POSITIVES: none expected; a color theme has no legitimate reason to spawn a batch file
#event_simpleName=/^(ProcessRollup2|SyntheticProcessRollup2)$/
| event_platform=Win
| ParentBaseFileName=/^(code|code - insiders|cursor|windsurf|codium|vscodium)(\.exe)?$/i
| FileName=/^cmd\.exe$/i
| CommandLine=/temp_batch\.cmd/i
| table([@timestamp, aid, ComputerName, UserName, ParentBaseFileName, FileName, CommandLine, TargetProcessId, SHA256HashData])
Q2 · Any cmd.exe executing temp_batch.cmd from a temp path
CONF HIGHFP LOWCOST LOW

Looks for: Parent-agnostic execution of temp_batch.cmd through cmd.exe. Catches a variant that re-parents through node.exe or an Electron helper, where the editor is not the direct parent.

// HUNT: cmd.exe executing temp_batch.cmd (parent-agnostic)
// MITRE: T1059.003
// CONF: high
// FP: low
// COST: low
// REQUIRES: ProcessRollup2 on Windows
// FALSE POSITIVES: an unrelated internal script that happens to share the filename (verify the parent chain)
#event_simpleName=/^(ProcessRollup2|SyntheticProcessRollup2)$/
| event_platform=Win
| FileName=/^cmd\.exe$/i
| CommandLine=/temp.{0,3}temp_batch\.cmd/i
| table([@timestamp, aid, ComputerName, UserName, ParentBaseFileName, FileName, CommandLine, TargetProcessId])
Q3 · Payload-host lookup correlated with batch execution on the same host
CONF HIGHFP LOWCOST MEDIUM

Looks for: Both halves of hypothesis H2 on one host: the DNS lookup of the payload domain, and a cmd.exe that runs temp_batch.cmd. Correlating them raises confidence well above either signal alone. Why this is not a file-write query: the loader writes the batch file from inside the editor's in-process Node runtime, and a .cmd script is not a PE, ELF, archive or document, so no documented Falcon file-write event (NewExecutableWritten, PeFileWritten, ElfFileWritten, ZipFileWritten, DocumentFileWritten) fires on it. The write itself is recorded as a gap in S15 rather than detected with an event name this pack cannot verify.

// HUNT: payload-host DNS lookup correlated with temp_batch.cmd execution on the same host
// MITRE: T1105, T1059.003, T1071.001
// CONF: high
// FP: low
// COST: medium
// REQUIRES: Falcon sensor on Windows developer hosts (DnsRequest + ProcessRollup2)
// FALSE POSITIVES: near none; requires both the named attacker domain and the named batch filename on one host
// TUNING: selfJoinFilter correlates by host (aid) over the search window, not by exact process tree or ordering; confirm the DNS lookup precedes the cmd.exe start before escalating, and widen the window if the drop and run are minutes apart
#event_simpleName=/^(DnsRequest|ProcessRollup2|SyntheticProcessRollup2)$/
| selfJoinFilter(field=[aid], where=[
    {#event_simpleName=DnsRequest DomainName=/fingercakes4sale\.store$/i},
    {FileName=/^cmd\.exe$/i CommandLine=/temp_batch\.cmd/i}
  ])
| table([@timestamp, aid, ComputerName, UserName, #event_simpleName, DomainName, ParentBaseFileName, FileName, CommandLine])

Q5 · Editor spawns a shell, scripting host or download tool (generic theme-loader behavior)
CONF MEDIUMFP MEDIUMCOST MEDIUM

Looks for: Rare child-process pairs under a VS Code-family editor on Windows: cmd, PowerShell, wscript, cscript, mshta, node, curl, certutil, bitsadmin. A theme loader that runs decoded JavaScript and hands off to the shell lands here even when the filename changes. FP: the integrated terminal, Git, task runners and debuggers legitimately spawn shells and node. Review the rare tail, not the head.

// HUNT: Editor process spawns shell, script host or downloader
// MITRE: T1059.003, T1059.007, T1059.001, T1105
// CONF: medium
// FP: medium
// COST: medium
// REQUIRES: ProcessRollup2 on Windows developer endpoints
// FALSE POSITIVES: integrated terminal, git, npm/node tasks, debuggers, language servers
// TUNING: baseline 14 days, then exclude the CommandLine values your developers legitimately use (for example CommandLine=/git\.exe|conhost|--ms-enable-electron-run-as-node/i) and sort ascending so rare spawn pairs surface first
#event_simpleName=/^(ProcessRollup2|SyntheticProcessRollup2)$/
| event_platform=Win
| ParentBaseFileName=/^(code|code - insiders|cursor|windsurf|codium|vscodium)(\.exe)?$/i
| FileName=/^(cmd|powershell|pwsh|wscript|cscript|mshta|node|curl|certutil|bitsadmin)\.exe$/i
| groupBy([aid, ComputerName, ParentBaseFileName, FileName], function=[count(as=Spawns), max(@timestamp, as=LastSeen), collect([CommandLine])])
| sort(Spawns, order=asc, limit=200)
Q6 · Editor process resolves Solana infrastructure (dead-drop lookup)
CONF MEDIUMFP MEDIUMCOST MEDIUM

Looks for: The Cosmic Nebula loader reads a Solana transaction memo to learn its next-stage address. A code editor has no business resolving Solana RPC hosts; the sources advise alerting on developer machines that query the Solana blockchain unexpectedly. FP: developers building web3 or Solana projects will resolve these hosts from their own tooling, usually from node or a terminal, not from the editor process itself.

// HUNT: Editor process DNS lookup for Solana RPC / blockchain hosts
// MITRE: T1102.001
// CONF: medium
// FP: medium
// COST: low
// REQUIRES: DnsRequest with ContextBaseFileName (validate the field in your tenant)
// FALSE POSITIVES: web3 and Solana developers; Solana extensions that call RPC on purpose
// TUNING: exclude hosts in a web3 developer group (aid list or sensor grouping tag) and any approved Solana extension; keep the editor-parent filter so terminal-launched tooling stays out
#event_simpleName=DnsRequest
| DomainName=/solana/i
| ContextBaseFileName=/^(code|code - insiders|cursor|windsurf|codium|vscodium|code helper.*|cursor helper.*)(\.exe)?$/i
| groupBy([aid, ComputerName, ContextBaseFileName, DomainName], function=[count(as=Lookups), max(@timestamp, as=LastSeen)])
| sort(Lookups, order=desc, limit=200)
Q7 · Binary or script launched from a VS Code extensions directory
CONF MEDIUMFP MEDIUMCOST LOW

Looks for: Processes whose image sits under a .vscode, .cursor, .windsurf or .vscode-oss extensions folder. A theme extension has no native executable to run, so any hit from a theme folder is a strong lead; hits from language-tooling extensions are the noise. FP: language servers and debuggers ship native binaries inside extension folders (Go, Rust, C/C++, Python).

// HUNT: Process image launched from an editor extensions directory
// MITRE: T1195.002, T1059
// CONF: medium
// FP: medium
// COST: low
// REQUIRES: ProcessRollup2; the dot after the profile folder matches the path separator so no slash is needed
// FALSE POSITIVES: language servers, debug adapters, formatter binaries bundled by legitimate extensions
// TUNING: exclude known publisher folders (for example ImageFileName=/ms-python|golang\.go|rust-lang|ms-vscode\.cpptools/i) and keep any hit whose folder name contains "theme"
#event_simpleName=/^(ProcessRollup2|SyntheticProcessRollup2)$/
| ImageFileName=/\.(vscode|cursor|windsurf|vscode-oss|vscode-insiders).extensions/i
| groupBy([aid, ComputerName, ImageFileName, ParentBaseFileName], function=[count(as=Runs), max(@timestamp, as=LastSeen), collect([CommandLine])])
| sort(Runs, order=asc, limit=200)

CrowdStrike Custom IOA Recommendations

IOA-1 · Editor spawns cmd.exe running temp_batch.cmd HIGH PRIORITY

Pattern: Process Creation, parent image matches the editor list, image cmd.exe, command line contains temp_batch.cmd. Deployment: deploy directly in detect mode; no baseline needed. Exclusions: none. Alert framing: [CRITICAL] Detection: GlassWorm theme loader, editor ran temp_batch.cmd.

IOA-2 · Batch file written to temp by an editor-launched process

Pattern: File Creation, file name temp_batch.cmd in a user temp directory. Deployment: detect mode. Exclusions: none identified.

Playbook A · extension audit

# Playbook A: flag theme extensions that ship executable JavaScript (read-only)
# Prerequisites: PowerShell 5.1+, read access to the user profile folders
# Reboot required: No
# Rollback: none required, this playbook only reads files
$roots = @("$env:USERPROFILE\.vscode\extensions","$env:USERPROFILE\.cursor\extensions","$env:USERPROFILE\.windsurf\extensions","$env:USERPROFILE\.vscode-oss\extensions")
foreach ($r in $roots) {
  if (-not (Test-Path $r)) { continue }
  Get-ChildItem $r -Directory | ForEach-Object {
    $pj = Join-Path $_.FullName 'package.json'
    if (-not (Test-Path $pj)) { return }
    $j = Get-Content $pj -Raw | ConvertFrom-Json
    $isTheme = $null -ne $j.contributes.themes
    $hasCode = ($null -ne $j.main) -or ($null -ne $j.browser)
    $always  = $j.activationEvents -contains '*'
    if ($isTheme -and ($hasCode -or $always)) {
      [pscustomobject]@{ Extension=$_.Name; Main=$j.main; ActivatesAlways=$always }
    }
  }
}
