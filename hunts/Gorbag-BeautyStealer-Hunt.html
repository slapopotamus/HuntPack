Executive Summary

Gorbag is a Russia-aligned espionage group that ESET has tracked since at least February 2025. It targets Ukrainian organizations only: about a quarter law enforcement and justice bodies, about a quarter local administrations (mostly city councils near the front line), the remainder defense-sector entities, plus one transportation hub for foreign military aid. ESET published its findings on 2026-11-03 after presenting them at Virus Bulletin on 2026-10-14.

The group runs a small toolset built for one pass of intelligence collection. BeautyStealer, a C++ stealer tracked from version 0.9 to 2.0, takes browser cookies, saved passwords and Local State (Chrome, Edge, Opera, Firefox), OpenVPN configurations and files by extension (priority: .ovpn, .kdbx, .jks, .zs2, .rdp, .pfx), archives them, sends them to a Telegram chat or, from v1.2, a custom FastAPI server, and then deletes itself. The earlier tool, Prime ReverseShell, is a PowerShell reverse shell derived from a public GitHub repository (PSSW100AVB); ESET has not seen it used since BeautyStealer appeared. Delivery was a macro-enabled .xlsm in 2025 and, from early 2026, a weaponized RAR exploiting CVE-2025-8088 (WinRAR path traversal through NTFS alternate data streams) that drops a LNK in the Startup folder plus a PowerShell loader and encrypted payload in %ProgramData%.

ESET suggests Gorbag may be an initial access broker, so stolen VPN configs and credentials may be reused by others for later-stage intrusion. The activity overlaps a cluster CERT-UA tracks as UAC-0226 and Trend Micro as SHADOW-EARTH-066 (per The Hacker News); ESET also notes the GIFTEDCROOK stealer that CERT-UA attributes to UAC-0226 has appeared in earlier public reporting.

Posture: every indicator here comes from a single vendor (ESET), so nothing is shipped at prevent or critical. The two IPs and four SHA-1 hashes are detect-only. Hardening (section 12) is what blocks this chain: patched WinRAR, Office macro and child-process controls, and PowerShell logging.

Defender priority: confirm every WinRAR install is on a patched release, block Office from launching script hosts and writing executables, and run Q1, Q2 and Q9 first. Treat any hit as credential exposure: rotate VPN, KeePass, RDP and browser-stored secrets for that user.

Q1 · Startup-folder LNK launching a hidden PowerShell loader from ProgramData
CONF MEDIUMFP MEDIUMCOST LOW

Looks for: A PowerShell process started by explorer.exe (what a Startup-folder shortcut looks like on logon) whose command line points into ProgramData and uses hidden, bypass or encoded switches. This is the persistence leg of the 2026 WinRAR chain: ESET says the LNK in the Startup folder triggers the PowerShell loader dropped in %ProgramData% at each startup. FP: Corporate logon scripts delivered as Startup shortcuts that call PowerShell from a ProgramData path. Exclude the known script folder, see the TUNING line.

Validation: schema-aligned, static-reviewedAutomated: static-passedEquivalence: equivalent-with-schema-assumptionsProfiles: microsoft-defender-xdr, sentinelone-endpoint-ocsf
Known limitations and deployment notes
  • PowerQuery: Flags separated by tabs rather than spaces are not matched.
  • PowerQuery: The Startup shortcut file itself is not tied to the process.
  • PowerQuery assumes: The Startup-folder shortcut is only inferred from explorer as the creator; the shortcut file itself is not visible to this query.

Hardening: Tiered

Immediate (this week)
  • Update WinRAR everywhere to a current release and remove unmanaged copies (MITRE M1051 Update Software; fixes CVE-2025-8088). Verify with the audit in section 10. Authority: WinRAR vendor release notes.
  • Block Office macros from internet-sourced files (MITRE M1042 Disable or Remove Feature; Microsoft 365 Apps security baseline, CIS Microsoft Office benchmark). Playbook P2.
  • ASR rules in audit, then block: Office child processes, Office executable content (MITRE M1040 Behavior Prevention on Endpoint; Microsoft Defender ASR documentation). Playbook P1.
  • PowerShell script block logging on (MITRE M1047 Audit; CIS Windows benchmark, PowerShell logging). Playbook P3.
Near term (1 to 4 weeks, pilot first)
  • Block unprevalent executables and ProgramData execution: ASR rule for executables not meeting prevalence/age/trust criteria, then AppLocker or WDAC path rules for ProgramData root (MITRE M1038 Execution Prevention; Microsoft application control guidance). Pilot in audit.
  • Mail filtering: quarantine .rar attachments from external senders and macro-enabled Office files, and flag mail from partner accounts that suddenly send attachments (MITRE M1049 Antivirus/Antimalware, M1017 User Training). Best-practice, no formal benchmark.
  • Restrict browser password storage via managed browser policy so credentials are not stored for local theft (MITRE M1054 Software Configuration; vendor browser policy documentation).
Strategic (1 to 3 months)
  • Telegram egress policy: where there is no business need, restrict api.telegram.org to approved hosts through the web proxy category policy (MITRE M1021 Restrict Web-Based Content). Policy decision, not an IOC block.
  • Rotate and tighten secrets: phishing-resistant MFA on VPN, short-lived VPN profiles, and no cleartext credentials on endpoints, because BeautyStealer targets OpenVPN configs, KeePass databases and key files (MITRE M1032 Multi-factor Authentication, M1027 Password Policies).
  • Application control for archive-extracted content and removal of local admin where not needed (MITRE M1038, M1026 Privileged Account Management).

Verify post-deployment: the audit block in section 10 plus Q1 to Q5 should show no new hits from sanctioned activity after tuning.
