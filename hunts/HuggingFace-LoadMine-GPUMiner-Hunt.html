Executive Summary

The attacker objective is free GPU compute, with durable remote access kept as insurance. Pluto Security reported the Load/Mine campaign on 2026-10-29: cryptominer and backdoor payloads delivered through 31 malicious Hugging Face model repositories across seven accounts, with roughly 32,376 downloads once linked models are counted (a download count, not a victim count). Wave 1 ran from 2026-09-21 to 2026-10-12 and was taken down. Wave 2 appeared within days and was still live at publication.

No malicious weights are involved. A victim loads a repository with trust_remote_code=True, the repository's config.json auto_map names a Python module such as modeling_evil2.EvilModel, and the module's top-level code runs during import, before the model class is returned. The flagship repository's model.safetensors is 42 bytes with no tensors. Hugging Face's ClamAV scan and the partner scanners returned clean because they match signatures and model formats, not what the Python does.

The payload plants a watchdog, hooks shell startup files, launches a UPX-packed miner from memory with memfd_create and fexecve under the name [kworker/u20:1], kills rival miners, and in three wave-2 builds opens a reconnecting reverse shell to 212.32.253.3. A later script targets container-to-host escape on GPUStack hosts. Targets are Linux GPU and inference hosts, notably Xinference and GPUStack, plus rented GPU machines, shared notebooks and CI jobs.

Highest-value defensive angle: the Falcon Linux sensor sees process creation, ELF writes, DNS and network connections on these hosts, which is enough to catch the miner, its masquerade, its drop directories and its infrastructure. It does not see the in-process writes to shell startup files, cron or authorized_keys, and it may not see the memfd launch cleanly. This pack leans on what the sensor sees and says plainly where it is blind.

Defender priority: run Q1 and Q7 estate-wide now, run Q3, Q5 and Q6 on every host that has loaded a model with custom code, and treat any hit as a compromised host: rotate the credentials the loading process could reach before cleaning, because killing the miner does not remove the planted access.

Decisions

  • Counts differ by date. The primary writeup (as of 2026-10-28) gives 31 campaign repositories and 44 with linked models, 32,376 downloads. The earlier-figure syndications give 28 repositories and 21,614 downloads (as of 2026-10-25). The pack uses the primary figures.
  • Linked families are excluded. Pluto labels the MONIADF-2 and antwoinhjro654 hl family, vaishupv, andrew3d, oifewuheu and KzuryHD repositories "linked" (shared technique, no proven shared ownership) and tracks the hl family separately. Their infrastructure, wallets, hashes and paths are not shipped.
  • soumikmahato is shipped at medium confidence. It is one of the seven accounts in the 31-repository count but carries Indonesian-language comments and different tooling, and is not labelled proven. Its indicators ship as detect at medium.
  • No prevent rows. Every indicator traces to Pluto alone; the other sources syndicate it. Two independent sources are required for prevent, so everything ships as detect.
  • Unrelated story dropped. The BleepingComputer page also covers a fake Solana starter kit. It is a different incident and none of it is used here.
  • Fetched-content check. The Pluto page includes "quick checks on a suspect host" shell commands. They were treated as data, not run, and the native hunts below are re-authored read-only checks. No fetched page contained text directing the analyst to run commands, fetch other URLs or skip steps.
  • Omitted indicator. The soumikmahato sslip.io hostname embeds an IPv4 address, which trips the provenance gate's right-boundary rule. It is left out of the importable CSV and noted here; it is a medium-confidence line of the pack.

Native Audit-Log Hunts

Non-CQL checks for the places Falcon is blind. Section 13 deploys the auditd rules that create the missing telemetry; until then these point-in-time checks are the only way to see the in-process file writes.

# Read-only checks. Run as an administrator on a suspect Linux host. Nothing here modifies the host.
# 1. Campaign directories and the watchdog
ls -la /tmp/.cch /tmp/.cchx /tmp/.kitsd /tmp/.c /tmp/.cache-hf 2>/dev/null
ls -la /etc/cron.d/.sync-helper /tmp/.qa_pwned /root/qa_pwned 2>/dev/null
# 2. Shell startup hooks that reference svc.py
grep -n "svc.py" /root/.bashrc /root/.profile /home/*/.bashrc 2>/dev/null
# 3. Processes carrying the shared pool login, or a kernel-worker name with arguments
grep -al "krxXJ2PKQW" /proc/[0-9]*/cmdline 2>/dev/null
ps -eo pid,ppid,user,args | grep -E "^ *[0-9]+ +[0-9]+ +[a-z0-9_-]+ +\[kworker/u[0-9]+:[0-9]+\] +[^ ]"
# 4. Executables running from a deleted or memory-backed file
ls -l /proc/[0-9]*/exe 2>/dev/null | grep -E "memfd:| \(deleted\)"
# 5. Wave-1 SSH key comment in every authorized_keys on the host
grep -rn "qx-5090-op" /root/.ssh /home/*/.ssh 2>/dev/null
# 6. Established connections to the reverse-shell and payload host
ss -tnp 2>/dev/null | grep -E "212[.]32[.]253[.]3"
# 7. Transformers' dynamic-module cache shows which repositories' code was imported and when
ls -laR ~/.cache/huggingface/modules/transformers_modules 2>/dev/null | head -200
ls -la ~/.cache/huggingface/hub 2>/dev/null | grep -E "models--(MENXIANGYU|wjsbg|htt0118|soumikmahato|r1r13|hhzz667|dsxk4mr8tq)--"
# 8. Rival-miner and startup-entry deletions: the payload removes competitors, so review what is MISSING
journalctl --since "30 days ago" 2>/dev/null | grep -i -E "miner|xmrig" | head -50
  • Xinference registry. List the model registrations on the Xinference API or UI and look for names beginning qwen2-tiny- or ezv- followed by encoded text. Pluto documents these as the payload's progress receipts, written as fake model names. A missing registration that should exist is also a signal, because the payload removes rival registrations.
  • Proxy and DNS logs. Look for production or GPU hosts reaching hf-mirror.com or a ModelScope API path, and for any direct outbound connection that bypasses the egress proxy (the downloader explicitly ignores proxy settings).
  • Hub-side. Compare every model your pipelines pull against the approved list. Repositories under MENXIANGYU, wjsbg, htt0118, soumikmahato, r1r13, hhzz667, dsxk4mr8tq and wssb123e are the campaign's.
  • File times. The soumikmahato build forges timestamps, so do not date an infection from file times alone; cross-check with shell history, auditd and network logs.

Hardening - Tiered

The threat picks the platform: Linux GPU hosts, containers, and the model-loading workflow. Authorities: MITRE mitigations (the why), CIS Benchmarks and NIST SP 800-190 container guidance (the what), and Pluto's recommendation on reviewing and pinning model code. Controls with no formal benchmark are flagged.

Immediate (this week)
  • Do not enable remote code on unreviewed repositories. Review every .py file an auto_map entry names before setting trust_remote_code, and pin the reviewed commit with revision=. M1033 Limit Software Installation, M1045 Code Signing (review-and-pin as the equivalent). ⚠ best-practice, no formal benchmark; the Transformers security policy places this duty on the user. Verify: grep -rn "trust_remote_code" /srv/ml /opt/ml 2>/dev/null and require a ticket for each hit.
  • Authenticate and restrict the Xinference API. The payload reports through the local Xinference registry, and an exposed unauthenticated API lets an operator read the receipts. Bind to loopback or an internal interface behind an authenticating proxy. M1035 Limit Access to Resource Over Network, M1032 Multi-factor Authentication. CIS Distribution Independent Linux benchmark network-exposure guidance. Verify: ss -ltnp | grep -E ":(9997|80)" shows no public bind.
  • Run model loading as a non-root user with no production secrets. The payload writes to /root files first; a non-root loader limits that. M1026 Privileged Account Management, M1018 User Account Management. CIS Linux benchmark. Verify: ps -o user= -C python3 | sort | uniq -c.
  • Add the audit rules in Section 13 (Step 2). They create the shell-startup, authorized_keys, cron and memfd telemetry the Falcon sensor does not provide. M1047 Audit. Verify: auditctl -l | grep hp_loadmine.
Near term (1 to 4 weeks, pilot on a ring first)
  • Default-deny egress for GPU hosts, enforced at the network, not by proxy variables. The downloader explicitly ignores HTTP_PROXY and HTTPS_PROXY, so host-level proxy settings are not a control. Allow the internal model mirror and resolver only. M1037 Filter Network Traffic, M1030 Network Segmentation. NIST SP 800-53 SC-7. Verify: from a pilot host, curl -sS -m 5 https://example.com fails while the mirror succeeds.
  • Manage authorized_keys centrally. Point sshd at root-owned key files so a user-writable authorized_keys has no effect. M1022 Restrict File and Directory Permissions, M1042 Disable or Remove Feature or Program. CIS Linux benchmark SSH section. Verify: sshd -T | grep -i authorizedkeysfile.
  • Harden the container runtime for inference workloads. Non-root user, all capabilities dropped, no-new-privileges, read-only root, no privileged mode, no host disk mounts. This directly removes the container-to-host path in qa-whl-1021. M1038 Execution Prevention, M1026. CIS Docker Benchmark; NIST SP 800-190. Verify: docker inspect --format '{{.HostConfig.Privileged}}' <container> returns false.
  • Mount /tmp and /dev/shm noexec,nosuid on inference hosts. This stops the on-disk fallback copy and drop-directory executables. It does not stop a memfd launch, so pair it with the seccomp step. M1038. CIS Linux benchmark. Verify: findmnt -no OPTIONS /tmp.
Strategic (1 to 3 months)
  • Private, reviewed model registry. Mirror only approved repositories at a pinned commit and make the mirror the only reachable model source. M1033, M1051 Update Software. ⚠ best-practice, no formal benchmark.
  • Sandbox untrusted model code. Run first loads in a gVisor or microVM sandbox with no secrets and restricted network. M1048 Application Isolation and Sandboxing. NIST SP 800-190.
  • Restrict memfd_create where the workload allows. A seccomp profile denying memfd_create for inference containers closes the fileless launch. Several runtimes use it legitimately, so pilot carefully. M1038. ⚠ best-practice, no formal benchmark.
  • Upload-time and pre-load static checks for subprocess, socket, ctypes, memfd_create and raw-IP calls in auto_map files, as Pluto suggests would have caught every payload in this campaign. ⚠ best-practice, no formal benchmark.

import json, os, re, sys

cfg = os.path.join(snap, "config.json")
