Executive Summary

ICMacOS (also tracked as Icarus macOS) is a macOS malware-as-a-service stealer that SOCRadar's Threat Research Unit says is sold on Russian-speaking forums since early September 2026. Delivery is a ClickFix page that makes the victim paste a Terminal command. A bash chain then shows a spoofed "System Preferences" dialog, checks the typed password against the login Keychain (up to five attempts), picks an arm64 or amd64 Go Mach-O, and runs it with the verified password. The stealer targets browsers, wallets, messaging apps and, notably for enterprises, developer secrets: SSH keys, cloud config, Kubernetes credentials and .env files.

Version 2, in SOCRadar's 2026-10-12 report, adds a com.apple.systemupdater LaunchAgent (KeepAlive, StartInterval 3600) and a persistent WebSocket C2 that runs operator commands through /bin/sh in real time, turning a one-shot stealer into a remote-access implant. The implant skips CIS victims using a ru_RU locale check and an ipinfo.io country lookup.

Detection strategy: the durable signals are command-line behaviors of stock tools (security, osascript, launchctl, curl), the infrastructure strings, and the implant's own name and children. All indicators come from one report, so they ship at detect.

Defender priority: hunt developer and admin Macs first for the LaunchAgent label, ICMacOs processes and the two domains (Q5, Q6, Q8, Q11). On any confirmed host assume the macOS password and every secret on disk are compromised and rotate in order; the stolen cloud and Kubernetes keys will be used from other systems, outside endpoint telemetry.

Native Audit-Log Hunts

Run these on a suspect Mac (or through MDM). All are read-only.

# 1. Persistence: Apple-labelled agents in the user folder, and the specific label
ls -la ~/Library/LaunchAgents/ | grep -i "com.apple."
launchctl print gui/$(id -u)/com.apple.systemupdater 2>&1 | head -20
plutil -p ~/Library/LaunchAgents/com.apple.systemupdater.plist 2>&1

# 2. Hidden staging and log artifacts
ls -la /tmp/.update-helper.log /tmp/.cache-update.log /tmp/.systemd-private-helper.zip /tmp/.update-tmp 2>&1

# 3. Hash any binary found (compare to the Mach-O rows in section 10)
shasum -a 256 /tmp/.update-tmp/* 2>/dev/null

# 4. Live network: who is talking to the C2 host
lsof -nP -i 2>/dev/null | grep -i -E "ICMacOs|escapeai"

# 5. Unified log: privileged AppleScript and keychain CLI use in the last day
log show --last 1d --predicate 'process == "osascript" OR eventMessage CONTAINS "unlock-keychain" OR eventMessage CONTAINS "systemupdater"' --style compact | head -100
  • Proxy and DNS logs: search 30 days for escapeai[.]live and mikoblico[.]xyz, paying attention to /ws, /upload and /ICMacOs?arch= paths in proxy logs.
  • Cloud and VCS audit logs (stolen developer secrets): for any confirmed host, review AWS CloudTrail, Kubernetes audit, Git hosting audit and SSH bastion logs for use of that user's keys from new source addresses after the infection time.
  • Identity provider: new sessions, token grants and MFA changes for the user after infection.

CONF HIGHFP MEDIUMCOST LOW

Looks for: The dropper validates the phished password with security unlock-keychain -p (up to five tries) and the stealer falls back to security dump-keychain -d. T1555.001.

FP: Build agents that unlock a code-signing keychain with -p (fastlane, xcodebuild wrappers, CI runners). Exclude by service account or parent; keep interactive-user hits in scope.

Validation: schema-aligned, static-reviewedAutomated: static-passedEquivalence: equivalent-with-schema-assumptionsProfiles: microsoft-defender-xdr, sentinelone-endpoint-ocsf
Known limitations and deployment notes
  • PowerQuery: A keychain command run by a process the agent did not observe starting is not captured.
  • PowerQuery assumes: src.process.user holds the account that ran the creating process.
  • PowerQuery assumes: tgt.process.cmdline holds the full argument string of the created process.
  • KQL – Defender XDR: A keychain command run by a process the sensor did not observe starting is not captured.
  • KQL – Defender XDR assumes: The query carries no operating-system filter; the security binary name is macOS specific.

Triage checklist (L1)

  1. Confirm the hit: host, user, parent chain, full command line.
  2. Run Q6 and Q7 for the same aid to see whether DNS or connections to the C2 exist.

Hardening: Tiered

Immediate (this week, no user-visible change)
  • Alert on the network indicators, do not block on them yet. Add escapeai[.]live, mikoblico[.]xyz and the two IPs to DNS and proxy alerting. Single-origin indicators justify visibility first; blocking is the owner's decision. MITRE M1037 Filter Network Traffic. Verify: Q6 and Q7 return results in a test.
  • Run the LaunchAgent audit across the Mac fleet. Flag any com.apple.* plist in a user LaunchAgents folder. MITRE M1047 Audit. Verify: playbook step 1 output. CIS Apple macOS Benchmark covers login item and LaunchAgent review by name; exact item numbers vary by OS release.
  • Confirm FileVault and a lock-on-sleep policy. A stolen login password unlocks the keychain, so full-disk encryption plus screen lock limit what a lost or idle Mac exposes. CIS Apple macOS Benchmark (FileVault, screen saver lock). Verify: fdesetup status.
  • Brief developers and admins on the exact lure. No legitimate site or support person needs a command pasted into Terminal, and no dialog that appears after running a script should receive the login password. MITRE M1017 User Training.
Near term (1 to 4 weeks, pilot first)
  • Restrict who can run Terminal-based installers on non-developer Macs. Use MDM application restrictions or an allowlisting tool (for example a binary-authorization agent) so unsigned or unknown downloads cannot execute from /tmp. MITRE M1038 Execution Prevention. Mac Gatekeeper and notarization enforcement is in the CIS Apple macOS Benchmark. Verify: spctl --status.
  • Managed login items. Use MDM to inventory and, where supported, control Background Task Management items so unknown LaunchAgents surface to the admin. MITRE M1018 User Account Management, M1022 Restrict File and Directory Permissions. best-practice, no formal benchmark item named
  • Keychain hygiene for admins and developers. Use a separate keychain password from the login password where policy allows, and store high-value secrets in an agent-protected store, not in plaintext files. MITRE M1027 Password Policies. best-practice, no formal benchmark
  • Tune the Falcon Mac prevention policy to the strongest machine-learning and script-control settings your tenant supports and confirm the sensor is current on every Mac. best-practice, vendor setting names vary by console version
Strategic (1 to 3 months)
  • Remove long-lived developer secrets from disk. Move to short-lived cloud credentials (federated SSO sessions), hardware-backed or agent-held SSH keys, and Kubernetes exec-based credential plugins. This directly removes the high-value files ICMacOS targets (.ssh, .aws, .kube, .env*). MITRE M1027, M1041 Encrypt Sensitive Information. NIST SP 800-53 IA-5.
  • Detect stolen-credential use at the source. Enable and centralize cloud, Kubernetes, VCS and bastion audit logs with alerts on new-source use of an existing key (ATT&CK T1078 follow-on). Outside endpoint telemetry by design.
  • Browser and wallet policy. Keep crypto wallets and password managers out of corporate browser profiles; require MFA that is phishing resistant for admin SaaS so a stolen cookie is not enough. MITRE M1032 Multi-factor Authentication.

Step 4: Post-incident credential rotation (order matters)

  4. Password manager master credentials and recovery material if its data folder was present.
  5. Crypto wallets: move funds to new wallets created on a clean device.
  6. Messaging sessions (Telegram, Discord, Slack, Signal) revoked from the account side.
