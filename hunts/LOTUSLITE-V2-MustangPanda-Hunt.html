Executive Summary

LOTUSLITE V2 is a .NET (C#) backdoor that its discoverers at Antares Research (published 2026-11-15) assess with high confidence to be a successor to the earlier C++ LOTUSLITE family and to be the work of the China-nexus actor Mustang Panda (Earth Preta). The campaign focus reported is Thailand and the Indo-Pacific policy theme. Two news write-ups on 2026-11-16 repeat the analysis and stress that the lineage and attribution are analytical judgments, not independently confirmed.

Chain: a public Zoho WorkDrive link downloads Integrated_Assessment_Indo-Pacific_Economic_and_Security.zip. It holds an assessment-themed .NET executable (assembly RegExt v2.1.18.0) and CommonLib.dll. Running it stages RegExt.exe and CommonLib.dll into C:\ProgramData\Microsoft\DeviceSync\, where RegExt.exe loads the DLL by side-loading. Persistence is threefold: a Run value (name contains PDFgear DeviceSync), the per-user Windows\Load value, and a hijack of the PdfGear.App.1 ProgID open command to PDFLauncher.exe in the same folder. C2 is XOR-encoded (key 0x55) with protocol magic 0x50524F31 (PRO1) and AES-256-GCM at the application layer.

Highest-value defensive angle: the indicators are few and brittle (two IPs, three hashes), but the host behavior is distinctive and cheap to detect: a vendor-themed folder under ProgramData\Microsoft, a Run value, a Load value and a ProgID command that all name DeviceSync. Hunt those first (Q4, Q5, Q8, Q9, Q10), then use the IPs and hashes to scope.

RegExt.exe is unresolved in the sources. One source section calls the staged RegExt.exe a "trusted PDFgear executable"; the same report lists a single hash for the .NET assessment executable and the staged RegExt.exe, and describes RegExt as the .NET assembly name. The sources do not resolve this. Nothing in this pack is set to prevent or block: every indicator ships at detect, and the pack hunts the side-load relationship and paths instead. See section 2.

Defender priority: run Q4, Q5, Q8, Q9 and Q10 across the fleet over 90 days now. Any hit is a confirmed host. Then check egress logs for the two C2 addresses (Q11) and for UDP/53 to public resolvers (Q13).

RegExt.exe: how this pack resolved it

  • The Antares text describes RegExt.exe as "a trusted PDFgear executable" that loads CommonLib.dll. GBHackers writes "a signed PDFgear executable operating as RegExt.exe".
  • The same Antares report says the assessment executable is a .NET binary containing the RegExt assembly (v2.1.18.0, entry point RegExt.Program.Main()), and its hash table lists one SHA-256 for "Assessment executable and staged RegExt.exe". Read literally, the staged file is the same bytes as the .NET stager, which would make it malicious rather than stock PDFgear. The table and the prose cannot both be right, and the report offers no signer, no hash for a stock PDFgear, and no explanation.
  • Resolution: the sources do not resolve it. This pack does not claim which hash is a legitimately signed binary. If the staged file is stock signed software, blocking its hash would break the vendor product for every user. So the hash 33cf56f1...8515ea ships detect only, and the pack hunts the relationship (a RegExt.exe under ProgramData, a CommonLib.dll write beside it, the DeviceSync path, the ProgID command) instead of the signed-binary identity.
  • Resolve it in your own environment: check the Authenticode signer and the SHA-256 of any staged copy (Playbook C step 1). Stock PDFgear installs under Program Files; a copy under ProgramData is out of place whatever its signature says.

Prompt-injection check: none of the four fetched pages contained text directed at an AI agent. The only imperative content was ordinary article text, treated as data.

Native Audit-Log Hunts

Non-CQL checks. These also close the two gaps CQL cannot (module load, mutex).

1. Sysmon (module load, file, registry, network)

Event ID 7  (Image loaded): ImageLoaded ends with \ProgramData\Microsoft\DeviceSync\CommonLib.dll
            and Image ends with \RegExt.exe   -> confirmed side-load
Event ID 11 (FileCreate):   TargetFilename starts with C:\ProgramData\Microsoft\DeviceSync\
Event ID 13 (RegistryValueSet): TargetObject ends with \CurrentVersion\Windows\Load
Event ID 13: TargetObject contains PdfGear.App.1\shell\open\command and Details contains DeviceSync
Event ID 13: TargetObject contains \CurrentVersion\Run and (TargetObject contains "PDFgear DeviceSync" or Details contains \DeviceSync\)
Event ID 3  (NetworkConnect): Image ends with \RegExt.exe and Image contains \DeviceSync\

2. Web proxy / secure web gateway

Host contains zohoexternal.com and URI path contains /public/workdrive-external/download/, with a ZIP or octet-stream response. Legitimate for Zoho users; correlate with the user and a following Q1 or Q4 hit. The Antares report publishes an equivalent proxy filter.

3. Live-response sweep of persistence (read-only)

  Get-ItemProperty $p -ErrorAction SilentlyContinue | Format-List *
}

$hits | Get-FileHash -Algorithm SHA256 | Format-Table Path, Hash
Get-AuthenticodeSignature 'C:\ProgramData\Microsoft\DeviceSync\RegExt.exe' -ErrorAction SilentlyContinue | Format-List Status, SignerCertificate

4. Mutex check (the gap)

No endpoint event exposes mutexes. On a suspect host, use Sysinternals handle.exe -a PDFgear_DeviceSync_Mutex (administrator prompt) or search a memory image for the same string. A hit is high confidence, a miss is not evidence of absence.

5. Network sensors

The protocol magic 0x50524F31 (PRO1) replaces the older LOTUSLITE magics, so signatures keyed on the old values miss V2. Because the payload is AES-256-GCM inside the stream, a magic-value rule can only see the framing, and only where the stream is not wrapped in TLS. Treat it as a hunt, not a gate.
