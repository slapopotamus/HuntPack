Executive Summary

Dr.Web disclosed on 2026-11-05 a long-running campaign that plants malware in GitHub repositories posing as legitimate projects. Earlier lures targeted crypto-wallet and blockchain-game users. The current wave targets information security professionals with fake repositories for scan automation, security testing and log analysis, including one posing as an output beautifier for the Fscan scanner. More than 2,000 Windows machines were infected at the time of research.

The malicious code hides in Visual Studio project files (a .csproj PreBuildEvent and PowerShell inside .suo files) and behind long runs of whitespace in .go and .py sources. A PowerShell stage fetches an encrypted download link from attacker servers or legitimate platforms (YouTube, Telegram, Google Docs, GitCode, Pastebin), pulls an Electron loader (Dr.Web: Trojan.Loader.3261, a process named Microsoft.exe), and that loader weakens Windows security, removes three antivirus products and injects two AsyncRAT copies and a clipboard clipper into legitimate Windows processes. A separate Electron stealer harvests browser, FTP, SSH-client, VPN, messenger, game and Discord data.

This pack uses only designators Dr.Web publishes. Dr.Web assigns no campaign name and no actor name, and neither does this pack. Quixo.7z, Nexara.7z and Lodge.7z are archive filenames, not campaign names.

Defender priority: treat any third-party security or scan-automation repository as untrusted code. Hunt for execution from C:\ProgramData\Windows.Microsoft.Photos, PowerShell dropped as t.ps1 or L.ps1 under C:\Users\Public\Pictures, and RegAsm.exe, dwwin.exe or dwm.exe started by an unexpected parent or reaching the internet. All indicators are single-origin (Dr.Web), so every one ships detect, none prevent.

Decisions

  • Independence: sources 3 and 4 are secondary coverage of source 1. Sources 1 and 2 are the same vendor. No indicator has a second independent origin, so every indicator is detect, never prevent (publish rule: prevent or critical needs two independent sources).
  • Snapshots: all four sources were saved as plain text before any HTML was written, and every atomic value in this pack was copied from the saved IOC list file, not from search summaries.
  • No campaign name: Dr.Web gives detection names only (Trojan.Loader.3261, Trojan.Clipper.688, JS.Stealer.191 and others). This pack coins nothing.
  • Hash type: Dr.Web publishes SHA-1 only. No MD5 or SHA-256 value exists in any source and none is invented.
  • Not borrowed: no indicator from other AsyncRAT or clipper campaigns is included.

Contradictions and gaps

  • The second IP (130[.]12[.]182[.]209) appears only in the IOC list (source 2). The report page (source 1) lists only the first address in its prose.
  • Cyber Press says the loader persists with scheduled tasks and registry Run entries. Dr.Web's report says only that the loader makes sure it is restarted automatically. Query 10 is therefore a hypothesis.
  • Dr.Web does not publish the commands used to disable Defender, UAC, System Restore and VSS, or to uninstall antivirus products. Queries 12, 14 and 15 cover the generic technique and need tenant validation.
  • The Telegram bot identifiers and the config.json decryption keys are not published. The hosts-file entries written for antivirus vendor domains are not listed.
  • Most hashed samples (.suo, .csproj, .go, .py, .ps1, app.asar) are not PE files, so process-image hash matching will rarely hit.

Immediate

  • Review the hosts file and the drivers\etc folder on developer and analyst hosts. (MITRE M1022 Restrict File and Directory Permissions)
Near term
  • Deploy ASR rules in audit mode first: block executable files unless they meet prevalence criteria, block obfuscated scripts, block JavaScript or VBScript launching downloaded executables. Promote after measuring FP. (MITRE M1038 Execution Prevention, M1040 Behavior Prevention on Endpoint; Microsoft Defender ASR rule reference)
  • Use application control (WDAC or AppLocker) to stop unsigned executables running from ProgramData and Public folders on non-administrator workstations. This is a path-and-publisher control, not a blocklist of Windows components. (MITRE M1038 Execution Prevention; Microsoft WDAC deployment guidance)
  • Keep Smart App Control or an equivalent reputation-based control enabled where supported, and alert on policy-state changes (Q13). (MITRE M1038 Execution Prevention)
  • Alert on DNS and proxy requests to Pastebin raw, Telegram t.me/s/, Google Docs and GitCode from non-browser processes (Q4). (MITRE M1037 Filter Network Traffic)

Strategic
  • Build and test security tooling from public repositories only inside disposable virtual machines or dev containers with no access to production credentials, password stores or SSH keys. (MITRE M1048 Application Isolation and Sandboxing)
  • Vet third-party tools: repository age, maintainer history, release signing, source review before first build, and a mirrored internal copy for approved tools. (MITRE M1017 User Training)
  • Reduce the value of what the stealer targets: FTP and SSH client credentials protected by master passwords or key agents, hardware-backed MFA, short-lived VPN credentials, no browser-saved passwords on analyst hosts. (MITRE M1027 Password Policies, M1032 Multi-factor Authentication, M1042 Disable or Remove Feature or Program)
