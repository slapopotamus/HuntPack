Executive Summary

MovieReaper is a previously unknown, modular, multi-stage Windows malware framework disclosed by Kaspersky's GReAT team on 17 September 2026. It is distributed by way of a supply-chain-style compromise of itorrents[.]org, a public torrent-file repository that many independent tracker sites rely on to serve .torrent files. Rather than compromising trackers one at a time, the attackers compromised the shared repository itself: when a victim follows a legitimate magnet link, the repository silently returns a malicious torrent file instead of the requested one. The lure observed most often is a fake release of the film "The Odyssey" (filename pattern: the odyssey (2026) [1080p] [webrip] [5.1].exe), though the same loader hash has shipped under many different movie-themed filenames.

The infection chain runs four stages: (1) a loader with anti-sandbox evasion that downloads shellcode over plain HTTP from deadhub[.]org (IP fallback 193.23.118[.]155) at URI paths disguised as image assets; (2) shellcode that queries the Solana blockchain's getAccountInfo RPC endpoint for a specific account to retrieve a base64-encoded, XOR-encrypted second-stage C2 address — using a public blockchain as takedown-resistant dead-drop storage; (3) a module that performs a UAC bypass and persists by masquerading as %ProgramData%\Microsoft\Windows\Telemetry\msedge.exe; and (4) a final "file manager" implant exposing 21 commands for filesystem read/write/enumerate plus thumbnail/preview generation so operators can triage valuable files before exfiltration. Kaspersky reports several hundred victims — individuals and organizations — across Europe, Asia, and Africa, spanning enterprise, government, IT, consulting, retail, transportation, and agriculture sectors, with activity from the same actor traced back to October 2025.

Novel durable signal: the Solana blockchain dead-drop resolution step is the most distinctive and hardest-to-evade behavioral signature in this pack — legitimate business processes essentially never call public Solana RPC endpoints (getAccountInfo and similar) from a non-browser, non-wallet, non-dev-tooling process. That behavioral pattern survives IP/domain rotation and is the centerpiece hunt in §8 (Q9).

Q9 · Novel Signal: Non-Browser Process Querying a Public Solana RPC Endpoint
CONF MEDIUMFP MEDIUMCOST MEDIUMHIGH VALUE — DURABLE

Looks for: the durable, IP/domain-rotation-resistant signal at the heart of this campaign — a non-browser, non-crypto-wallet process resolving a public Solana RPC hostname. Securelist's own text cites api.mainnet.solana.com specifically; this query also covers the well-known public mainnet-beta endpoint and several third-party public RPC providers, since the technique (querying any public Solana RPC for getAccountInfo) is what's durable, not any one hostname. Containment Runbook

Phase 1 — Isolate

  • Network-isolate (Falcon Network Containment) any host firing Q1 (confirmed hash), Q3/Q4 (Telemetry-folder drop/execution), or Q7/Q8 (confirmed C2 contact).
  • Treat any Q9 (Solana RPC) hit on a host with no documented blockchain-development role as presumptively malicious pending investigation.
  • Preserve current process/network/DNS Falcon telemetry for affected hosts before further remediation.

Phase 2 — Eradicate

  • Remove the persistence binary at %ProgramData%\Microsoft\Windows\Telemetry\msedge.exe and confirm no autostart entry (Run key/scheduled task/service) still references it — the exact autostart mechanism is undocumented by either source, so check all three categories.
  • Terminate any remaining loader/implant processes matching the confirmed hash set.
  • Because the final-stage implant is a 21-command file manager with file read/copy/preview capability, treat any host that reached Stage 4 as a potential data-exposure incident, not just a malware infection — inventory what files were accessible to the compromised user account.
  • Rotate credentials for any account active on an affected host during the suspected dwell window, prioritizing accounts with access to sensitive file shares (the file-manager implant's core capability is file access and exfiltration staging).

Phase 3 — Recover

  • Validate backup integrity from a copy predating the earliest suspected compromise indicator on the host.
  • Re-image affected endpoints where the persistence/UAC-bypass chain fully completed, rather than relying on in-place remediation of an undocumented autostart mechanism.
  • Re-verify Playbooks B and C (WDAC Telemetry-folder deny, UAC hardening) are in effect on rebuilt hosts before returning them to production.
