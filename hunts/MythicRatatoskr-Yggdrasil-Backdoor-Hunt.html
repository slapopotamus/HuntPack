Executive Summary

ESET Research (published 2026-10-22) documents an intrusion at a Ukrainian grain logistics company in which UAC-0099 gained initial access on 2025-07-16 with a spearphishing attachment, then deployed a previously undocumented Go backdoor, MythicRatatoskr, on 2025-07-17. Access was later handed to Sandworm, which carried out a data-wiping attack on 2025-09-17 by deploying the Sysinternals SDelete utility through Active Directory Group Policy. ESET attributes the early stage to UAC-0099 and the wiping stage to Sandworm, both with high confidence, and says it could not determine which group operated the backdoor.

MythicRatatoskr is notable for hiding its command-and-control server inside the Yggdrasil mesh network. It is built on the yggstack and yggdrasil-go libraries, connects to three randomly chosen peers from 32 hardcoded public Yggdrasil peers, and talks to a C&C reachable only as a Yggdrasil IPv6 address over HTTPS on port 443. It runs as a Windows service named ieupdate, keeps an AES-encrypted configuration in a dot-prefixed file, and supports shell, file transfer, screenshots, port exposure and a reverse SOCKS5 proxy. A separate Go SOCKS5 server, bindProxy, listens on 127.0.0.1:33690.

What this pack hunts. Because the C&C address lives inside the mesh, ordinary C&C blocking does not work. ESET says blocking the public peers is a viable mitigation, so this pack hunts the visible underlay (peer connections, service and file artifacts, the loopback listener, shell children) and the destructive stage (SDelete, especially one command line fanning out across many hosts). MATCHBOIL and MATCHWOK appear only as the documented delivery chain of this intrusion. They are covered in depth by the separate UAC-0099 pack and are not rebuilt here.

Defender priority: run Query 1 (the ieupdate service), Query 4 (ESET SHA-1 hashes) and Query 9 (port 33690) across 30 days now, then Query 12 for any SDelete fan-out. Block the 32 public Yggdrasil peers at egress and DNS. A wiping stage that follows a quiet backdoor by two months means a MythicRatatoskr hit should be treated as a pre-destructive intrusion: protect offline backups and the accounts that can edit Group Policy before anything else.

Web-hunter decisions

  • Second sourcing. Independent coverage (The Record, The Next Web) confirms the story but publishes no atomic indicators. Every hash, the C&C address and both domains therefore rest on ESET alone, and all ship at detect. No indicator ships at prevent. The Group Policy delivery of SDelete is likewise ESET-only; The Next Web only says "network settings".
  • SHA-1 discrepancy. The article lists the last ieupdate.exe hash ending ...996F1629D682...; the ESET GitHub file lists ...996F1429D682.... One is almost certainly a typo. Both are shipped and searched, and the spelling is labelled in the CSV. Re-check against ESET before relying on either.
  • C&C address. The article body gives the full address with the 201: prefix; its IoC table and the GitHub file drop the prefix. The body form is shipped (it is a valid 200::/7 address and matches the configuration table).
  • Not carried forward. Pages that tried to instruct this research: none observed. The GlobeNewswire press release returned Access Denied and is not cited. The lead hints about a Linux variant are kept as a labelled possibility only: ESET found indications, no sample.
  • Scope control. The library already carries a UAC-0099 pack (LUNCHPOKE, MATCHBOIL, Notepad++). This pack imports only the two delivery-chain indicators ESET ties to this intrusion (uztickets.com, egyptanimals.com) and three host artifacts (pdfopentask, temporarydoc.txt, UpdateMonitor).

Hardening: Tiered

Immediate (this week, low compatibility risk)
  1. Block the 32 public Yggdrasil peers at egress and DNS. ESET calls this a viable mitigation, and it is the only control that denies the backdoor its way into the mesh. MITRE M1037 Filter Network Traffic and M1031 Network Intrusion Prevention; CIS Controls v8 Control 13 (Network Monitoring and Defense). Verify: a test connection to a listed peer fails and Q5 and Q6 show only blocked attempts.
  2. Turn on the audit trail that the wiping stage depends on. Enable Audit Directory Service Changes on domain controllers (event 5136) and Audit Security System Extension everywhere (event 4697). MITRE M1047 Audit; Microsoft advanced security audit policy guidance and the CIS Microsoft Windows Server Benchmarks audit-policy section. Verify with auditpol /get.
  3. Shrink who can create, edit and link Group Policy. Remove GPO edit and link rights from everyone except named Tier 0 administrators. MITRE M1026 Privileged Account Management and M1018 User Account Management; Microsoft enterprise access model (tiering). Verify with Get-GPPermission.
  4. Protect backups from the wiper. Keep an offline or immutable copy that Group Policy cannot reach and test a restore. MITRE M1053 Data Backup (T1485); CIS Controls v8 Control 11 (Data Recovery).
Near term (1 to 4 weeks, pilot first)
  1. Application control for user-writable and System32 paths. Deny execution of unsigned binaries from Downloads, %LocalAppData% and user profile folders, and flag unsigned new files in System32. MITRE M1038 Execution Prevention; Microsoft WDAC / AppLocker documentation; CIS Controls v8 safeguards on authorized software allowlisting. Verify with Q2 and Q3 going quiet.
  2. Disable OpenSSH Server where it has no role. The intrusion moved implants through an OpenSSH SFTP server. MITRE M1042 Disable or Remove Feature and M1035 Limit Access to Resource over Network. Best-practice: no formal CIS item covers an unused optional Windows feature, flagged ⚠ best-practice, no formal benchmark. Verify with Get-Service sshd.
  3. Attack surface reduction for the email entry point. Audit then enforce the rules that block executable content from email clients and Office child processes. MITRE M1040 Behavior Prevention on Endpoint and M1049 Antivirus/Antimalware; Microsoft ASR rules reference. Requires Defender Antivirus in active mode.
  4. Default-deny egress for servers. Servers rarely need arbitrary outbound TLS on odd ports; allow named destinations only. MITRE M1037; CIS Controls v8 Control 13.
Strategic (1 to 3 months, architecture or budget)
  1. Privileged access workstations and a GPO change workflow. Only a hardened admin tier edits Group Policy, with change approval and an alert on any GPO change near a business off-hours window. MITRE M1026, M1032 Multi-factor Authentication; Microsoft enterprise access model.
  2. Inspect or proxy all outbound TLS from server tiers so mesh and tunnel traffic is visible even when addresses are not on a list. MITRE M1031.
  3. Treat an ieupdate hit as a Tier 0 compromise. Pre-plan the credential reset, SYSVOL review and rebuild procedure so containment starts hours, not days, after detection (Section 14).

Playbook 1: egress block of the hardcoded Yggdrasil peers (Windows Firewall)

Step 1. Block the ten raw-IP peers outbound on managed Windows hosts.
Prerequisites: local administrator or a GPO with firewall write rights; confirm no sanctioned Yggdrasil use (Q5 baseline).
Reboot required: No
$peers = @('37.205.14.171', '109.176.250.101', '65.21.57.122', '95.217.35.92', '51.255.223.60', '51.15.204.214', '62.210.85.80', '23.137.249.65', '78.27.153.163', '193.93.119.42')
New-NetFirewallRule -DisplayName 'HuntPack-Block-Yggdrasil-Peers' -Direction Outbound -Action Block -RemoteAddress $peers -Profile Any
Verify: Get-NetFirewallRule -DisplayName 'HuntPack-Block-Yggdrasil-Peers' | Get-NetFirewallAddressFilter
Rollback: Remove-NetFirewallRule -DisplayName 'HuntPack-Block-Yggdrasil-Peers'

Step 2. Sinkhole the hostname peers on the internal DNS server (Windows DNS policy shown; use your resolver's RPZ equivalent otherwise).
Prerequisites: Windows Server 2016 or later DNS role; DnsServer module; run on each DNS server.
Reboot required: No
Add-DnsServerQueryResolutionPolicy -Name 'HuntPack-Block-Ygg-yt' -Action DENY -Fqdn 'EQ,*.ygg.yt'
Add-DnsServerQueryResolutionPolicy -Name 'HuntPack-Block-Ygg-neilalexander' -Action DENY -Fqdn 'EQ,yggdrasil.neilalexander.dev'
# repeat for the remaining hostnames in the Yggdrasil Public Peer List block
Verify: Resolve-DnsName g.ygg.yt -Server <dns-server>   (expect a refusal)
Rollback: Remove-DnsServerQueryResolutionPolicy -Name 'HuntPack-Block-Ygg-yt' -Force   (and each additional policy name)

Playbook 2: audit policy for Group Policy changes and service installs

Step 1. Record the current audit policy, then enable the two subcategories.
Prerequisites: domain admin for the DC step; run the first command on every host you change.
Reboot required: No
auditpol /backup /file:C:\Windows\Temp\audit-before.csv
auditpol /set /subcategory:"Directory Service Changes" /success:enable      (domain controllers)
auditpol /set /subcategory:"Security System Extension" /success:enable      (all hosts)
Verify: auditpol /get /subcategory:"Directory Service Changes","Security System Extension"
Rollback: auditpol /restore /file:C:\Windows\Temp\audit-before.csv
Note: size the Security log first; Directory Service Changes is moderately chatty on busy DCs.

Playbook 3: disable OpenSSH Server where unused

Step 1. Stop and disable the sshd service on hosts with no sanctioned SSH role.
Prerequisites: inventory of administrators who rely on SSH; confirm with Q15 baseline.
Reboot required: No
if (Get-Service sshd -ErrorAction SilentlyContinue) { Stop-Service sshd -Force; Set-Service sshd -StartupType Disabled }
New-NetFirewallRule -DisplayName 'HuntPack-Block-Inbound-22' -Direction Inbound -Protocol TCP -LocalPort 22 -Action Block
Verify: Get-Service sshd | Select Status,StartType
Rollback: Set-Service sshd -StartupType Automatic; Start-Service sshd; Remove-NetFirewallRule -DisplayName 'HuntPack-Block-Inbound-22'

Playbook 4: attack surface reduction rules in audit mode

Step 1. Audit the email-executable and Office child-process rules for 30 days before enforcing.
Prerequisites: Microsoft Defender Antivirus in active mode (ASR is not applied in passive mode, so skip this on hosts where another AV is primary).
Reboot required: No
Add-MpPreference -AttackSurfaceReductionRules_Ids be9ba2d9-53ea-4cdc-84e5-9b1eeee46550,d4f940ab-401b-4efc-aadc-ad5f3c50688a -AttackSurfaceReductionRules_Actions AuditMode,AuditMode
Verify: Get-MpPreference | Select AttackSurfaceReductionRules_Ids,AttackSurfaceReductionRules_Actions
Rollback: Remove-MpPreference -AttackSurfaceReductionRules_Ids be9ba2d9-53ea-4cdc-84e5-9b1eeee46550,d4f940ab-401b-4efc-aadc-ad5f3c50688a

Playbook 5: Group Policy edit-rights review (read-only, no change)

Step 1. List who can edit or link each GPO, then review for non-Tier-0 principals.
Prerequisites: GroupPolicy module (RSAT); domain read access.
Reboot required: No
Get-GPO -All | ForEach-Object { $g=$_; Get-GPPermission -Guid $g.Id -All | Where-Object { $_.Permission -match 'GpoEdit|GpoEditDeleteModifySecurity' } | Select @{n='GPO';e={$g.DisplayName}},Trustee,Permission }
Rollback: none required, this step only reads permissions. Any later permission removal is reverted with Set-GPPermission using the saved output.
