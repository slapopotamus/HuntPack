NIK C2: AI-Enabled Command-and-Control Framework

NIK C2 is a Go-based, 64-bit Windows remote access framework with a dual-channel C2, AES-256-GCM encrypted traffic and a built-in client for the OpenAI Chat Completions API, so an operator can have a model analyse harvested data inside the compromised session. It also carries a screen-locking ransomware module and a bootkit-preparation stub. Built on the Cisco Talos report of 2026-10-29. No actor is named.

Executive Summary

Attacker objective. NIK C2 is a remote access framework for Windows. Once the implant runs, the operator can dump browser credentials, cookies, Discord tokens, cryptocurrency wallets and saved Wi-Fi passwords, stream every keystroke, capture the screen, camera and microphone, tunnel into the internal network through an embedded SOCKS5/HTTP proxy, and deploy a screen-locking ransom screen that demands Bitcoin or USDT. [#1]

Why it is different. The implant embeds an OpenAI client behind an ai_generate command. The operator's prompt travels over the C2, the victim machine calls api.openai.com/v1/chat/completions and the answer goes back encrypted. If the operator supplies no API key, the implant uses the victim's OPENAI_API_KEY environment variable, so the victim pays for the operator's inference and the provider's logs show the victim's key. The default model string is gpt-4. Talos argues that collection and analysis now happen in one live session, which removes the offline delay defenders used to rely on. [#1]

What is not known. Talos names no actor and describes no delivery vector. It saw at least three versions, all built with Go 1.23.4, and describes a technically proficient team with prior malware experience. It assesses with moderate confidence that this is a functional framework and not a proof of concept, because it saw active infrastructure. The public indicator set is small: 8 sample hashes, 1 domain and 2 IP addresses. [#1] [#2]

What this pack does. Because the indicator list is short and perishable, most of the pack is behavioral: the screen-lock launch chain, the SystemLock Run value, the fodhelper registry key, the raw MBR read, the chcp 65001 recon prefix, netsh Wi-Fi key extraction, system-process names running from the wrong folder, and the boot-firmware survey. The indicators ship as detect. None ships as prevent, because every value comes from one vendor.

Defender priority. Run Q12 (system-process names outside System32) and Q4 to Q7 over 30 days first: they catch the implant by what it does and do not depend on a hash or a domain. Then run Q1 to Q3 for the published indicators. Treat any host that matches as having lost every browser, wallet, Wi-Fi and Discord secret, and rotate before you rebuild.

Decisions and discrepancies

  • Single vendor. Sources 1 to 3 are one publisher. No indicator is corroborated by an independent team, so no row ships as prevent and nothing is marked critical. [#1] [#2] [#3]
  • Second IP. The IP 2.26.51.12 and the URL on port 4443 appear in the IOC repository and not in the article text. They are Talos-published and for the same report, so they ship as detect with that caveat. The URL is not shipped as a separate row because its host is already covered. [#2] [#3]
  • Link spelling. The article text prints the OpenAI URL with a stray space after the scheme. The endpoint is https://api.openai.com/v1/chat/completions; the query matches only the host name because DNS carries no path. [#1]
  • Build identifier. The build path /opt/nik_panel/data/build_52b79724a1fc4b8f/main.go is in the article. The article says an eight-byte hex token matching the build identifier is embedded in the implant; the value is not listed separately, so it is carried only as part of the path. [#1]
  • Published cryptographic material. The article prints the decoded AES seed and the derived 32-byte key. These are useful for memory or traffic decryption in an analysis lab and are not endpoint-log indicators, so they are not in the CSV.
  • Not in any source. Delivery method, victims, actor, panel pricing or sale model. The pack does not assume any. Related-cluster indicators from other reports are deliberately excluded.
