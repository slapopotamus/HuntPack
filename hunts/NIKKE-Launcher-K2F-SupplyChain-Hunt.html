Executive Summary

What happened. The publisher, Level Infinite, confirmed on 2026-11-04 that the PC launcher's script files may have been tampered with by a third party, and shipped a client fix. An independent researcher (MotherSphere) reports that four official JavaScript files on the publisher's CDN were modified on 2026-09-27 to carry an obfuscated loader. BleepingComputer examined two of the modified files itself and confirmed the loader retrieves and executes code from insightjs.com, falling back to insightjs.org.

What the chain does. Per the researcher, the downloaded code abuses the launcher's native download function to fetch a LuaJIT payload named insight.bundle, which runs a remote-access agent called K2F inside the launcher. The agent can run commands, browse and download files, take screenshots, collect NIKKE account credentials and steal browser-stored data. A further command installs platform_experience_helper.dll, which can stay active after the launcher closes. BleepingComputer found strings in a VirusTotal DLL sample that indicate wallet-extension theft code (MetaMask, Phantom, Coinbase Wallet and others), including recovery phrases and private keys.

What is not established. BleepingComputer states it is unknown whether the attackers deployed the wallet-stealing DLL on infected systems or stole any cryptocurrency. The log string k2f_chan registered shows the Lua agent ran; it does not confirm the DLL loaded. The publisher and the researcher disagree on when distribution began (publisher: 2026-10-30; researcher: agent starts reported from 2026-10-23). The updated launcher can erase infection evidence, so the log and cache are perishable.

Sourcing. There is no vendor analysis. The technical detail comes from one independent researcher's static analysis of one infected machine plus victim reports in the gist comments (marked "reported" in the source and treated here as unverified). BleepingComputer and Malwarebytes relay it; the publisher notice confirms the check steps. Confidence is stated accordingly throughout. No actor, campaign or malware name beyond those the sources print (K2F, insight.bundle) is used.

Hunt posture. Seven CQL queries cover the loader and agent network indicators, launcher-spawned shells, the COM persistence key, and the DLL. The in-process agent commands (credential reads, screenshots, file reads) spawn no process, so they have no endpoint query; the native checks in Section 7 and the evidence-preservation playbook cover that gap. Only the two domains insightjs.com and insightjs.org carry a prevent action (two independent lines of evidence). Everything else ships detect.

Defender priority. On any host that opened the Windows launcher since 2026-09-27, copy Launcher\intl_service\debug.log, the Launcher\log folder and tbs_cache BEFORE the launcher is opened again, then search the log for k2f_chan registered. Do the evidence copy first: the updated launcher can delete these files. Rotate credentials from a clean device if the string is found.

Decisions

  • No vendor analysis exists. No endpoint or threat-intel vendor has published analysis of K2F. The confidence assessment in the header reflects a single independent origin plus BleepingComputer's own partial verification.
  • Two lines of evidence for the loader domains. BleepingComputer examined the modified files itself, separately from the researcher. That is why insightjs.com and insightjs.org are the only prevent rows. analytics.insightjs.com, the IP addresses and every hash are single-sourced to the researcher and ship detect.
  • The file names are published. The researcher names the four modified files (Section 4). They share their names with the clean, legitimate files, so a name alone proves nothing; only the hash or the loader content does. Nothing here blocks by file name.
  • The VirusTotal value. BleepingComputer links a VirusTotal page for a DLL sample. The 64-hex value is the link path; the article never labels it a hash. It ships labelled exactly that way, single-sourced, detect only. The researcher states the installed DLL is built per victim, so a hash match is not expected to be common.
  • Excluded. A separate script-download lure that a gist comment pushed is stated by the researcher not to be part of this attack and is not used. The researcher's clean-file hashes are not shipped (they identify legitimate files).
  • Fetch notes. BleepingComputer returned HTTP 403 to a scripted request; its text was captured through a browser session. The publisher page renders client-side and was captured the same way. A summarising fetch tool returned date errors for the BleepingComputer updates and was not used as a source. The publisher's separate follow-up notice and the X statement were not fetched; they are cited only through the sources above.
  • Prior ledger entry. An earlier one-article drop for this incident failed on sourcing (no payload description). That gap is now closed by the researcher's analysis and BleepingComputer's examination.

07

Native Audit-Log Hunts

Start here. The strongest evidence lives in files that no endpoint query sees. All steps below are read-only. Preserve before you clean (Playbook 1).

7.1 Launcher log

Search Launcher\intl_service\debug.log under each install (for example the default folder and the Google Play Games folder) for k2f_chan registered. A hit means the Lua agent ran. It does not confirm the DLL loaded. After the updated launcher has run, a missing log or a clean result proves nothing, because the launcher can delete the log. A related line startup failed: EIO: invalid UTF-8 in string can follow when the Windows user name is non-ASCII; the agent was still downloaded and ran (researcher, reported).

7.2 Payload file on disk

List Launcher\log\tinyget. The publisher says to look for a 205,135-byte tinyget.<date>-<time>.log. The researcher adds that size varies by build and that any file there starting with bytes 1B 4C 4A 01 is the agent. The file is normally deleted within seconds, so its presence usually means the download stopped early. The same folder's request log records the insight.bundle download; a download is only complete if a later line for the same task shows success (researcher).

7.3 Persistence

For each user profile, check HKCU\Software\Classes\CLSID\{E77CC89B-7401-4C04-8CED-149DB35ADD04} (the HKLM copy is legitimate and must be left alone) and list 64-hex subfolders under %LOCALAPPDATA%\Google\Chrome\User Data\PlatformExperienceHelper\ that contain platform_experience_helper.dll. A process that loaded the DLL can keep it locked after the browser closes, so a restart may be needed before removal. A clean antivirus scan does not mean the DLL is absent: the researcher reports Microsoft Defender Offline missed it on one machine.

7.4 Launcher cache

Search %APPDATA%\nikke_launcher\tbs_cache\Local Storage\leveldb\ (and the _hmt and _google variants) for the text k2f.agent. A hit counts; no hit is weaker evidence because the record can sit in a compressed table. The Code Cache folder holds loader entries with a timestamp of when each loader last ran (about 200 bytes, no script). Preserve the whole folder before deleting it: it can still hold the modified scripts, which the launcher would load again.

7.5 DNS, proxy and router logs

A lookup of insightjs.com means the loader ran. A lookup of analytics.insightjs.com most likely means the agent stage was reached (researcher). A resolver log only sees queries sent to it: on one infected PC that also used an IPv6 DNS server from the router, the resolver log had no agent-stage lookup, so a log without it does not rule the agent out (reported).

7.6 Perishable forensic artifacts

  • Temporary files k2f-bcreds-*.db and k2f_screen_* in the temp folder are normally deleted right after use; one leftover was reported. Finding none proves nothing.
  • The NTFS change journal can still show the payload and temp-database create and delete records (researcher: run the journal read as administrator). The journal is a fixed size; check the date of its oldest record before treating an empty result as a negative.
  • SRUM bytes-sent per program per hour can show bulk upload under the launcher's embedded browser process (researcher, reported). A TUN-mode proxy can book the traffic to the proxy process instead.
  • Antivirus names reported by users for cache traces: Trojan.Loader.K2F, Trojan.Trace.K2F. Removing them removes evidence; copy first.

7.7 Account and wallet exposure

If the agent ran, assume anything the Windows user could read was readable, including saved browser passwords, cookies, developer tokens and wallet-extension data. The researcher notes the launcher manifest reportedly requests administrator rights (reported), which would widen reach. Review sign-in and token-use logs for the affected accounts from 2026-09-27, and treat any wallet whose recovery phrase may have been entered while the DLL could have been active as exposed (deployment is unconfirmed).

Hardening: Tiered & Deployable

Immediate (this week)
  1. Preserve before cleaning. Copy the launcher log, log folder and tbs_cache off host before the launcher or any cleanup touches them (Playbook 1). Authority: MITRE M1047 Audit (evidence), publisher notice. Verify: the copy exists and its hash file matches.
  2. Block the two loader domains at DNS and web proxy. insightjs.com and insightjs.org (Playbook 2). Authority: MITRE M1031 Network Intrusion Prevention and M1037 Filter Network Traffic. Two lines of evidence (BleepingComputer, researcher). Verify: Resolve-DnsName insightjs.com returns the sinkhole or no answer from a managed host. Blocking by IP is not shipped (single-sourced, and the main address is reported shut down).
  3. Find where the launcher is installed. Inventory hosts with the launcher or the Google Play Games build; on managed corporate endpoints it is rarely a business need. Authority: MITRE M1033 Limit Software Installation; CIS Controls v8 Control 2 (software asset inventory). Verify: a process-creation hunt for the launcher image names in your telemetry over 60 days.
Near term (1 to 4 weeks, pilot first)
  1. Stop saving passwords in the browser on machines that run third-party launchers. The agent's browserscan reads saved logins; managed-browser policy PasswordManagerEnabled=0 removes the stored set (Playbook 5). It does not stop a DLL reading what is typed into pages. Authority: MITRE M1027 Password Policies; vendor Chrome Enterprise policy. Pilot with a ring first; users lose the built-in password prompt.
  2. Extension allowlist for wallet and password-manager extensions. Use the managed-browser extension allowlist so only approved extensions install. Authority: MITRE M1038 Execution Prevention; vendor Chrome Enterprise policy (ExtensionInstallAllowlist). Verify: chrome://policy shows the policy as applied.
  3. Standard users, not local administrators. The researcher reports the launcher manifest requests administrator rights (reported), which lets the agent reach more. Keep gaming users out of the local Administrators group. Authority: MITRE M1026 Privileged Account Management. Verify: net localgroup Administrators on a sample.
  4. DNS filtering on workstations. Route endpoint DNS through a filtering resolver and make that the only path, so the IPv6-resolver bypass the researcher reports cannot hide lookups. Authority: MITRE M1037 Filter Network Traffic. Verify: disable IPv6 resolver advertisement from the router or confirm a test lookup appears in the filter log.
Strategic (1 to 3 months)
  1. Application control for user-writable DLL paths. Deny DLL loads from user profile folders (WDAC or AppLocker DLL rules, audit mode first). Authority: MITRE M1038 Execution Prevention; Microsoft Windows application control guidance. Verify: Get-AppLockerPolicy -Effective or the WDAC policy summary, then a CQL spot-check that Q5 and Q7 stay silent.
  2. Treat third-party launchers and updaters as untrusted code paths. Run them on unmanaged devices or isolated profiles, not on machines that hold work credentials or wallets. Authority: MITRE M1048 Application Isolation and Sandboxing; NIST SP 800-161 supply chain risk practice. Verify: asset inventory shows no launcher on privileged-user devices.
  3. Linux and Steam Deck through Proton. The researcher states Proton does not protect the user: the compatibility layer exposes the home folder and environment variables to the game. Run the launcher in a sandbox that withholds the home folder and secrets. ⚠ best-practice, no formal benchmark. Verify: from inside the sandbox, a read of a home-folder secret file fails.

Controls that disable or block legitimate product files are deliberately absent. The pack does not recommend blocking the launcher's own binaries.
