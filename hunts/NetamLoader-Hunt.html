Executive Summary

NetamLoader is a layered .NET loader that Kaspersky GReAT disclosed on 2026-10-29 (Securelist and a press release, presented at Security Analyst Summit 2026). It was found on a single host running a customized Windows 10 build used only by government organizations in an Asian country. Kaspersky has not attributed it to any known actor and did not see how the package arrived, but the location and contents point to a possible software supply chain attack.

The chain starts with a CAB archive in the Windows update download area. Its seven files unpack into C:\Windows\SoftwareDistribution\Download\Install. When a legitimate, signed PatchMyPC-ScriptRunner.exe starts, a planted PatchMyPC-ScriptRunner.exe.config makes the .NET runtime load a Microsoft-signed assembly, which reads fabric.config, which in turn makes Resources.resx deserialize nested payloads. Layers of encoding, compression and encryption lead to an AMSI patch, a cleanup stage that deletes the dropped files, CLR usage logs, Prefetch files and selected update-log lines, and finally a plugin that runs inside dllhost.exe, started through a remote COM object so that it leaves the original process tree. After a random 20 to 40 minute pause it polls an HTTPS C2 on openaigpt4v.com, which sits on Cloudflare's CDN.

Defensive angle. The files are legitimate or inert, so hashes alone will not carry this hunt. The durable signals are where and how things run: the Patch My PC wrapper and its companion DLLs under SoftwareDistribution\Download\Install, a dllhost.exe that makes outbound connections, DNS for the C2 domain, and gaps in locally kept logs. Kaspersky says Patch My PC and its distribution systems were not shown to be compromised, so none of its files or hashes ship as a block here.

Defender priority: run Q1, Q2 and Q6 over 30 to 90 days now, then check that update and CLR logs are forwarded off the endpoint. Everything in this pack ships at detect. The domain and file hashes come from one vendor report, and the stock Patch My PC and Windows binaries must never be blocked.

Decisions and judgment calls

  • One technical origin. The Hacker News and the press release restate the Securelist report, so they are not independent confirmation. Nothing in this pack is therefore eligible for prevent or critical severity.
  • Cloudflare is hosting, not fronting. Securelist says the C2 address belongs to Cloudflare's CDN and the domain is registered with Cloudflare. It does not describe domain fronting, so this pack does not claim it.
  • Country not named by Kaspersky. Kaspersky says only "an Asian country". The Hacker News speculates about which one. That is not carried into this pack.
  • Delivery and persistence unknown. Kaspersky did not observe how the CAB arrived and describes no persistence mechanism. The plugin ends itself after roughly 28 hours (config value wi of 100801 seconds), so a restart would need a fresh delivery.
  • CAB name length. Securelist prints the CAB name as 40 hex characters. The Hacker News prints 39. The Securelist value is used.
  • Hash reuse. The report lists MD5 values only. Seven of the eleven belong to in-memory payloads that normally never touch disk, so only the four on-disk items go into the import CSV.
  • Fetched content. No fetched page contained text directed at the analyst or the pipeline.

Hardening, Tiered & Deployable

NetamLoader is delivered malware with no CVE, so there is no patch. Hardening targets what it needs: a place to run signed binaries with attacker-controlled config files, local logs it can edit, and a COM surrogate that can reach the internet. Controls are anchored to MITRE mitigations from the saved ATT&CK pages and to the Kaspersky and Patch My PC statements in the snapshots.

Immediate: this week, no user-visible change
  • Audit the update download folder. Run the read-only inventory in P1 on a sample of hosts. Kaspersky advises monitoring this folder for unexpected executables and configuration files. M1047 Audit (T1685). Vendor advisory: Kaspersky press release.
  • Forward logs off the endpoint and alert on gaps. Send Windows event logs, update-agent logs and EDR telemetry to a central store, and alert when a host's local log goes missing lines. NetamLoader deletes local copies. M1029 Remote Data Storage (T1070). Vendor advisory: Kaspersky. ⚠ best-practice, no formal benchmark for the update-agent log.
  • Scope any Patch My PC exclusion by path, not by name. The vendor article recommends excluding PatchMyPC-ScriptRunner.exe from ASR rules. That is safe only for its CCMCache and IMECache staging folders. A by-name exclusion would also cover the copy abused here. Check with P3. M1047 Audit (T1685). Judgment call: the vendor article does not say to scope by path.
  • Turn on Q1, Q2 and Q6 as scheduled detections at detect severity, after the 30-day look-back is clean.
Near term: 1 to 4 weeks, pilot on a ring first
  • Application control in audit mode for the update download folder. Audit execution from SoftwareDistribution\Download with AppLocker, then enforce on a ring once the audit log is clean (P2). M1038 Execution Prevention (T1685, T1574.014 context). Edition and policy-mode limits apply: ⚠ verify AppLocker support on a customized Windows 10 build.
  • Baseline COM surrogate registrations. List every AppID that carries a DllSurrogate value and review changes (P4). M1026 Privileged Account Management and M1048 Application Isolation and Sandboxing (T1559.001: AppID registry permissions under HKLM\SOFTWARE\Classes\AppID).
  • Egress control for dllhost.exe. Where policy allows, block or alert on outbound internet access from dllhost.exe at the host firewall or proxy. ⚠ best-practice, no formal benchmark.
Strategic: 1 to 3 months
  • Verify the origin of every update package. Inventory the tools allowed to place packages in the update folder, require signature verification of each, and run third-party management tools only from approved locations. Vendor advisory: Kaspersky press release. Supports T1195.
  • Write-protect .NET application directories. Install .NET software in locations that standard and service accounts cannot write to, including the folders applications run from. M1022 Restrict File and Directory Permissions (T1574.014). Note the loader needs administrator rights, so this reduces but does not remove risk.
  • Managed-code application control. Prefer WDAC policies that control which .NET assemblies and configs a signed host may load, over name-based allow lists. M1038. ⚠ best-practice, no formal benchmark.
  • Network anomaly monitoring for infrequent encrypted connections to unfamiliar hosts behind content delivery networks, including 22 to 28 hour retry cadences. Vendor advisory: Kaspersky press release (KATA is Kaspersky's product; any NDR with long-window analytics fits).
