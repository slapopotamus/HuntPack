Executive Summary

Neutrino ransomware (also called the Neutrino virus by PCrisk) is a Windows file-encrypting, double-extortion family that CYFIRMA reported in its Weekly Intelligence Report dated 2026-11-13, after finding it while monitoring underground forums. It replaces file names with random strings and appends .neutrino (example in the sources: 1.jpg becomes 5xnraLY2.neutrino), drops README-RECOVERY.txt into affected directories, changes the desktop wallpaper to an encryption notice with a victim reference ID, and deletes Volume Shadow Copies with vssadmin.exe and wmic. The note claims data theft and a leak-or-sell deadline, and sends victims to a Telegram bot to negotiate. The theft claim is the attackers' own and is unverified.

This is a behavior-led pack, by design. The primary source contains no atomic indicators in its Neutrino section (its IOCs paragraph only says to refer to an IOCs section that holds no values for this family). Across three snapshotted sources the only atomic hash is one SHA-256 for a sandbox sample named win-x64.exe, single-sourced and shipped as detect. There is no confirmed C2 infrastructure. The detection value is in the recovery-inhibition command lines, the note and extension artifacts, the wallpaper change and bulk file behavior.

Not the Neutrino exploit kit. This pack covers the 2026 .neutrino ransomware only. The older Neutrino exploit kit (and the unrelated Neutrino botnet builder) share the name and nothing else that these sources establish: none of their history, tactics or indicators is used here. Gridinsoft explicitly warns against treating the exploit kit, a similarly named bot or a generic antivirus family label as the same threat.

Defender priority: alert on shadow copy deletion (Q1, Q2) and protect backups first. That command is the earliest high-fidelity signal in the sources, it fires before encryption completes, and offline backups are the only reliable recovery path (no public decryptor was listed in the No More Ransom catalog as of 2026-11-04, per Gridinsoft).

  • T1489 not in the primary table. Service stop (T1489) was supplied with the task but does not appear in CYFIRMA's ATT&CK table or text. It is shipped only as a low-confidence precursor hunt (Q8) and labelled as such.
  • Not carried forward. The BleepingComputer forum thread surfaced in search returned HTTP 403 to the fetch and was not snapshotted or cited. The VirusTotal behavior page cited by Gridinsoft is a script-rendered page and could not be read, so the sandbox findings are taken at second hand. A victim client ID that PCrisk prints from a sample note is victim-specific and was not carried.

  • Prompt-injection check. No instruction-like text aimed at an AI agent was found in any of the three fetched pages.

07

Native Audit-Log Hunts

Endpoint telemetry alone cannot see the file writes that matter most for this family. These checks use native logs and file-server controls.

  • File creation audit (Sysmon Event ID 11 or Windows object-access auditing on shares): any file named README-RECOVERY.txt or ending .neutrino. Many directories receiving the same note name within minutes is the high-confidence shape.
  • Process creation with command line (Sysmon Event ID 1 or Security Event ID 4688 with command-line auditing): run the Q1, Q2 and Q3 logic. Without command-line auditing enabled the shadow delete is invisible; see playbook P4.
  • Registry set (Sysmon Event ID 13): HKCU\Control Panel\Desktop\Wallpaper written by a process other than the shell or your wallpaper manager.
  • PowerShell script block logging (Event ID 4104): shadow, delete, Remove-WmiObject and Win32_ShadowCopy strings. Encoded commands from endpoint-management agents are a known false-positive source per the source Sigma rule.
  • Service installation (System log Event ID 7045): new services with binaries in user-writable paths (Q10 logic).
  • File server FSRM: a passive file screen for the two artifact patterns (playbook P5) gives an alert before analysts see user tickets.
  • Triage lookups: check the SHA-256 in section 4 against VirusTotal by hand and record the result in the ticket; this pack could not read that page.

CrowdStrike LogScale CQL Hunt Queries

Pick your tenant's cloud first. Every "Open in Falcon" button below uses this selection.
Q1 · Reported shadow copy deletion command lines (vssadmin / wmic)
CONF HIGHFP MEDIUMCOST LOW

Looks for: The two inhibit-recovery command lines CYFIRMA reports for Neutrino: vssadmin.exe Delete Shadows /all /quiet and wmic shadowcopy delete /nointeractive. Both binaries are native Windows tools, so this is a detection surface and never a block rule. FP: Administrators reclaiming disk space, imaging and backup agents that manage shadow storage. Exclude a backup agent by its parent process and signer after baselining, and confirm any hit against a change ticket.

// HUNT: Neutrino-reported shadow copy deletion (vssadmin / wmic)
// MITRE: T1490, T1047
// CONF: high  FP: medium  COST: low
// REQUIRES: process creation with command line (ProcessRollup2)
// FALSE POSITIVES: admin disk cleanup, backup and imaging agents managing shadow storage
// TUNING: exclude the backup agent parent (ParentBaseFileName) once baselined, scoped by hash or signer, not by name alone
// LOOKBACK: 7d
#event_simpleName=/ProcessRollup2|SyntheticProcessRollup2/
| FileName=/^(vssadmin|wmic)(\.exe)?$/i
| CommandLine=/(delete\s+shadows|shadowcopy\s+delete)/i
| table([@timestamp, ComputerName, UserName, FileName, CommandLine, ParentBaseFileName, SHA256HashData], limit=1000)
Q2 · Shadow copy and backup destruction, Sigma parity (powershell, wmic, vssadmin, diskshadow, wbadmin)
CONF HIGHFP MEDIUMCOST LOW

Looks for: A CQL port of the Sigma rule CYFIRMA ships for Neutrino (Shadow Copies Deletion Using Operating Systems Utilities): shadow plus delete on powershell, pwsh, wmic, vssadmin or diskshadow; wbadmin with delete, catalog and quiet; vssadmin resize shadowstorage with unbounded or MaxSize=. Covers T1490 and, for hidden powershell, T1564.003. FP: The Sigma rule itself lists legitimate administrator deletion and LANDesk LDClient / Ivanti PS EncodedCommand activity. Exclude the Ivanti agent by its parent hash or signer. Do not exclude on the string LDClient in the command line, because an attacker can add that string.

// HUNT: Shadow copy / backup destruction via OS utilities (Sigma parity)
// MITRE: T1490, T1564.003
// CONF: high  FP: medium  COST: low
// REQUIRES: process creation with command line (ProcessRollup2)
// FALSE POSITIVES: legitimate administrator shadow deletion; LANDesk LDClient / Ivanti-PSModule (PS EncodedCommand), per the source Sigma rule
// TUNING: exclude the Ivanti/LANDesk agent as a parent by hash or signer after confirming its image in your tenant; never by command-line string
// LOOKBACK: 7d
#event_simpleName=/ProcessRollup2|SyntheticProcessRollup2/
| FileName=/^(powershell|pwsh|wmic|vssadmin|diskshadow|wbadmin)(\.exe)?$/i
| case {
    FileName=/^wbadmin/i and CommandLine=/delete/i and CommandLine=/catalog/i and CommandLine=/quiet/i | Match := "wbadmin delete catalog quiet";
    FileName=/^vssadmin/i and CommandLine=/resize/i and CommandLine=/shadowstorage/i and CommandLine=/(unbounded|maxsize=)/i | Match := "vssadmin resize shadowstorage";
    FileName=/^(powershell|pwsh|wmic|vssadmin|diskshadow)/i and CommandLine=/shadow/i and CommandLine=/delete/i | Match := "shadow delete via OS utility";
    * | Match := "none";
  }
| Match != "none"
| table([@timestamp, ComputerName, UserName, FileName, Match, CommandLine, ParentBaseFileName], limit=1000)

// HUNT: .neutrino extension on files touched by ransomware-protection telemetry
// MITRE: T1486
// CONF: medium  FP: low  COST: low
// REQUIRES: ransomware-protection file-open telemetry (RansomwareOpenFile). Validate in tenant that TargetFileName holds the renamed file

| TargetFileName=/\.neutrino$/i
| groupBy([aid, ComputerName], function=[count(as=NeutrinoFiles), min(@timestamp, as=FirstSeen), max(@timestamp, as=LastSeen)], limit=500)

Q6 · Bulk file-open burst on one host (encryption-in-progress shape)
CONF MEDIUMFP MEDIUMCOST MEDIUM

Looks for: More than 100 ransomware-protection file-open events on a single host in the search window. Behavioral and family-agnostic: Neutrino sources give no encryption-rate figure, so the threshold is a starting point to tune, not a reported value. FP: Backup, antivirus full scans, large archive extraction and file-sync clients. Raise the threshold or exclude the known scanner after a 14 day baseline.

// HUNT: bulk ransomware-protection file-open burst per host
// MITRE: T1486
// CONF: medium  FP: medium  COST: medium
// REQUIRES: ransomware-protection file-open telemetry (RansomwareOpenFile)
// FALSE POSITIVES: backup agents, full AV scans, large archive extraction, sync clients
// TUNING: baseline 14 days, then raise the 100 threshold or exclude the scanning image by signer
// LOOKBACK: 1d
#event_simpleName=RansomwareOpenFile
| groupBy([aid, ComputerName], function=[count(as=FilesTouched), min(@timestamp, as=FirstSeen), max(@timestamp, as=LastSeen)], limit=500)
| FilesTouched > 100
| sort(FilesTouched, order=desc)

Q8 · Mass service stop targeting backup, database and security services
CONF LOWFP HIGHCOST LOW

Looks for: Service-stop command lines aimed at backup, database or security services. T1489 was supplied with the task but is not in CYFIRMA's Neutrino ATT&CK table, and the sources show no service-stop command, so treat this as a generic pre-encryption precursor hunt with low confidence. FP: Patch windows, software installers and admin maintenance stop services routinely. Alert only on 3 or more distinct stop commands per host in the window, and exclude change windows and the patching agent.

// HUNT: burst of service-stop commands for backup / SQL / security services
// MITRE: T1489 (reported to the requester, NOT in the CYFIRMA table)
// CONF: low  FP: high  COST: low
// REQUIRES: process creation with command line (ProcessRollup2)
// FALSE POSITIVES: patching, installers, scheduled maintenance, admin scripts
// TUNING: exclude the patch/software-deployment agent parent and change windows; keep the 3+ distinct commands threshold
// LOOKBACK: 1d
#event_simpleName=/ProcessRollup2|SyntheticProcessRollup2/
| FileName=/^(net|net1|sc|taskkill|powershell|pwsh)(\.exe)?$/i
| CommandLine=/(stop-service|\bnet1?\s+stop|\bsc(\.exe)?\s+(config|stop)|taskkill)/i
| CommandLine=/(veeam|backup|sql|vss|sophos|defender|crowdstrike|csagent|sense|wdfilter|msexchange)/i
| groupBy([aid, ComputerName], function=[count(CommandLine, distinct=true, as=StopCmds), collect([CommandLine], limit=10)], limit=500)
| StopCmds > 2
| sort(StopCmds, order=desc)

Hardening: Tiered and Deployable

All controls target Windows. Authority: MITRE mitigations (the why) plus Microsoft Defender attack surface reduction documentation and the CIS Microsoft Windows benchmarks (the what). Each is verifiable with the read-only checks in the section 10 audit block.

Immediate (this week)
  • Immutable or offline backups, tested restore (M1053 Data Backup, T1486/T1490). Shadow copies are not a backup: Neutrino deletes them. Keep one copy that domain admin credentials cannot delete.
  • Command-line process auditing (M1047 Audit). Required for every command-line detection in this pack. Playbook P4.
  • ASR rule "Use advanced protection against ransomware" in audit then block (M1040 Behavior Prevention on Endpoint, T1486). Microsoft Defender documentation. Playbook P1.
  • Reduce Backup Operators and local admin membership (M1026 Privileged Account Management, T1490). CIS Windows benchmarks, user rights assignment. Playbook P6.
Near term (1 to 4 weeks, pilot first)
  • ASR rules for PSExec/WMI process creation and LSASS credential theft (M1040, M1043; T1047, T1569.002, T1003). Pilot in audit mode: the PSExec/WMI rule breaks some management tools. Playbook P1.
  • LSA protection (RunAsPPL) (M1043 Credential Access Protection, T1003). Needs driver and plug-in compatibility testing; reboot required. Playbook P3.
  • Controlled folder access (M1040, T1486) in audit mode, then block on file-server-adjacent hosts. Playbook P2.
  • MFA and patching for internet-facing and remote-access services (M1032, M1051; initial access). The sources give no vector, so apply to the commonly abused surfaces PCrisk lists: unpatched software, exposed remote services, brute-forceable logins.
  • Passive FSRM file screen on shares (M1047). Playbook P5.
Strategic (1 to 3 months)
  • Application control (WDAC or AppLocker) limiting who may run vssadmin, wmic, diskshadow and wbadmin (M1038 Execution Prevention). best-practice, no formal benchmark for these specific binaries
  • Tiered administration and credential hygiene (M1026, M1027 Password Policies). Break the path from a compromised workstation to backup infrastructure.
  • Remove WMIC where unused (M1042 Disable or Remove Feature). Newer Windows builds ship it as a removable feature; confirm inventory use first.
  • Egress monitoring for bulk outbound transfer to catch the claimed exfiltration stage. best-practice, no formal benchmark

Deployable Playbooks

Each step lists prerequisites, whether a reboot is needed, and how to undo it. Test on a pilot ring.

P1 · Attack surface reduction rules, audit mode first

Prerequisites: Microsoft Defender Antivirus active and cloud protection on; Windows 10/11 or Server 2019+. Run on a pilot ring.
Reboot required: No

# AuditMode first. Change Audit to Enabled only after reviewing the ASR audit events.
$ids = @(
 'c1db55ab-c21a-4637-bb3f-a12568109d35', # Use advanced protection against ransomware
 'd1e49aac-8f56-4280-b9ba-993a6d77406c', # Block process creations originating from PSExec and WMI commands
 '9e6c4e1f-7d60-472f-ba1a-a39ef669e4b2'  # Block credential stealing from the Windows local security authority subsystem
)
foreach ($id in $ids) { Add-MpPreference -AttackSurfaceReductionRules_Ids $id -AttackSurfaceReductionRules_Actions AuditMode }
Get-MpPreference | Select-Object -ExpandProperty AttackSurfaceReductionRules_Ids

Rollback: set each rule back to Disabled with Add-MpPreference -AttackSurfaceReductionRules_Ids <id> -AttackSurfaceReductionRules_Actions Disabled, or remove it with Remove-MpPreference -AttackSurfaceReductionRules_Ids <id>. Rules take effect without restart.

P2 · Controlled folder access, audit mode

Prerequisites: Defender Antivirus active. Inventory line-of-business apps that write to Documents and Desktop.
Reboot required: No

Set-MpPreference -EnableControlledFolderAccess AuditMode
(Get-MpPreference).EnableControlledFolderAccess   # 2 = audit

Rollback: Set-MpPreference -EnableControlledFolderAccess Disabled.

P3 · LSA protection (RunAsPPL)

Prerequisites: Test all security providers, smart card and authentication plug-ins on a pilot ring first. Know that on UEFI systems Windows can lock the setting in firmware.
Reboot required: Yes

reg add HKLM\SYSTEM\CurrentControlSet\Control\Lsa /v RunAsPPL /t REG_DWORD /d 1 /f
reg query HKLM\SYSTEM\CurrentControlSet\Control\Lsa /v RunAsPPL

Rollback: set RunAsPPL to 0 and reboot. If a UEFI lock was applied, removing it needs Microsoft's documented procedure for clearing the variable; check Microsoft guidance before enabling on a fleet.

P4 · Command-line process creation auditing

Prerequisites: Local or Group Policy edit rights. Event volume rises on busy servers; size the Security log.
Reboot required: No

reg add HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\Audit /v ProcessCreationIncludeCmdLine_Enabled /t REG_DWORD /d 1 /f
auditpol /set /subcategory:"Process Creation" /success:enable
auditpol /get /subcategory:"Process Creation"

Rollback: reg delete HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\Audit /v ProcessCreationIncludeCmdLine_Enabled /f and auditpol /set /subcategory:"Process Creation" /success:disable.

P5 · Passive FSRM file screen for the Neutrino artifacts

Prerequisites: File Server Resource Manager role installed; a notification method (email) configured. Passive mode logs and notifies without blocking writes.
Reboot required: No

$grp = New-FsrmFileGroup -Name 'Neutrino-artifacts' -IncludePattern @('*.neutrino','README-RECOVERY.txt')
New-FsrmFileScreen -Path 'D:\Shares' -IncludeGroup 'Neutrino-artifacts' -Active:$false

Rollback: Remove-FsrmFileScreen -Path 'D:\Shares' then Remove-FsrmFileGroup -Name 'Neutrino-artifacts'.

P6 · Review Backup Operators and local admin membership

Prerequisites: Change approval. Confirm no backup service account depends on the membership you remove.
Reboot required: No

Get-LocalGroupMember -Group 'Backup Operators'
# Remove only after review:
# Remove-LocalGroupMember -Group 'Backup Operators' -Member '<account>'

Rollback: Add-LocalGroupMember -Group 'Backup Operators' -Member '<account>' (record the original membership before changing).
