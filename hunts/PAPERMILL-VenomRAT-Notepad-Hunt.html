01

Executive Summary

PAPERMILL is an emerging malware cluster reported by JUMPSEC's Detection and Response Team (DART) on 2026-09-15. The attacker's objective is straightforward remote-access commodity crimeware: get VenomRAT v6.0.3 running on an Indian tax-payer's workstation to enable hidden-desktop (HVNC) control, keystroke logging, browser-credential theft, and cryptocurrency-wallet draining. The lure is a tax-audit-themed phishing email carrying an ISO 9660 disk image with a .img extension, built with PyCdlib. Because files inside a mounted disk image do not inherit the Mark-of-the-Web, the payload chain — a legitimately signed Notepad++ binary renamed to look like a tax notice, sideloading a malicious libcurl.dll that proxies only the four real curl_* exports Notepad++ needs — walks straight past SmartScreen and download-reputation checks that would normally fire on a browser-downloaded archive.

The highest-value defensive angle is not the atomic indicators (hashes and a handful of infrastructure values rotate quickly and are dynamically generated per victim per JUMPSEC's own reporting) — it is the three durable behavioral anomalies the campaign cannot easily change without rebuilding its whole toolchain: (1) a child process launched from a mounted, non-system-drive image volume; (2) a legitimately-signed executable whose on-disk FileName does not match its expected identity, sitting next to an anomalously-located libcurl.dll; and (3) a persistence artifact (RuntimeBroker.exe) running from %APPDATA% instead of its legitimate System32 home. §8 builds hunts around all three.

Defender priority: this pack is built from a single independent primary source (JUMPSEC DART; every other cited outlet is derivative coverage of that one report — see §2). Every atomic indicator in this pack therefore ships as action=detect, never prevent, and no severity is marked critical. Treat the behavioral hunts in §8 (mounted-image execution, signed-binary/DLL-sideload mismatch, RuntimeBroker path anomaly) as the primary, durable coverage; treat the IOC table as a perishable pivot list, not a blocklist.

Hunt Brief & Attack Chain

Hunt hypotheses (ordered by fidelity)

  1. H1 — High: A signed executable whose FileName does not match a known-good identity loads a co-located libcurl.dll from a non-standard directory. This is the campaign's core defense-evasion trick and is hard to change without rebuilding the whole sideload chain.
  2. H2 — High: RuntimeBroker.exe — a legitimate Windows filename — executes from %APPDATA%\Microsoft\Crypto\RuntimeBroker\ instead of %SystemRoot%\System32\. Path, not name, is the anomaly.
  3. H3 — Medium: A process is launched with its ImageFileName rooted on a non-system drive letter with no surrounding directory structure, parented by explorer.exe — consistent with double-clicking an executable inside a freshly-mounted ISO/.img.
  4. H4 — Medium: libcurl.dll — a legitimate library name shipped by many dev tools — loads from a path outside the small set of known-good vendor install directories. The loader's own internal module name, libcurl.dll_<digits>.dll (the digits vary per build), is a more durable variant of this same signal and is folded into Q2/Q3.
  5. H5 — Medium: An HKCU...\RunOnce registry value is written by a process executing from a user-writable %APPDATA% path rather than a signed installer under Program Files.
  6. H6 — Medium: cvtres.exe — a legitimate Visual C++ resource-compiler helper — runs with a parent process outside the normal MSVC/MSBuild toolchain. JUMPSEC's IOC appendix confirms VenomRAT's HVNC worker kills any running cvtres.exe process on reconnect, which is the behavior this hunt targets.
  7. H7 — High: Outbound network connection to the reported C2 endpoint 154.36.188.201:4449.
  8. H8 — High: DNS resolution to the campaign's reported delivery infrastructure domains.

07

Native Audit-Log Hunts

Email gateway / MTA

Filter for inbound mail with an .iso or .img attachment (including inside a .zip) combined with a subject line matching the Devanagari tax-audit lure pattern (कर लेखापरीक्षा परिणाम) or the ASCII reference pattern ITD/SCNU/2026-. Cross-reference envelope sender domain against hsaui.cc and HELO/PTR against mos1.17dlz.cn (§4/§10). Most secure email gateways expose this as a content-disposition + regex rule; exact syntax is vendor-specific (Proofpoint, Mimecast, Defender for Office 365 mail flow rules, etc.) and is out of CQL scope for this pack.

Mark-of-the-Web / Zone.Identifier verification

On a suspect host, confirm the absence of a Zone.Identifier alternate data stream on the executed binary — the mechanical signature of MOTW bypass via mounted image:

Get-Item -Path 'C:\Users\<user>\Desktop\Tax_Notice_*.exe' -Stream Zone.Identifier -ErrorAction SilentlyContinue
# No output / "PropertyNotFoundException" == no MOTW was ever applied == consistent with mounted-image execution

Volume-mount event review

Review Microsoft-Windows-VHDMP-Operational and Microsoft-Windows-DeviceSetupManager/Admin Windows Event Logs for a new optical/virtual-CD-ROM device arrival immediately preceding process execution from a non-system drive letter — this corroborates §8 Q1 without relying on Falcon telemetry alone.

Q1 · Process execution from a mounted ISO/.img volume (H3)
CONF MEDIUMFP MEDIUMCOST LOW

Looks for: a process launched directly from the root of a non-system drive letter (consistent with a freshly-mounted ISO/.img), parented by Explorer. FP: legitimate portable apps run from USB drives or IT-approved imaging tools will also match — see TUNING.

// HUNT: Process execution from a mounted ISO/.img volume
// MITRE: T1566.001, T1553.005
// CONF: medium  FP: medium  COST: low
// REQUIRES: ProcessRollup2 / SyntheticProcessRollup2 (default 7d search window via the Falcon time picker, not an in-query filter)
// FALSE POSITIVES: portable apps launched from IT-approved USB media; legitimate optical-media software installers
// TUNING: exclude known imaging/deployment tool paths and first-seen-elsewhere-on-fleet executables; scope to hosts with no active IT ticket for physical/virtual media use
#event_simpleName=/ProcessRollup2|SyntheticProcessRollup2/
| ParentBaseFileName=/^explorer\.exe$/i
| ImageFileName=/^[D-Zd-z]:\\[^\\]+\.exe$/i
| ImageFileName!=/^[Cc]:\\/
| table([@timestamp, aid, ComputerName, UserName, ImageFileName, ParentBaseFileName, CommandLine, SHA256HashData])
Q2 · libcurl.dll loaded from a non-standard directory (H4)
CONF HIGHFP MEDIUMCOST MEDIUM

Looks for: libcurl.dll — a legitimate filename shipped by many dev tools — loading from a path outside the small set of known-good vendor install directories. Also matches the loader's own internal module name, libcurl.dll_<digits>.dll (JUMPSEC observed libcurl.dll_38768.dll; the digit suffix is per-build), which is a more durable variant of the same signal since it survives a rename of the on-disk filename. FP: Git for Windows, CMake, PostgreSQL and similar dev tools legitimately ship their own libcurl.dll — see TUNING.

// HUNT: libcurl.dll (or its internal libcurl.dll_<digits>.dll name) module load from a non-standard directory
// MITRE: T1574.002
// CONF: high  FP: medium  COST: medium
// REQUIRES: ImageHash
// FALSE POSITIVES: Git for Windows (Program Files\Git\...), CMake, PostgreSQL, curl's own official installer -- all ship a legitimate libcurl.dll
// TUNING: exclude FilePath prefixes under Program Files\Git\, Program Files\CMake\, Program Files\PostgreSQL\, and other approved dev-tool install roots
#event_simpleName=ImageHash
| rename(field=[[FileName, Dll_Loaded], [FilePath, Dll_Path]])
| Dll_Loaded=/^libcurl\.dll(_\d+\.dll)?$/i
| Dll_Path!=/\\Windows\\(System32|SysWOW64)\\/i
| Dll_Path!=/\\Program Files\\Git\\/i
| Dll_Path!=/\\Program Files\\CMake\\/i
| Dll_Path!=/\\Program Files\\PostgreSQL\\/i
| table([@timestamp, aid, ComputerName, TargetProcessId, Dll_Loaded, Dll_Path])
Q3 · Signed non-Notepad++ image co-loading libcurl.dll (H1 — core sideload hunt)
CONF HIGHFP MEDIUMCOST MEDIUM

This is the direct behavioral signature of the campaign's renamed-binary + sideload trick, independent of any specific hash. FP: a small number of legitimate signed installers legitimately pair with a differently-named libcurl.dll — see TUNING.

// HUNT: Signed executable, not Notepad++, co-loading libcurl.dll from its own directory
