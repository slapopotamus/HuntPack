Executive Summary

BITTER, a suspected South Asian cyberespionage group active since at least 2013, is running a campaign against South Asian organizations that uses PowerShell and cmd scripts and a custom remote access trojan the Fortinet report calls PapRAT. FortiGuard Labs attributes it to BITTER with high confidence from lure filenames, C2 patterns, file metadata and malware analysis. There are three delivery chains: an LNK that abuses ftp.exe and leaves no malware binary, a VHDX holding an LNK that silently runs an MSI beside a decoy spreadsheet, and a RAR holding a .url that pulls an LNK over WebDAV. PapRAT exists as a C++ build (plaintext HTTP) and a Rust build (HTTPS), and in chain 3 it fetches a second implant, WmRAT.

The durable detections are behavioral. Chain 1 uses only stock Windows tools (ftp, curl, schtasks, conhost, more, msg), so signature or hash coverage alone will miss it. This pack ships 10 queries centred on the ftp.exe child-process shape, the MicrosoftUpdates and BiosUpdates task paths, the "more file | cmd" task action, MSI launches beside a decoy spreadsheet, and WebDAV @SSL installs. All 13 atomic indicators come from a single vendor report, so they ship as detect and none as prevent.

⚠ Defender priority: hunt Q2 and Q10 (task paths under MicrosoftUpdates or BiosUpdates), Q3 (task action piping a log into cmd), Q1 (ftp.exe spawning a shell) and Q6 (MSI beside a decoy spreadsheet). Removing PapRAT alone may not end the intrusion, because WmRAT and the server-side script tasks can persist independently.

Hunt Brief & Attack Chain

Working hypothesis: a user opens a themed archive, disk image or shortcut. The chain runs only stock Windows tools or a hidden MSI, plants a scheduled task that re-runs a downloaded command file every few minutes, and installs PapRAT. Detection should anchor on command-line shapes and task paths rather than on file hashes.

Hypotheses (ordered by fidelity): H1 task path under MicrosoftUpdates or BiosUpdates (high, Q2, Q10). H2 task action piping a log file into cmd (high, Q3). H3 ftp.exe as a shell launcher (high, Q1). H4 MSI beside a decoy spreadsheet or WebDAV @SSL install (high, Q6). H5 curl with revocation and certificate checks off (medium, Q4). H6 recon and decoy pop-up (medium, Q5). H7 campaign hostnames and hashes (retro-hunt, Q7, Q9). H8 vnces.exe and bruzsvc.exe names (medium, Q8).

Deployable Playbooks

Playbook: BITTER PapRAT delivery and persistence. Estimated deploy time: 2 hours plus a pilot ring. Test on a pilot ring first. Config below is defensive and reversible.

Step 1: Disable the WebClient service

Prerequisites: confirm no business use of mapped WebDAV drives or SharePoint "Open with Explorer" on the target ring. Reboot required: No. Rollback: re-enable with the commands below.

sc.exe stop WebClient
sc.exe config WebClient start= disabled
# Verify
Get-Service WebClient | Select-Object Status, StartType
# Rollback
sc.exe config WebClient start= demand
sc.exe start WebClient

Step 2: Hide the Mount verb for disk images

Prerequisites: Windows 10 or 11; confirm the ProgID for .vhdx on your build with cmd /c assoc .vhdx (expected Windows.VhdFile); admins can still mount through PowerShell. Reboot required: No (sign out and in for Explorer). Rollback: delete the values.

reg add "HKLM\SOFTWARE\Classes\Windows.VhdFile\shell\mount" /v ProgrammaticAccessOnly /t REG_SZ /d "" /f
reg add "HKLM\SOFTWARE\Classes\Windows.IsoFile\shell\mount" /v ProgrammaticAccessOnly /t REG_SZ /d "" /f
# Verify
reg query "HKLM\SOFTWARE\Classes\Windows.VhdFile\shell\mount" /v ProgrammaticAccessOnly
# Rollback
reg delete "HKLM\SOFTWARE\Classes\Windows.VhdFile\shell\mount" /v ProgrammaticAccessOnly /f
reg delete "HKLM\SOFTWARE\Classes\Windows.IsoFile\shell\mount" /v ProgrammaticAccessOnly /f

Step 3: Restrict Windows Installer to managed installs

Prerequisites: software is deployed by Intune, SCCM or similar running as SYSTEM; pilot first because user-initiated MSI installs will stop. Reboot required: No. Rollback: remove the value.

reg add "HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer" /v DisableMSI /t REG_DWORD /d 1 /f
# Verify
reg query "HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer" /v DisableMSI
# Rollback
reg delete "HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer" /v DisableMSI /f

Step 4: Audit ftp.exe with an AppLocker rule (audit mode)

Prerequisites: Application Identity service running; back up the current policy; merge, never overwrite. Reboot required: No. Rollback: restore the backup or remove the rule. Move to Enforce only after reviewing audit events (8003).

Get-AppLockerPolicy -Local -Xml | Out-File C:\Temp\applocker-backup.xml
$xml = @'
<AppLockerPolicy Version="1">
  <RuleCollection Type="Exe" EnforcementMode="AuditOnly">
    <FilePathRule Id="b1f3a6d2-5c41-4e8a-9a37-2f0e6c1d7a10" Name="Deny ftp.exe for standard users" Description="BITTER PapRAT chain 1 abuses ftp.exe as a script runner" UserOrGroupSid="S-1-1-0" Action="Deny">
      <Conditions><FilePathCondition Path="%SYSTEM32%\ftp.exe" /></Conditions>
    </FilePathRule>
  </RuleCollection>
</AppLockerPolicy>
'@
$xml | Out-File C:\Temp\ftp-rule.xml
Set-AppLockerPolicy -XmlPolicy C:\Temp\ftp-rule.xml -Merge
# Rollback
Set-AppLockerPolicy -XmlPolicy C:\Temp\applocker-backup.xml

Step 5: Log scheduled-task creation

Prerequisites: Security log size sized for the added events. Reboot required: No. Rollback: disable the subcategory.

auditpol /set /subcategory:"Other Object Access Events" /success:enable

auditpol /get /subcategory:"Other Object Access Events"
