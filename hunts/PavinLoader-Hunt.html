Executive Summary

PavinLoader is a multi-stage .NET loader that delivers information stealers and backdoors for its operators. Netskope Threat Labs (Vini Egerland, published 2026-11-19) dissected a November 2026 generation and describes a leaner rebuild of the chain. An Inno Setup installer posing as "NVMe Driver Helper Setup" drops three files into a folder under %LocalAppData%: a renamed copy of the legitimate Microsoft MSBuild (NovosUpdater.exe), its project file (NovosUpdater.csproj) and a trojanized copy of the libphonenumber-csharp library (PhoneNumbers.dll). The project file uses MSBuild's UsingTask element to load that DLL, whose added code runs a custom 256-opcode virtual machine fed by a 21.6 MB resource.

The loader resolves its C2 over DNS-over-HTTPS, downloads a stage 2 .NET DLL (assembly Pegasus.Common) disguised as a .js file, and loads it in memory. Stage 2 is a gatekeeper: it scores the machine with SMBIOS, ACPI, HID and monitor checks, looks for AWS device IDs, and always beacons a JSON fingerprint to the operator, who decides whether to hand out a payload. Netskope saw no persistence: the loader drops, runs and waits for a task. Older revisions used .wsf scripts, conhost.exe and MSBUILDENABLEALLPROPERTYFUNCTIONS=1; the current one goes from installer straight to MSBuild. Malwarebytes (August 2026) tracks the same family across ClickFix, fake downloads and RenPy game lures, and links it to Amatera Stealer and HijackLoader deliveries.

Netskope states that every indicator in the post rotates, so this pack hunts the structure first: a renamed MSBuild run against a .csproj from a user profile folder, the dropped trio, and an outbound HTTPS beacon from that build process. It ships ten CrowdStrike CQL queries and 16 atomic indicators, all at detect. Nothing ships at prevent: the launcher is a Microsoft-signed binary and the reporting is a single first-party analysis (see s2).

Defender priority: run Q1, Q3 and Q8 first. A hit means a loader has executed on that host, and because the operator decides what comes next, assume a stealer or backdoor may have followed. Isolate, preserve memory, and reset the user's credentials and sessions from a clean device (s14). The drop folder deletes itself, so do not expect to find the trio on disk.

Decisions taken from the sources

  • The MSBuild hash is not imported. Netskope calls NovosUpdater.exe a renamed copy of the legitimate MSBuild 4.8.9032.0. A hash row for a stock product binary would alert on the real tool, so it stays out of the CSV and out of this pack's text. The rename is detected by behavior instead (Q1, Q2).
  • The tier-2 beacon addresses are context. The two addresses Netskope lists for skeegulduz.blog sit in a shared CDN range, and the three DoH resolvers are public services. None is blocked on this evidence.
  • Related clusters are out of scope. Malwarebytes' hashes, addresses and .lat, .cfd, .shop, .icu domains, the derp.ca HellsUchecker indicators, and the Emerging Threats signature for another family's response envelope (sid 2071865, which Netskope says this traffic matches) are not shipped. Only the November generation's own indicators are.
  • Names as the sources write them: "PavinLoader", Netskope's "Loader-as-a-Service" hypothesis (Malwarebytes calls it a possibility it cannot confirm: no build panel or sales channel found), the dropped names NovosUpdater, PhoneNumbers.dll, Rebus.dll and the stage 2 assembly Pegasus.Common. The pack coins no campaign name and attributes the activity to no actor, because no source does. Netskope's antivirus note: a "Trojan.PavinLoader" detection means the loader has executed.
  • A discrepancy worth knowing: Netskope credits derp.ca with documenting the chain in March, but that page describes a different payload and never says PavinLoader. Treat the lineage as Netskope's and Malwarebytes' assessment, not as something the derp.ca page itself states.
  • Prompt-injection screen: none of the five fetched pages contained text addressed to an automated reader or asking for any action. They hold site navigation, marketing and article text only.

  • PowerQuery assumes: On Process Creation, tgt.process.* is the new process and src.process.* is its creator, so the CQL's parent field maps to src.process.name.
