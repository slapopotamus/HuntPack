Executive Summary

Arctic Wolf Labs is tracking an ongoing campaign that compromises legitimate Ukrainian business websites (a hair-treatment clinic, a scale-model manufacturer, a specialist bookseller/publisher, a psychological facility, a tool retailer, and an automotive retailer) and injects an iframe that loads a fake, Ukrainian-language Cloudflare "human verification" page. Instead of the usual encoded PowerShell ClickFix payload, this campaign poisons the clipboard with a msiexec.exe /i <url>.msi /passive command and instructs the visitor to paste it into the Windows Run dialog. The MSI retrieves a previously undocumented 64-bit Windows infostealer that Arctic Wolf named Psychedelic Stealer after its embedded configuration tag. The implant harvests Chromium browser passwords, account tokens, and cryptocurrency-wallet data (browser-extension and desktop-wallet), installs a browser native-messaging bridge, persists via a logon-triggered scheduled task named psychedelicloveUtils, and polls a hardcoded C2 for further tasking (including arbitrary EXE/MSI/PowerShell execution).

The attacker's own operational infrastructure is short-lived and same-day: the delivery domain uasputnik[.]com was registered 2026-09-09 and lure activity was already observed within days. An exposed lure-management panel (branded "РУБЛЁВКА TDS" / Rublevka TDS) recorded 557 views, 426 clicks and 79 "complete" events across 32 countries, 446/351/71 of them from Ukraine, confirming the Ukraine-focused targeting.

The attacker's highest point of leverage is the moment the victim executes a Windows-Installer command they pasted themselves: it bypasses browser and mail-gateway file-download controls entirely. The defender's highest point of leverage is the same moment, from the other side: a Run-dialog-parented msiexec.exe invoking a remote, non-corporate MSI URL is a rare, high-fidelity, one-line detection that predates payload execution, persistence, and theft altogether (Section 8, Q1).

Defender priority: the browser-side delivery (iframe injection on the compromised site, and the clipboard write itself) generates no Falcon endpoint telemetry. Detection coverage starts at the moment the pasted command executes. Treat Q1/Q2 (Section 8) as the primary control and pair them with the DNS-filtering and clipboard-policy hardening in Section 12 to cover the pre-execution gap.

Hunt Brief & Attack Chain

Hunt hypotheses (ordered by fidelity)

  1. H1 (high): msiexec.exe is launched with explorer.exe as its parent (Windows Run dialog) and a command line containing a remote HTTP(S) MSI URL. This is the single highest-value signal in the whole chain: it fires before payload execution, is rare in normal enterprise use, and directly corresponds to how the campaign forces execution.
  2. H2 (high): A msiexec.exe /passive install carries the campaign's distinctive ORG_NOTE= MSI property containing the Ukrainian "verification" text — a string unique to this lure's clipboard payload.
  3. H3 (high): A process or file named psychedeliclove.exe executes, or the confirmed SHA-256 is observed.
  4. H4 (high): A logon-triggered scheduled task named psychedelicloveUtils is registered — the implant's sole documented persistence mechanism.
  5. H5 (high): A host makes an outbound connection to the hardcoded implant C2 (193.178.159.128:8080) or the next-stage payload host (107.175.82.242:9000).
  6. H6 (medium): A host resolves the delivery domain uasputnik[.]com or the iframe-loader domain fsputnik[.]com — useful as an early pivot but weaker alone (DNS resolution does not prove the MSI was fetched or executed).
  7. H7 (medium): Native-messaging bridge artifacts (host.ps1, host.bat, com.lunex.explorer.json) are written to a browser profile directory.
  8. H8 (medium): A non-browser process reads Chromium credential stores (Login Data, Web Data, Local State) or known wallet-extension storage paths.

Native Audit-Log Hunts

For hosts without Falcon coverage, or to cross-validate Section 8, use native Windows / infrastructure logging:

  • Windows Security Event ID 4688 (process creation, requires command-line auditing enabled): filter New Process Name = msiexec.exe, Creator Process Name = explorer.exe, command line containing /passive or an http(s):// URL.
  • MsiInstaller Event ID 1040/1042 (Application log): captures the source of an MSI install, including a remote URL source, independent of Falcon.
  • Task Scheduler Operational log Event ID 4698 (task registered): filter Task Name containing psychedelicloveUtils.
  • Sysmon (hosts without EDR): Event ID 1 (Process Create) for the msiexec/psychedeliclove.exe pattern, Event ID 3 (Network Connect) for the two C2/staging IPs, Event ID 11 (File Create) for host.ps1/host.bat/com.lunex.explorer.json.
  • DNS resolver / secure web gateway logs: query for resolutions of uasputnik.com and fsputnik.com even where Falcon DnsRequest telemetry is unavailable or disabled.
  • Chrome/Edge enterprise policy compliance report: verify the ClipboardAllowedForUrls / DefaultClipboardSetting policy (Section 13, Playbook 1) is actually applied fleet-wide — this is the compensating control for the sensor-blind clipboard step.
  • Web-hosting / CMS audit trail (for MSPs or businesses hosting client-facing sites of the small-business profile this campaign targets): review file-integrity-monitoring alerts or CMS admin/audit logs for unauthorized template or iframe modifications. This is the only realistic detection point for the initial iframe injection step, which no endpoint sensor observes.

Q1 · Run-Dialog-Parented msiexec.exe Fetching a Remote MSI (Primary Signal)
CONF HIGHFP LOWCOST LOW

Looks for: msiexec.exe launched with explorer.exe as its immediate parent (the Windows Run dialog is hosted inside explorer.exe) and a command line requesting a remote HTTP(S) install. FP: legitimate remote MSI installs launched interactively via Run are rare in a managed fleet and worth investigating on their own merits.

// HUNT: ClickFix-style msiexec.exe launched from the Windows Run dialog, fetching a remote MSI package
// MITRE: T1204.004, T1218.007
// CONF: high  FP: low  COST: low
// REQUIRES: ProcessRollup2 (Windows sensor)
// FALSE POSITIVES: interactive admin-run remote MSI installs via Run dialog are rare -- treat any hit as worth investigating
// LOOKBACK: 7d (set in the Falcon time picker)
#event_simpleName=/ProcessRollup2|SyntheticProcessRollup2/
| FileName=/^msiexec\.exe$/i
| ParentBaseFileName=/^explorer\.exe$/i
| CommandLine=/\/i\s+["']?https?:\/\//i
| table([@timestamp, ComputerName, UserName, ParentBaseFileName, FileName, CommandLine])
| sort(@timestamp, order=desc)

Alert package — DETECT: ClickFix msiexec Remote MSI via Run Dialog (Q1)

Alert email subject: [HIGH] Detection: Psychedelic Stealer ClickFix -- Run-dialog msiexec fetching remote MSI

Alert email body: A host executed msiexec.exe as a direct child of explorer.exe (consistent with a Windows Run dialog paste) referencing a remote MSI package over HTTP(S).   1. Pull the full CommandLine and confirm the referenced MSI URL/domain against the IOC table (Section 4).
  2. Check whether the MSI actually installed (subsequent child processes of msiexec.exe, or a new file matching a known MSI name).
  3. Run Q4 for the same aid to check for psychedeliclove.exe execution.
  4. Run Q5 for the same aid to check for psychedelicloveUtils scheduled-task creation.

Hardening — Tiered & Deployable

Controls are tiered by deployment friction and cover the three surfaces this threat actually touches: the Windows endpoint, the Chromium browser, and DNS/network egress. A fourth surface, the web-hosting layer that hosts the compromised business sites, is out of scope for endpoint tooling and is called out separately.

Immediate (this week)
  • Block programmatic clipboard writes from untrusted web origins via Chrome/Edge enterprise policy (DefaultClipboardSetting / ClipboardAllowedForUrls). This directly breaks the ClickFix delivery mechanism at the one point that is entirely browser-side and otherwise invisible to endpoint telemetry. Authority: MITRE M1038 (Execution Prevention); Chrome Enterprise policy documentation (Google). Verify: Section 10 audit block, Config/Policy Audit.
  • Restrict outbound network access for msiexec.exe via host-based firewall (msiexec.exe legitimately needs internet access only in specific managed-deployment scenarios). Authority: MITRE M1037 (Filter Network Traffic). Verify: Section 10 audit block.
  • Block the confirmed campaign infrastructure (Section 4/10 IOC list) at DNS/proxy/firewall and via Falcon Custom IOC import. Authority: MITRE M1037.
Near term (1-4 weeks)
  • AppLocker/WDAC policy restricting MSI installer sources to signed publishers or an internal software-distribution path, blocking arbitrary remote-MSI execution outright. Authority: MITRE M1038; CIS Microsoft Windows Benchmark, Application Control section. Pilot on a ring before fleet-wide enforcement.
  • Enable and centralize Windows Installer verbose logging (MsiInstaller Event ID 1040/1042) into the SIEM, independent of EDR, so remote-MSI installs are visible even on hosts with reduced sensor coverage. Authority: Microsoft Windows Installer logging documentation.
  • Restrict non-admin scheduled-task creation for logon-trigger tasks via Task Scheduler folder ACLs / GPO, raising the bar for the persistence step. Authority: MITRE M1018 (User Account Management); Microsoft Security Baseline guidance.
  • ClickFix-specific user-awareness training: run a phishing simulation modeling a fake CAPTCHA/verification prompt that asks the user to paste a command into Run. Authority: MITRE M1017 (User Training).
Strategic (1-3 months)
  • Fleet-wide default-deny application control (WDAC) for unsigned executables, closing the arbitrary EXE/MSI/PowerShell execution path the implant's own C2 tasking relies on for follow-on payloads. Authority: MITRE M1038; Microsoft WDAC design guide.
  • Newly-registered-domain (NRD) blocking at the DNS/secure-web-gateway layer. The delivery domain in this campaign was registered and weaponized within days; category/age-based blocking of NRDs closes an entire class of same-pattern campaigns, not just this one. Authority: MITRE M1021 (Restrict Web-Based Content).
  • File-integrity monitoring (FIM) and a Web Application Firewall on any client-facing website your organization or MSP practice hosts, specifically covering the CMS template/iframe injection point this campaign relies on for initial access. This is the only control that addresses the step no endpoint sensor can see. Authority: CIS Benchmark (web server hardening); OWASP guidance. ⚠ best-practice, no single formal benchmark covers third-party CMS iframe-injection monitoring end-to-end — combine FIM + WAF + CMS vendor hardening guidance.
  • Confirm Chrome/Edge App-Bound Encryption is enforced on all managed endpoints, raising the cost of offline decryption of Local State/Login Data even if a stealer reads the raw files. Authority: Chrome Enterprise / Chromium project documentation on App-Bound Encryption.

Deployable Playbooks

Playbook 1 — Block programmatic clipboard writes from untrusted origins (Chrome/Edge)

Prerequisites: Chrome/Edge managed via Group Policy ADMX templates or Chrome Browser Cloud Management; identify any internal web apps that legitimately use navigator.clipboard.writeText so they can be allowlisted before enforcement.
Reboot required: No — browser restart only.
Rollback: Remove or set the GPO value back to "Not Configured" and force a policy refresh (gpupdate /force); the browser reverts to its default clipboard-permission prompt behavior.

' GPO path: Computer Configuration > Administrative Templates > Google Chrome > Content Settings
' Or Edge: Computer Configuration > Administrative Templates > Microsoft Edge > Content Settings > Clipboard

' Registry equivalent (deploy via GPO Preference or Intune):
reg add "HKLM\SOFTWARE\Policies\Google\Chrome" /v DefaultClipboardSetting /t REG_DWORD /d 2 /f
reg add "HKLM\SOFTWARE\Policies\Google\Chrome" /v ClipboardAllowedForUrls /t REG_SZ /d "[\"https://*.yourorg.com\"]" /f

' Edge equivalent:
reg add "HKLM\SOFTWARE\Policies\Microsoft\Edge" /v DefaultClipboardSetting /t REG_DWORD /d 2 /f
reg add "HKLM\SOFTWARE\Policies\Microsoft\Edge" /v ClipboardAllowedForUrls /t REG_SZ /d "[\"https://*.yourorg.com\"]" /f

' DefaultClipboardSetting=2 blocks clipboard read/write by default for all sites not on the allow list.

Playbook 2 — Restrict msiexec.exe to internal/signed sources and block its outbound network access

Prerequisites: Inventory legitimate remote-MSI deployment tooling (SCCM, Intune, third-party RMM) and its source IP ranges/hostnames before enabling; test on a pilot ring.
Reboot required: No.
Rollback: Remove-NetFirewallRule -DisplayName "Block-Msiexec-Outbound" and remove/disable the AppLocker MSI rule via gpupdate /force after unlinking the GPO.

# Windows Firewall: block msiexec.exe outbound except to your internal deployment server range
New-NetFirewallRule -DisplayName "Block-Msiexec-Outbound" -Direction Outbound `
  -Program "%SystemRoot%\System32\msiexec.exe" -Action Block -Enabled True
New-NetFirewallRule -DisplayName "Allow-Msiexec-Internal-Deploy" -Direction Outbound `
  -Program "%SystemRoot%\System32\msiexec.exe" -RemoteAddress 10.0.0.0/8 -Action Allow -Enabled True

# AppLocker: restrict Windows Installer rules to a trusted internal path (deploy via GPO)
New-AppLockerPolicy -RuleType Msi -User Everyone -FilePathCondition "%OSDRIVE%\ApprovedInstalls\*" `
  -Generate | Set-AppLockerPolicy -Merge
