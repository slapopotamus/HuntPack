Executive Summary

Attacker objective. QuartzLine is a Windows PDF viewer that works, and that is the point: nobody uninstalls it. Hidden inside is a backdoor module called zenith that gives the operator remote command execution, browser-profile tampering and a way to install more malware. Mandiant tracks it as CLOUDHAZE. [#1] [#2] Expel confirmed 38 incidents at 32 customers by 20 October 2026. [#1] MCNC describes an eCrime campaign with a focus on education. [#4]

How it arrives. A Google ad on an unrelated third-party site redirects through beatramiro[.]com and softwareslizards[.]com to a download from an AWS S3 bucket. Victims were often searching for a consent form or a wallpaper, not a PDF reader. [#1] [#2] [#3] The installer is signed with an EV certificate issued to Guangzhou Guoying Communication Technology Co., Ltd., which Sectigo has revoked with the reason Privilege Withdrawn. [#2]

What it does next. Within seconds of the first check-in the server orders a hidden cmd /C install: copy to %LOCALAPPDATA%\QuartzLine, register the task QuartzlineUpdateCheck, verify with findstr, kill and relaunch Chrome. Days later it pulls a Chrome history uploader, then a self-update, then weeks later the Caira RAT with a second task, CairaServiceCheck. IronBark follows and also spreads through its own ads. [#1] [#2]

Why this pack. Blocking C2 does not clean the host: the tasks keep launching the implant every hour. [#1] [#2] [#3] This pack hunts the persistence, the install folders, the shell chain, the Chrome kill-and-relaunch, the DNS footprint and the follow-on stages, and gives a removal order that does not trigger the task loop. [#4] It ships only QuartzLine-family indicators. Twelve hashes and twenty-six domains are included, 16 as prevent where two independent snapshots agree and 22 as detect.

Defender priority: alert on Q1 and Q3 (the tasks), Q7 (viewer spawning shells) and Q5 (C2 and redirect DNS). For every network block that fired, find the device: it is still infected. Remove the scheduled tasks first, then the processes, then the folders, and reset credentials and sessions for the user.

Decisions and conflicts

  • Snapshots. Every indicator in this pack was copied from the saved snapshot text in QuartzLine-CLOUDHAZE-PDFViewer-Hunt-sources/, not from search summaries. Section 10 values were resolved from those files by script and any value not found would have stopped the build.
  • Prevent needs two sources. Rogue Authority, Expel and ReliaQuest are independent observers. MCNC repeats much of the Expel list, so it does not count as an independent second source. Indicators named only by Expel, only by Rogue Authority or only by MCNC ship as detect.
  • Role conflicts. MCNC labels three hashes as initial droppers. Expel names two of them as hosthealth.exe and updater-helper.exe, and Rogue Authority and Expel name the third as the QuartzLine update (fielddesk.exe / quartzline.exe). This pack uses the Expel and Rogue Authority roles.
  • Excluded. The Cloudflare edge addresses MCNC lists for the C2 domains are shared infrastructure and are not shipped. A PDFMaestro domain that only MCNC lists is not shipped because no other snapshot explains it. A search-result summary linking this activity to a differently named actor appears in no saved source and is not used: no actor attribution is made.
  • Delivery wording. Expel confirmed Google Ads clicks in two cases and could not see the path in others. MCNC says search-engine malvertising. The pack says Google Ads malvertising as reported by Expel, Rogue Authority and ReliaQuest.
  • Named in the sources and used here: QuartzLine, zenith, CLOUDHAZE, Caira, LeafDesk, Canvex, IronBark, Paperline. No other name is used.
  • Hostile content. None found in any fetched page.

Looks for: creation of QuartzlineUpdateCheck, CairaServiceCheck, IronbarkUpdateCheck or a HostHealthCache task. Deleting the file does not remove the task, so this finds hosts that are still being relaunched every hour.

Validation: schema-aligned, static-reviewedAutomated: static-passedEquivalence: approximate-analytic, equivalent-with-schema-assumptionsProfiles: microsoft-defender-xdr, sentinelone-endpoint-ocsf
Known limitations and deployment notes
  • PowerQuery: A task registered through a path that does not write the cache key under the monitored hive is not seen.
  • PowerQuery: The CQL's task executable field has no equivalent here; read the action from the host after a hit.
  • PowerQuery assumes: The Task Scheduler cache key path ends in or contains the task name, so a plain substring pattern after TaskCache\Tree finds the registration.
  • PowerQuery assumes: Case-insensitive matching is the PowerQuery default for matches, which reproduces the CQL /i intent.
  • KQL – Defender XDR: Tasks created before the sensor onboarded, or on hosts that do not report this action type, are not captured.
  • KQL – Defender XDR assumes: ScheduledTaskCreated is attested in Microsoft-owned hunting repositories rather than on the Learn table page.
  • KQL – Defender XDR assumes: AdditionalFields is a JSON string that carries a TaskName key for this action type.

Hardening: Tiered & Deployable

Immediate (this week)
  • Import the Section 10 CSV and block the prevent-set domains at DNS and proxy. Exact bucket hosts only, never S3 broadly. A DNS or proxy block stops new contact but does not clean the host. Framework: MITRE M1037, M1021; CIS Controls v8 9.2 and 9.3. Verify: Playbook 5 and Q5.
  • Find and remove the persistence. Delete the tasks first, then end the processes, then delete the folders, because the tasks relaunch the implant. Reimage if cleanup cannot be confirmed. Framework: MITRE M1047; vendor guidance from Expel, ReliaQuest and MCNC. Verify: Playbook 1 and Q1.
  • Reset credentials and revoke sessions for users of any infected device. Treat browser-stored passwords, cookies and tokens as exposed. Framework: MITRE M1032, M1026; NIST SP 800-63B. Verify: identity provider sign-in logs (N9).
  • Turn on the logging this hunt needs. Command-line capture, Task Scheduler events, and the Task Scheduler operational log. Framework: MITRE M1047; CIS Controls v8 8.5. Verify: Playbook 4.
  • Do not trust a signature alone. The viewer was EV-signed and a sibling build used a short-lived Microsoft Trusted Signing certificate. Educate help desk: a signer, file details and window title that name different companies is a red flag. Framework: MITRE M1017. Source: Rogue Authority.
Near term (1 to 4 weeks, pilot first)
  • Lock Chrome settings by policy. Set the default search provider, new-tab page and download restrictions, and block extension installs outside an allowlist. A managed setting overrides a value written into the profile. Framework: MITRE M1054, M1021; CIS Google Chrome Benchmark; Chrome Enterprise policy documentation. Verify: Playbook 2 and chrome://policy.
  • Add Attack Surface Reduction rule 01443614 in audit mode. It blocks executables that do not meet prevalence, age or trusted-list criteria, which a freshly published build may fail. Framework: MITRE M1038, M1049; Microsoft Defender ASR documentation. Verify: Playbook 3.
  • Restrict execution from user-writable paths. QuartzLine installs into %LOCALAPPDATA%, so admin lockdown does not stop it. Use AppLocker or WDAC in audit mode first, then enforce, with publisher rules for approved per-user software. Framework: MITRE M1038; CIS Controls v8 2.5; NIST SP 800-53 CM-7, CM-11. Verify: Get-AppLockerPolicy -Effective.
  • Alert on desktop software with no User-Agent. Add a proxy rule or detection for POSTs with an empty User-Agent from non-browser processes. Framework: MITRE M1031; best-practice, no formal benchmark. Verify: N1.
Strategic (1 to 3 months)
  • Software request path. Users should get PDF and productivity tools from an approved catalog. Remove standing user rights to install. Framework: MITRE M1017, M1038; CIS Controls v8 2.3; MCNC advice to use local IT for approved software.
  • Trust by publisher, not by valid signature. WDAC publisher or managed-installer rules so a freshly issued EV certificate does not by itself grant execution. Framework: MITRE M1045; Microsoft WDAC documentation.
  • Shrink the value of stolen sessions. Shorter session lifetimes, phishing-resistant MFA and device-bound sessions where your identity provider supports them. Framework: MITRE M1032, M1027; NIST SP 800-63B. Best-practice, no formal benchmark for session binding.
  • Cover unmanaged devices. Expel found a case where the only signal was a network block on a host with no EDR agent. Framework: CIS Controls v8 1.1, 1.2.
