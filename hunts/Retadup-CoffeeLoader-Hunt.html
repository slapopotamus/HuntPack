Executive Summary

Retadup is a USB worm written in AutoIt and AutoHotkey, first seen in 2017. French law enforcement took over its command servers in July 2019 and remotely disinfected more than 850,000 machines. Around 2024 someone began re-registering the old Retadup C2 domains. They first served SmokeLoader packed with the 32-bit Armoury packer, and from early 2025 they served CoffeeLoader. Kaspersky detected a new CoffeeLoader variant in August 2026 and reported roughly 15,000 systems with blocked Retadup infection attempts across the first three quarters of 2026, mostly in Peru, Angola, Russia and Bolivia.

The worm copies itself to connected flash and external drives as hidden files plus shortcut (LNK) files. A user who opens an infected drive on another PC and clicks the shortcut spreads it. The CoffeeLoader chain then starts from an NSIS installer that drops a patched copy of the 7-Zip library as 7z.dll into a temporary directory and runs it with rundll32.exe. The patched library holds self-decrypting shellcode (the new Armoury packer, which now decrypts on the GPU through OpenGL compute shaders instead of OpenCL). The downloader it unpacks persists through a Run value that calls rundll32.exe with the SetCodecs export, injects into a stock Windows process, and fetches its main body over HTTPS from /payload?md5=.

The strongest durable signals are behavioural, not indicator lists: a folder, a DLL and a Run value all named with the same eight hexadecimal digits, the rundll32 ...,SetCodecs autorun, a StartupApproved value written to defeat Task Manager, and stock Windows binaries (dllhost.exe, WerFault.exe, svchost.exe, OpenWith.exe, AtBroker.exe) launched by rundll32. This pack builds ten CQL hunts around those, plus indicator retro-hunts.

Defender priority: hunt the SetCodecs autorun and the eight-hex naming scheme first (Q1, Q2, Q3, Q6), then restrict execution from removable media. All indicators are single-sourced, so every IOC row ships at detect and nothing in this pack implements blocking.

Decisions and exclusions

  • The report does not name the USB shortcut or hidden-file names and gives no autorun or scheduled-task detail for the USB stage. None are invented here. USB coverage is a stated gap with one low-confidence hunt (Q10).
  • 7-Zip is legitimate software and 7z.dll is its real library name. No hash of stock 7-Zip is listed and no query alerts on the filename alone. The signal is a copy in a temporary or user-writable path loaded by rundll32.
  • The Run value name in the report's example is b79faace.dll (eight hex digits plus the .dll extension), matching the folder name and the DLL base name. The pattern, not the example value, is what the queries use.
  • SmokeLoader indicators and other "related" family values are intentionally excluded: only this campaign's own values ship.
  • Retadup and CoffeeLoader are the reporting's names. No new threat name is coined.

Hunt Brief & Attack Chain

Hypotheses (highest fidelity first)

  1. A Run-key value launches rundll32 with the SetCodecs export (Q1, Q3). Confidence high.
  2. A folder, DLL and Run value share one eight-hex-digit name (Q2, Q6). Confidence high.
  3. rundll32 runs a 7z.dll from a temporary or user-writable path (Q4). Confidence medium-high.
  4. rundll32 spawns a stock Windows process from the injection target list (Q5). Confidence medium-high.
  5. Those stock processes (or rundll32) make outbound HTTPS connections that they normally do not (Q7). Confidence medium.
  6. Endpoints resolve a known Retadup or CoffeeLoader domain, or execute a known DLL or installer (Q8, Q9). Confidence high but perishable.
  7. Executables are written to removable media by a non-installer process (Q10). Confidence low, hunt only.

Q1 · Run value launches rundll32 with the SetCodecs export
CONF HIGHFP LOWCOST LOW

Looks for: an autostart registry write whose data runs rundll32 with the SetCodecs export, the persistence form the report shows. Behavioural, so it survives hash and domain churn.

Validation: static-reviewedEquivalence: equivalent-with-schema-assumptionsProfiles: sentinelone-endpoint-ocsf
Known limitations and deployment notes
  • PowerQuery: Registry writes the agent does not monitor are not captured.
  • PowerQuery assumes: registry.value holds the written value data on Registry Value Modified events.
  • PowerQuery assumes: The CQL's optional exe suffix after rundll32 is subsumed by the bounded wildcard that follows it.
// HUNT: Run value launches rundll32 with the SetCodecs export (CoffeeLoader downloader persistence)
// MITRE: T1547.001, T1218.011
// CONF: high  FP: low  COST: low | REQUIRES: AsepValueUpdate registry telemetry
// LOOKBACK: 7d (set with the console time picker)
// FALSE POSITIVES: none known; SetCodecs is not a documented rundll32 entry for common software
#event_simpleName=AsepValueUpdate
| RegStringValue=/rundll32(\.exe)?.{0,200}SetCodecs/i
| table([@timestamp, ComputerName, UserName, RegObjectName, RegValueName, RegStringValue, ContextBaseFileName, aid])

Hardening: Tiered & Deployable

Immediate (this week)
  • Audit ASR rule "Block untrusted and unsigned processes that run from USB" in audit mode first (MITRE M1038 Execution Prevention, M1042 Disable or Remove Feature or Program; Microsoft Defender ASR documentation). Verify with Get-MpPreference. See playbook PB1.
  • Disable AutoPlay and AutoRun for all drive types (M1042; CIS Microsoft Windows benchmark, AutoPlay settings). Note Retadup spreads through LNK shortcuts, so this reduces but does not remove the exposure. See PB2.
  • Train staff not to open drives from other PCs and not to click shortcuts that sit where a folder should be (M1017 User Training).
Near term (1 to 4 weeks, pilot first)
  • Deny execute from removable disks by policy (M1034 Limit Hardware Installation, M1038; Group Policy "Removable Disks: Deny execute access"). Pilot with admins who run portable tools. See PB3.
  • Restrict removable storage to approved devices or read-only for standard users through device control (M1034). Falcon Device Control or Defender device control, whichever you own.
  • Alert on rundll32 executing from user-writable paths and on Run-key writes with rundll32 command data (M1047 Audit). Queries Q1, Q3 and Q4.
Strategic (1 to 3 months)
  • Application allow-listing (WDAC or AppLocker) so rundll32 and unsigned DLLs cannot load from %PROGRAMDATA% and %LOCALAPPDATA% (M1038; CIS application control guidance).
  • Retire USB mass storage where business process allows, or move to managed encrypted media with scanning on insertion (M1034).
  • Egress filtering and DNS filtering for newly re-registered or dynamic-DNS domains. Apply only after validating the domains locally, since the intelligence is single-sourced (M1031 Network Intrusion Prevention). best-practice, no formal benchmark for this campaign

PB4 · Read-only sweep for the eight-hex persistence pattern

Prerequisites: run in the user's context for HKCU and elevated for HKLM. Reboot required: No (read-only). Rollback: none required, the script changes nothing.

$runKeys = 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run','HKLM:\Software\Microsoft\Windows\CurrentVersion\Run'
foreach ($k in $runKeys) {
  $p = Get-ItemProperty $k -ErrorAction SilentlyContinue
  if ($p) { $p.PSObject.Properties | Where-Object { $_.Name -match '^[0-9a-fA-F]{8}\.dll$' -or "$($_.Value)" -match 'SetCodecs' } | ForEach-Object { "$k  $($_.Name) = $($_.Value)" } }
}
Get-ChildItem $env:ProgramData, $env:LOCALAPPDATA -Directory -ErrorAction SilentlyContinue |
  Where-Object { $_.Name -match '^[0-9a-fA-F]{8}$' } |
  ForEach-Object { Get-ChildItem $_.FullName -Filter *.dll -ErrorAction SilentlyContinue | Select-Object FullName, Length, LastWriteTime }
