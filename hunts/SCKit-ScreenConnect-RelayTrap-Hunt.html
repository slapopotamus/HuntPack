Executive Summary

On 2026-11-11 an operator with access to several cloud-hosted ScreenConnect panels pushed Run Commands, executing as SYSTEM, to groups of managed endpoints. The commands installed an attacker-controlled ScreenConnect client and then SCKit, a 16-file toolkit. Huntress counted at least 288 endpoints across 48 organizations, all hit within 90 minutes of roughly 17:47 UTC, about a third in the first ten minutes. The toolkit installs a persistent second client, swaps out the genuine client, and sets a "relay trap" that is designed to steal a technician's session cookie and spread to every other session that technician can reach.

Huntress and ConnectWise point at the RMM+ extension. Versions 1.0.31 and 1.0.32 accept a blank access key, and RMM+ bypasses ScreenConnect user accounts, roles and MFA. ConnectWise reported no vulnerability in ScreenConnect itself and no compromise of its own infrastructure, and disabled five third-party extensions across about 400 partner environments. The console-takeover and technician-to-endpoint spread was reconstructed from the code and has not been seen working: it failed in every recovered host log Huntress checked.

Highest-value defensive angle: hashes are explicitly weak here because the scripts are rebuilt with different embedded values and the trap executable is compiled on every host. This pack therefore leads with behavior and names: a ScreenConnect client service spawning a SYSTEM shell, the sckit-* files, the RelayTrap directory, the TrapWatch task, the RelayTrapLiteAlert Run value, a second client instance on one host, and sqlite3.exe against cookie stores. It contains 15 queries and no block rule on any ScreenConnect or ConnectWise file.

Defender priority: do not open an interactive ScreenConnect session to a suspect host. Huntress warns the session itself can trigger the spread to the technician workstation. Use EDR live response, WinRM or another out-of-band channel, and treat any workstation that already connected as potentially exposed.

CONF MEDIUMFP HIGHCOST LOW

Looks for: The core behavior of the campaign: the ScreenConnect client service launching cmd.exe or PowerShell as SYSTEM, which is how a panel Run Command executes on an endpoint. This is a baseline hunt, not an alert: legitimate MSP automation produces the same parent and child. FP: every approved Run Command or Toolbox script from your own support team looks identical. Use Q2 to separate a mass push from routine use.

Validation: schema-aligned, static-reviewedAutomated: static-passedEquivalence: equivalent-with-schema-assumptionsProfiles: microsoft-defender-xdr, sentinelone-endpoint-ocsf
Known limitations and deployment notes
  • PowerQuery: The SYSTEM test is a substring match on the user name, so an account whose name merely contains SYSTEM would also match.
  • PowerQuery assumes: src.process.user holds a value containing SYSTEM for the local system account, for example NT AUTHORITY\SYSTEM.
  • PowerQuery assumes: The service launches the shell directly, so the creator of the shell is the service binary.
  • KQL – Defender XDR: A shell the sensor did not observe starting is not captured.
  • KQL – Defender XDR assumes: AccountSid holds the SID of the account the created process runs under.

Hardening: Tiered

The campaign needs three things: a panel that accepts commands without MFA, an RMM client that is allowed to run anything as SYSTEM, and no one watching Run Command and Toolbox history. Each control below removes one.

Immediate: deploy this week

I1 · Disable the five named extensions and verify

ConnectWise disabled Labtech Plus, RMM Plus, RMM+, RMM Plus Password Link and RMM+ Password Link on hosted environments and urged on-premises partners to do the same. Do it, then confirm in the extensions list. Disabling an extension does not remove malware that is already installed and does not revoke access the attacker already holds; pair it with I3 and the section 14 runbook.
Authority: MITRE M1042 (Disable or Remove Feature or Program); ConnectWise partner advisory as quoted by the Hacker News. Verify: extensions list shows none enabled (P3). Risk: low; breaks only integrations that use RMM+.

I2 · Set or remove the RMM+ access key

If RMM+ is kept for a real project, update past 1.0.31 and 1.0.32 and set RMMPlus.AccessKey to a long random value. Those versions accept a blank key and bypass accounts, roles and MFA.
Authority: MITRE M1051 (Update Software), M1054 (Software Configuration). best-practice, no formal benchmark Verify: the setting is non-empty in the extension configuration. Risk: low.

I3 · Revoke from a clean device, then rotate

Terminate active ScreenConnect web sessions, rotate admin and technician credentials, and revoke browser and identity-provider sessions for any technician who connected to a suspect host. The toolkit is designed to steal session cookies, so a password change alone is not enough.
Authority: MITRE M1032 (Multi-factor Authentication), M1026 (Privileged Account Management). Verify: no pre-rotation session token still works. Risk: medium; technicians are signed out.

I4 · Stop interactive sessions to suspect hosts

Write it into the runbook: use EDR live response, WinRM or another out-of-band channel. An interactive session can trigger the spread to the technician workstation.
Authority: vendor guidance (Huntress mitigation section). best-practice, no formal benchmark Verify: runbook updated and tabletop passed (G6). Risk: low.

Near term: 1 to 4 weeks, pilot first

N1 · Restrict who can Run Command and use the Toolbox

Limit the Run Command and Toolbox permissions to a small role, require MFA on every account, and restrict panel login to known addresses. Alert on mass Run Command use (Q2).
Authority: MITRE M1018 (User Account Management), M1032. Verify: a standard technician role cannot run commands on all sessions. Risk: medium; slows ad-hoc support.

N2 · Turn on Defender tamper protection and review exclusions

Tamper protection stops a script from adding exclusions silently. Review every existing exclusion for an owner.
Authority: MITRE M1038 (Execution Prevention) and M1054 (Software Configuration); Microsoft Defender documentation. best-practice, no formal benchmark Verify: P4 shows IsTamperProtected true. Risk: low.

N3 · Allowlist your own ScreenConnect instance in audit mode

Build the list of your own instance IDs and relay hostnames (Q10 and Q13 produce it), then use application control in audit mode to flag any other ScreenConnect client. This allowlists your instance; it does not block the product.
Authority: MITRE M1038 (Execution Prevention); CIS Controls v8 2.5. Verify: audit events appear for a test client with a different instance ID. Risk: medium; keep it in audit until the list is clean.

Strategic: 1 to 3 months

S1 · Separate technician workstations

Technicians reach hundreds of endpoints, so their workstation is the worm's second stage. Use dedicated, hardened workstations with no general browsing and phishing-resistant MFA.
Authority: MITRE M1030 (Network Segmentation), M1032. best-practice, no formal benchmark Verify: technician sign-ins come only from the dedicated pool. Risk: high; budget and process change.

S2 · Ingest ScreenConnect audit logs into your SIEM

Huntress notes the activity was visible in panel logs and not in sign-in events. Alert on Run Command to many sessions and on extension changes.
Authority: MITRE M1047 (Audit). Verify: a test Run Command appears in the SIEM within minutes. Risk: low.

S3 · Restrict egress to approved relays

Allow ScreenConnect clients to reach only your own instance hostnames, so a rogue relay on a dynamic DNS name is refused.
Authority: MITRE M1037 (Filter Network Traffic). Verify: Q13 shows only approved addresses. Risk: medium.

  [switch]$Apply
)
$ErrorActionPreference = 'Continue'
New-Item -ItemType Directory -Path $EvidenceDir -Force | Out-Null

foreach ($p in 'C:\ProgramData\RelayTrap', 'C:\Windows\Temp') {
  if (Test-Path $p) {
    Get-ChildItem $p -Recurse -Force -ErrorAction SilentlyContinue |
      Where-Object { $p -like '*RelayTrap*' -or $_.Name -like 'sckit-*' -or $_.Name -in 'sc.msi','runnew.cmd','Panel-Lateral.ps1','ToolboxRelayUploader.exe','sqlite3.exe' } |

  }
}

Get-CimInstance Win32_Service | Where-Object { $_.Name -like 'ScreenConnect Client*' } | ForEach-Object {
