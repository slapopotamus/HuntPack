Executive Summary

Bitdefender Labs (report dated 2026-11-26) tracks SYS010, assessed as likely the second major version of the SYS01 Facebook and Meta Business infostealer. Paid Meta ads promote free animated wallpaper apps for Windows and lead to look-alike download sites that serve a roughly 74 MB ZIP. The victim unpacks it and runs Wallpaper Engine.exe, which is a genuine signed MeisterTask Electron binary that loads an attacker-supplied app.asar. The app really works as a wallpaper browser, which is the decoy.

In the background the chain extracts a password-protected archive with a bundled 7-Zip into a per-build folder under %LOCALAPPDATA%, then runs a bundled PHP 7.2.23 runtime. The PHP code is now only a loader: it enrolls the host with a C2 server and waits for tasks. For hosts the operator selects, a second PHP stage (eclient.php) makes the browsers install a malicious extension themselves through enterprise-management features: a Chrome Browser Cloud Management enrollment token, a Firefox ExtensionSettings policy, and on Edge an attacker-run MDM enrollment. The extensions (Docs Helper for Chrome, Document Hub for Firefox) steal cookies and query the Meta Graph API for ad accounts, Business Managers and Pages. The Chrome build can also read and permanently delete Gmail and Outlook web messages.

Highest-value defensive angles: (1) browser policy writes by a process that is not your management agent (Q1, Q2); (2) a standalone 7-Zip extracting a password-protected archive into the user profile (Q3); (3) PHP or wscript running loader scripts and the two persistence task name patterns (Q4, Q5); (4) DNS to the published C2 and hosting names (Q8, Q9). The infection chain deliberately uses legitimate signed software, so every detection here keys on context (unexpected parent, path, command shape) and none of them blocks a stock tool.

Intel is thin on one axis: a single vendor report is the origin of every indicator, and the corroborating outlet republishes the same list. All indicators therefore ship as detect, none as prevent. The C2 set rotates (new domains are published through Telegram, Cloudflare R2 and Google pages), so the domain list will age quickly.

Defender priority: identify Windows machines used to manage Meta Pages or ad accounts that ran an ad-delivered wallpaper app since 2026-10-16, check Chrome, Edge and Firefox for unexpected management ("Managed by your organization"), and preserve evidence before revoking sessions or removing extensions.

Decisions

  • Name: SYS010 is Bitdefender's name and is used unchanged. No campaign name or actor alias has been added. Vietnamese-language artifacts and a UTC+7 build clock are reported by Bitdefender as consistent with, but not proof of, a Vietnamese-speaking operator; this pack makes no attribution.
  • Provenance: all 40 atomic indicators were read out of the saved Bitdefender snapshot by script and then confirmed present in the second snapshot. Hash type is not labelled by Bitdefender; the five values are 64 hex characters, so they are treated as SHA-256 by length. The secondary outlet also labels them SHA-256, which is a copy of the list, not independent confirmation.
  • Not independent: the second snapshot republishes the first source's list, so no value has two independent sources. Every row ships at detect; nothing is promoted to prevent.
  • Historical SYS01 indicators excluded. Bitdefender compares SYS010 to the 2022 to 2024 SYS01 activity (for example an older console-hiding helper). Those are not shipped as SYS010 indicators.
  • Legitimate software: the MeisterTask Electron binary, the standalone 7-Zip signed by Docker Inc., the PHP 7.2.23 runtime and wscript.exe are legitimate. They appear here as detect-only context, never as block entries.
  • Fetch notes: two further outlets (SC Media and BleepingComputer) returned HTTP 403 to automated fetches. They were not saved and are not cited. No instruction-like or AI-addressed text was found in any saved page.

Hardening: Tiered

Immediate (this week)

1. Remove local administrator rights from daily-driver accounts, especially those that manage ad or Business accounts. M1026 Privileged Account Management. The browser takeover needs elevation and the loader asks repeatedly, so a standard user without an admin credential cannot complete it. Verify: Get-LocalGroupMember -Group Administrators lists only named admin accounts.

2. Require consent on the secure desktop for administrators. M1026; Microsoft UAC policy settings. Playbook 4. Verify: ConsentPromptBehaviorAdmin equals 2.

3. Audit the current browser management state on every machine that handles Meta or ad accounts. M1047 Audit. Playbook 1 is read-only. Verify: output matches your approved enrollment and extension inventory.

4. Run Q1, Q2, Q3, Q4, Q5 and Q8 as scheduled searches at detect. M1047. Verify: each fires on its lab positive control (Section 11).

5. Brief social-media, marketing and creator staff. M1017 User Training. Software comes from the vendor's own site or a trusted store, never from an ad; cancel a UAC prompt you cannot explain; treat an unexpected "managed by your organization" notice as an incident. Verify: completion record.

Near term (1 to 4 weeks)

6. Attack Surface Reduction rules in audit mode. M1038 Execution Prevention; Microsoft Defender ASR rules reference. Audit "block execution of potentially obfuscated scripts" and "block JavaScript or VBScript from launching downloaded executable content" (Playbook 5), read the audit results for a baseline, then decide on enforcement. Whether these rules trigger on this chain is not confirmed by the report. Verify: Get-MpPreference.

7. Restrict browser extension installation by policy on managed fleets. M1033 Limit Software Installation; CIS benchmarks for Google Chrome, Microsoft Edge and Mozilla Firefox. Default-deny with an allowlist of approved extension IDs (Playbook 2). This raises the bar for user-level installs; it does not stop an attacker who already has admin rights, so keep it paired with Q1 and Q2.

8. Application control in audit mode for user-writable paths. M1038. AppLocker or WDAC with default rules in audit, then review what executes from %LOCALAPPDATA% and Downloads (Playbook 6). The chain runs an unsigned PHP runtime and scripts from the profile.

9. DNS or proxy filtering for the published hostnames. M1031 Network Intrusion Prevention. Load the Section 10 domains at alert first. Move to block only after you confirm them yourself: this is a single-source list and the operator rotates domains. Do not block Telegram, Cloudflare or Google by name.

10. Meta Business hygiene. Few admins, separate roles for content and moderation, remove stale people and partners, review payment methods and sessions. ⚠ best-practice, no formal benchmark.

Strategic (1 to 3 months)

11. Dedicated, managed browser profile or privileged access workstation for ad and Business account administration. M1026, M1018 User Account Management. Keeps session cookies for money-moving accounts off general browsing machines. ⚠ best-practice, no formal benchmark.

12. Extension inventory and enforcement through your own management plane. M1047, M1038. Centrally report every installed extension and its install source, and alert on any extension whose source is not your approved store or your own console.

13. Email protection for the recovery inbox. Phishing-resistant MFA and conditional access on the mailbox tied to Meta assets, and alerting on mass or permanent deletions. Session theft bypasses MFA at login, so pair it with session-lifetime limits and sign-in anomaly alerts.
