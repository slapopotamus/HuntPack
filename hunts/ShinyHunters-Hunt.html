Executive Summary

Attacker objective. ShinyHunters is a financially motivated extortion collective, active since at least 2019, that steals data and demands payment under threat of leaking it. It does not encrypt. Sekoia assesses the name now covers decentralised clusters sharing one brand and tied to The Com. [#1] [#8]

Google tracks the live intrusion work as three clusters. UNC6661 and UNC6671 gain access by voice phishing. UNC6240, the canonical ShinyHunters, runs the extortion and the 2026 Oracle PeopleSoft exploitation. [#2]

Track A: vishing to SaaS data theft. Operators call staff as IT support, send them to a victim-branded sign-in page, capture the SSO password and MFA code, then enroll an MFA device they control. [#2] Okta documents kits that let the caller steer the victim's browser in step with the call, which defeats push and number matching. [#6] Obsidian saw Okta FastPass enrolled from an emulated Android device named "Passkey". [#9] The actor then pulls data from SharePoint, OneDrive, Salesforce, Slack and similar platforms, and in one case authorized an add-on that deletes the "Security method enrolled" email. [#2]

Track B: PeopleSoft exploitation. UNC6240 exploited CVE-2026-35273 (CVSS 9.8) as a zero-day from 27 May to 9 June 2026, before Oracle's 10 June alert. [#3] In September it returned with a one-character URL-encoding trick that bypassed WAF rules and deployed web shells on dozens of systems. [#4] Post-exploitation used MeshCentral agents disguised as Azure services, an SSH credential-spray script, zstd archives and a Tor-hosted leak site. [#3] [#4]

Current status. Law enforcement reported detentions and arrests in September and October 2026. [#12] [#13] Nothing in the sources shows the extortion or exploitation stopping, and the brand reportedly changed hands during the arrests, so treat the threat as live.

Highest-value defensive angle. The first reliable signal is in the identity provider, not on an endpoint: an MFA factor change shortly after a failure-heavy sign-in. [#5] [#9] Patching PeopleSoft is the only reliable fix for Track B, because path-based WAF rules were already bypassed. [#4]

Defender priority: alert on every MFA activation, reset or device enrollment that follows failed sign-ins (Q8, Q9), and on any Java process on a PeopleSoft host that starts a shell (Q5). Patch CVE-2026-35273 and block /PSEMHUB and /PSIGW/HttpListeningConnector on the normalized path.

  • Dropped. Two further indicators appeared only in third-party aggregator pages and in no vendor report. They are not in the pack.
  • Typo reconciled. MITRE lists one extortion mailbox as shinycorp@tutonota[.]com. GTIG writes shinycorp@tutanota[.]com. The pack lists the GTIG spelling and keeps the MITRE variant as a hunt string.
  • No victim names. Victims named in sources are not repeated here. The pack is written around tradecraft so it ports to any environment.
  • Related packs. The library already holds a PeopleSoft CVE-2026-35273 pack (v0.3, June 2026) with six endpoint queries for the June zero-day activity, plus packs for UNC6671 vishing and AiTM, a Teams-vishing cluster, a Salesloft-Drift OAuth campaign, and Scattered Spider. This pack covers ShinyHunters as one actor. It repeats the June PeopleSoft infrastructure so it stands alone, and adds the September renewed exploitation (the %50SEMHUB WAF bypass, web shells, SIDEEYE, Neo-reGeorg, new addresses and domains) and the full Okta, Microsoft 365, Google Workspace and Salesforce track. See the PeopleSoft pack for its June-specific detail.

Contradictions and gaps

  • The June report lists five staging addresses and one mirror address. The September report lists three different addresses. They are different infrastructure generations, not a conflict.
  • GTIG's 19 January source IPs are residential-proxy and VPN addresses from January 2026. They are perishable and shared, so the pack uses them for hunting only.
  • Okta's indicator list and kit analysis are available only to Okta security contacts. This pack uses only what Okta published openly.
  • GTIG says the x.jsp, tunnel.jsp and tunnel.jspx hashes vary per deployment. Hunt those by name and path, not by hash.
  • Attribution is layered: UNC6661, UNC6671 and UNC6240 are separate clusters that GTIG links by shared extortion infrastructure. Do not assume one operator.

Overall confidence: High. At least two Tier 1 sources agree on every central claim. Perishability is high for the IP lists and low for tradecraft.

07

Native Audit-Log Hunts

These checks need no Falcon query. Run them in the product named in each row.

N1 · Okta System Log: MFA lifecycle and emulator

Where: Admin Console, Reports, System Log, or the System Log API.

eventType eq "user.mfa.factor.activate" or eventType eq "user.mfa.factor.reset_all" or eventType eq "device.enrollment.create"

Pivot on actor, client.ipAddress and client.userAgent.rawUserAgent. Look for Genymobile and for a device named Passkey.

N2 · Entra ID: security-info registration

Where: Entra admin center, Monitoring, Audit logs, filter Category = UserManagement.

Activity: User registered security info / User deleted security info

Compare the source IP to the user's normal sign-in locations and to Conditional Access results.

N3 · Microsoft 365: scripted SharePoint and OneDrive downloads

Where: Exchange Online PowerShell.

Search-UnifiedAuditLog -StartDate (Get-Date).AddDays(-14) -EndDate (Get-Date) -Operations FileDownloaded,FileAccessed -ResultSize 5000 |
  Where-Object { $_.AuditData -match 'WindowsPowerShell' } |
  Select-Object CreationDate, UserIds, Operations

Group by user and count. Mandiant's threshold was 50 documents of 3 or more types in 5 minutes.

N4 · Google Workspace: add-on authorization and mail deletion

Where: Admin console, Reporting, Audit and investigation, OAuth log events and Gmail log events.

OAuth log: App name contains ToogleBox Recall. Gmail log: event is delete or permanent delete and subject matches MFA enrollment wording.

A deleted 'Security method enrolled' message is the signal; check outbound mail deleted the same hour.

N5 · Salesforce: bulk export and connected-app token use

Where: Developer console or Workbench against EventLogFile.

SELECT EventType, LogDate, LogFile FROM EventLogFile WHERE EventType IN ('BulkApi','ReportExport','Login','RestApi') AND LogDate = LAST_N_DAYS:14

Look for new connected apps, API calls from unfamiliar addresses, and Data Loader user agents. For Experience Cloud, review guest-user API volume.

N6 · PeopleSoft web tier: exploitation attempts and web shells

Where: Shell on each WebLogic node (check every node behind the load balancer).

PS_CFG_HOME=/u01/app/psoft/ps_config_homes/csprd   # adjust to your install
grep -Eih 'psemhub|%50semhub|psigw/httplisteningconnector' $(find "$PS_CFG_HOME"/webserv -name '*access*log*') | head -200
find "$PS_CFG_HOME"/webserv/*/applications/peoplesoft/PSEMHUB.war \( -name '*.jsp' -o -name '*.jspx' -o -name '*.exe' \) -ls
find "$PS_CFG_HOME"/webserv/*/applications/peoplesoft/PSEMHUB.war/envmetadata -type f -ls

Any JSP, JSPX or EXE that is not part of the shipped product is hostile. Five to fifteen POSTs to the hub servlet from one address is target verification.

N7 · PeopleSoft hosts: credential and config reads

Where: Shell with auditd, or EDR file-read telemetry.

ausearch -i -f psappsrv.cfg
