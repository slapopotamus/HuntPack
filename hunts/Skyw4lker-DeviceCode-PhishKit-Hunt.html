Executive Summary

Skyw4lker is a phishing kit that automates Microsoft 365 account takeover through the OAuth 2.0 device authorization grant (the "device code" flow, RFC 8628). ANY.RUN published the analysis on 2026-10-27 and The Hacker News carried a contributed write-up on 2026-10-28. The kit gives the victim a real Microsoft device code and tells them to enter it at Microsoft's own sign-in page. When the victim completes the request, the attacker's backend, which has been polling, receives the Microsoft 365 tokens. No password has to be stolen and the victim satisfies MFA on genuine Microsoft infrastructure.

What is kit-specific here. The lure is a password-protected PDF, DOCX or XLSX (password in the email body) that links to a CAPTCHA page, sometimes through a lure page on Miro, Google Sites or Zoom. The page runs obfuscated JavaScript against a PHP backend: session_public.php with action=start registers the victim with IP and geolocation, then repeated action=poll calls wait for authentication. Landing tokens follow //it[A-Za-z0-9]{32}us (earlier //zt...op). ANY.RUN lists 173 hosting domains, finds the kit shares JavaScript modules, the landing-URL format and part of its hosting with a credential-phishing kit called Gabagool, and assesses with high confidence that both were built by the same developer.

Scale and targeting, as reported. ANY.RUN counted 618 sandbox analyses between June and 2026-10-21, with monthly volume rising from about 20 in June to about 200 in September. It attributes 46% of submissions to the United States in its summary and 47% in a later section (the post states both). Submitting organisations were mainly in technology, manufacturing and government. The Hacker News, in a piece it labels as contributed by a partner, says the campaign has focused on manufacturing, technology and healthcare. Those are sandbox-submission and vendor-narrative figures, not a confirmed victim census. No threat actor is attributed: ANY.RUN says the data does not let it distinguish one operator from several customers of the same platform.

What Falcon can and cannot see. Token theft happens entirely at Microsoft's identity plane and leaves no endpoint artefact. Falcon sees the document being opened, a browser started with a URL argument, DNS lookups and IP connections. Falcon does not see URL paths inside a running browser, so the kit's own backend paths (session_public.php, client_geo.js, the CAPTCHA widget) are proxy or web-gateway telemetry. The identity queries (Q8 to Q10) need Entra and Microsoft 365 logs in Next-Gen SIEM. The generic device-code primitive is covered in depth by the library's existing device-code pack; this pack concentrates on the kit-specific angles.
Defender priority. (1) Put a Conditional Access policy in report-only that blocks the device code flow, review the sign-in log impact, then enforce it. Microsoft recommends blocking it wherever possible. (2) Ingest interactive and non-interactive Entra sign-in logs plus the audit log, and run Q8 and Q9. (3) Import the section 10 CSV as detect only: every indicator is single-sourced to ANY.RUN, so nothing here is eligible for a prevent action.

Decisions and discrepancies

  • Not independently corroborated. The Hacker News page identifies itself as a contributed piece from a partner and restates ANY.RUN's research. Treat it as one source, not two. This is why nothing in the pack is a prevent or critical indicator.
  • US share: ANY.RUN's summary says 46% and its later section says 47%. The pack prints both.
  • Sectors differ by source: ANY.RUN says submissions came mainly from technology, manufacturing and government. The Hacker News says the campaign has focused on manufacturing, technology and healthcare. Healthcare is a single-source claim.
  • "No password stolen" needs a footnote. ANY.RUN's TTP table also records that the shared endpoint.js module logs e-mail, password, browser and MFA status to accounts.php. That module is shared with Gabagool's credential mode. The device-code mode does not need a password, but a victim who also saw a credential form should be treated as password-exposed. The runbook resets the password regardless.
  • Hash scope: the one hash is a lure document, not an executable. Falcon's file-hash fields describe executables, so it is a mail-security and sandbox indicator (section 7, N3), not an endpoint hunt.
  • Gabagool naming: an older secondary article describes a Cloudflare R2 AiTM kit also called Gabagool. ANY.RUN's Gabagool is first seen 2026-04-23 and harvests logins through accounts.php. They may be the same family or a name collision; no Gabagool-only indicator is imported here.

Native Audit-Log Hunts

Falcon endpoint telemetry cannot see the kit's backend paths. These checks run in the proxy, web gateway, mail and identity tools you already have.

N1 Web proxy / secure web gateway: kit URL grammar

Search URL path logs for these regular expressions (PCRE syntax; the first two are ANY.RUN's lead hunt guidance). A single action=poll hit repeated every few seconds from one client is the polling loop. Review the host for the other modules before concluding anything, because /admin/index.php and the bare module names are generic.

N2 Entra admin center: device-code sign-ins and protocol tracking

1. Entra admin center > Monitoring & health > Sign-in logs, then add the filter
   "Authentication Protocol" = Device code flow. Do this for BOTH the interactive and the
   non-interactive tabs (the attacker's redemption appears as non-interactive).
2. In Activity details, read "Original transfer method". A session that started with device
   code keeps that value; Conditional Access protocol tracking will block later refreshes.
3. After enforcing the block policy, error AADSTS530036 on a refresh means a device-code
   session was protocol tracked and its token is now unusable. Treat those users as targeted.
4. Source: Microsoft Learn "Conditional Access: authentication flows" (snapshot 06).

N4 Analyst checklist

  • Which users received a password-protected attachment from an external sender in the last 30 days? Confirm with message trace, not only with Q1.
  • For each opener, did a device-code event follow within 24 hours (N2)? If yes, treat as compromised until proven otherwise.
  • Did the same user register an MFA method, grant consent or create a mailbox rule in that window (Q10)?
  • Does the proxy show a kit module path (N1) from that host, and which lure hop (Google Sites, Miro, Zoom) preceded it?

The headline control is a Conditional Access policy that blocks the device code flow. It removes the primitive Skyw4lker needs, regardless of which kit, domain or lure is used. Everything else reduces exposure or speeds detection.
Immediate: deploy this week

1 Block the device code flow with Conditional Access CRITICAL

MITRE M1042 (Disable or Remove Feature or Program) for T1528. Authority: Microsoft Learn, Conditional Access block authentication flows and authentication flows (snapshots 05, 06): Microsoft recommends blocking device code flow wherever possible. Policy: All users, All resources, Conditions > Authentication flows > Device code flow, Grant > Block, break-glass excluded, Report-only first. No formal CIS benchmark control was verified in this run; vendor guidance is the authority.
