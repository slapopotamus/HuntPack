Executive Summary

Unit 42 (Palo Alto Networks, published 2026-10-15) tracks CL-UNK-1211, a campaign against government entities and state-affiliated infrastructure observed from October 2025 to April 2026. The attackers worked almost entirely on Linux servers, mixing web shells, a custom Go remote access Trojan Unit 42 named SysGoRAT, open-source tools, in-memory reverse shells and heavy cleanup. The objective was intelligence gathering: dumping databases and taking government mailboxes to reach linked social media accounts.

Attribution is unknown. The UNK designation means Unit 42 has not determined whether the cluster is nation-state or cybercrime. This pack makes no nation-state claim. Unit 42 also reports AI-generated payloads (conversational comments inside scripts) and says that suggests an LLM or an automated agent, not that either was proven.

Persistence and access: web shells under a php-fpm parent, auto_prepend_file rewritten under /etc/php/ and /opt/plesk/php/ (including a fake /usr/lib/php/plesk_sys_driver.php), a sudo alias in .bashrc that captures passwords, SSH key injection, and SysGoRAT with six persistence methods. Evasion: pkill against Cortex XDR components (Unit 42 says these attempts were detected and mitigated), deletion of auth, history, mail and web logs, timestomping with touch -t, and planted red-team markers.

This pack hunts Linux process, network and DNS telemetry from the Falcon Linux sensor, and says plainly what the sensor cannot see. File contents of PHP web shells, .bashrc edits made by file copy, PHP configuration writes, and the HTTP requests that reach a web shell need a web-server-log and file-integrity review (Sections 7 and 15). All 31 atomic indicators ship as detect because every one comes from a single vendor report.

Defender priority: on every Linux web or mail server, run Q1, Q4, Q6, Q7 and Q10 fleet-wide for 30 days, run the Playbook A read-only audit for auto_prepend_file, hidden SUID files and alias sudo, and review web-server logs for requests to plesk_sys_driver.php and search_social.php. If any hit lands, treat sudo passwords, database and SMTP credentials and mailbox-linked accounts on that host as exposed.

Web hunter decisions

  • No independent corroboration was found. Searches returned only outlets that cite Unit 42. Because no indicator has two independent sources, nothing is set to prevent or critical. All 31 atomic indicators are detect.
  • Every hash, IP and domain was re-derived from the saved Unit 42 snapshot, not from search summaries. The 10 hashes, 17 IPs and 4 domains in the snapshot match the task brief exactly.
  • Unit 42 does not label any hash as the SysGoRAT sample. The hash table covers the React2Shell scanner, a shell backdoor, GSocket, PwnKit and PHP web shells only. This is carried as a gap (Section 15), not filled in.
  • The IPs are not mapped to roles except 104.194.158.65, the SysGoRAT default. Unit 42 says reverse shells used at least seven C2 servers; it does not say which of the 17 IPs those are.
  • Legitimate services (gsocket.io relay, transfer.sh, bashupload.com, filebin.net, catbox.moe) appear in hunt queries only and are not imported as IOCs. Stock tools (python3, bash, nc, curl) are never indicators.
  • Attribution stays at "unknown". The planted RedTeamOps2025 and pentest123 markers are deception artifacts, not evidence of an authorized assessment.
  • The page body said the SolarWinds name in Solarwinds.StatusLog.txt is camouflage. Unit 42 states there is no evidence SolarWinds was compromised.

Logs the attackers tried to delete

  • Compare auth.log or secure, btmp, wtmp and mail logs against off-host copies (syslog server or SIEM). A gap or a truncated file is itself a finding.
  • Check shell history files for zero length or recent truncation on privileged accounts.
  • Check file timestamps against inode change time: stat on suspect scripts shows a change time that postdates the claimed modification time when touch -t was used.

Database audit logs

  • On MSSQL, search for sp_configure 'xp_cmdshell' being enabled and for xp_cmdshell invoking sqlcmd against a second server (the double-hop chain Unit 42 describes).
  • Look for new SQLite files such as dump.sqlite in /tmp and bulk CSV exports followed by tar archives.
