Executive Summary

TASK#STOMP is a VBScript-to-PowerShell Windows backdoor documented by Securonix Threat Research (Akshay Gaikwad and Aaron Beardslee) on 2026-09-21. Its objective is continuous, unattended document theft -- Word, PDF, PowerPoint, Excel, and archives are harvested from every fixed drive, prioritized by type and recency -- combined with credential/clipboard theft, screenshot capture, and open-ended remote-command execution over two redundant, token-authenticated command-and-control servers.

The malware's single highest-value defensive angle is not any one filename or task name -- both rotate -- it is the behavioral spine of the install chain: wscript.exe decodes and runs a VBScript from a user-writable path, that script registers four scheduled tasks from XML definitions staged under a single non-standard %LOCALAPPDATA% folder, drops a Startup-folder re-execution copy, backdates five of its own artifacts to a single fixed historical timestamp, launches two hidden PowerShell modules, and compiles C# at runtime via the legitimate csc.exe. That sequence survives every rename the operator makes to task names, folder names, or script filenames, and none of it resembles normal user or admin activity when correlated end to end.

Securonix built this analysis from one infected machine and explicitly states it cannot say how many organizations are affected, and separately states it is not making an attribution claim -- "nothing in the sample's code, infrastructure, or TTPs overlaps cleanly with a known APT's established toolkit." The document-type priority order (Word → PDF → PowerPoint → Excel, ahead of archives) points to corporate-document espionage rather than opportunistic crimeware, and reused, buggy watchdog code across both PowerShell modules is read by Securonix as the signature of a "competent-but-not-elite," mid-tier operator rather than a mature APT.

Single-source limitation: every atomic indicator in this pack traces back to one Securonix write-up analyzing one infected host. Treat IOCs as high-fidelity for THIS sample but do not assume broad campaign infrastructure, scale, or attribution from them -- see §4 and §18.

Defender priority: hunt the chain wscript.exe → ScheduledTaskRegistered (x4, AppData-rooted) → hidden PowerShell → csc.exe under a WinDefendSvc-style folder in %LOCALAPPDATA%. This behavioral spine is mechanically detectable and survives every filename/task-name rotation the operator makes -- prioritize Q1, Q3, and Q6 (§8) over any single hash or domain block.

Hunt hypotheses

  1. H1 (high): wscript.exe launching a .vbs file from Desktop/Downloads/Temp is a reliable initial-stage signal regardless of filename. → Q1.
  2. H2 (high): A second wscript.exe → .vbs launch from the Startup folder on a later logon indicates re-execution persistence has already taken hold. → Q2.
  3. H3 (high): Scheduled tasks that impersonate core Windows component names but resolve to an executable under a user's AppData\Local path are almost never legitimate. → Q3.
  4. H4 (high): Any process activity rooted in an AppData folder named to impersonate a Defender/security service (WinDefendSvc-style) merits review even before other TTPs fire. → Q4.
  5. H5 (medium): Hidden, Base64-encoded PowerShell that references a .dat file is a strong loader-stage signal once correlated with H3/H4. → Q5.
  6. H6 (high): csc.exe spawned directly by powershell.exe is rare outside developer/build hosts and is the clearest single-event T1027.004 signal in this chain. → Q6.
  7. H7 (medium): PowerShell invoking SetLastWriteTime is a generic but useful timestomping signal fleet-wide. → Q7.
  8. H8 (high): The literal backdate value 2024-01-15 08:30:00 is a near-unique, high-confidence pivot once it appears alongside timestomping syntax. → Q8.
  9. H9 (high): DNS resolution of either named C2 domain is a direct, low-noise network signal. → Q9.
  10. H10 (medium): WMI enumeration/termination that references the loader's own module-name fragments indicates the self-replacement behavior in Stage 4. → Q10.

Native Audit-Log Hunts

These checks do not require Falcon and cover techniques (T1016, T1059.003, T1070.004, T1119, T1005, T1113, T1115, T1552.001) that endpoint process telemetry alone represents only partially. Use them to backstop §8's CQL queries, especially in estates with inconsistent sensor coverage.

  1. Security Event 4698/4699/4702 (Task Created/Deleted/Updated): filter for the eight known camouflage task names in §4, independent of EDR. Requires "Audit Other Object Access Events" enabled.
  2. Sysmon Event ID 11 (FileCreate): alert on file creation under %LOCALAPPDATA%\WinDefendSvc\ and the Startup folder for any user, regardless of the process that wrote it.
  3. NTFS timestamp forensics: during IR triage, compare $STANDARD_INFORMATION vs $FILE_NAME timestamps in the MFT and review the USN Journal for the five artifacts. Securonix explicitly calls out that several scripts/data files under a user-writable path sharing the identical historical value 2024-01-15 08:30:00 is itself a high-confidence hunting pivot, independent of any live telemetry.
  4. Wi-Fi credential theft (T1552.001, T1016): Security Event 4688 command-line auditing for netsh wlan show profile combined with key=clear, launched by a non-interactive parent (wscript.exe, powershell.exe, or cmd.exe) rather than an interactively-typed console session.
  5. Proxy / web-gateway log review (T1071.001, T1016): search for the static X-Auth-Token value or any request to the nine listed API paths (§4) against ANY destination, not just the two known domains -- the token does not rotate per victim and is Securonix's strongest standalone network indicator. This is also the only practical way to catch the malware on hosts without endpoint telemetry.
  6. Decoy-page correlation (context only, T1059.003): browser history / process-creation review for chrome.exe launched with the irantenders[.]com/tender/tot-delete-6e137de.php URL as a command-line argument. Use strictly to corroborate a host already flagged by Q1/Q3 -- see §4 for why the domain itself is not blocked.
  7. Cleanup-script invocation (T1070.004): Security Event 4688 / Prefetch / AmCache review for any cmd.exe or powershell.exe command line ending in purge.bat. Contents of the script were never recovered by Securonix, so this hunts the invocation, not the payload.
  8. Bulk document read/collection baseline (T1119, T1005): DLP/CASB or Falcon FileOpenInfo baseline for a single process performing high-volume sequential reads of .docx/.pdf/.pptx/.xlsx/archive files across multiple fixed drives in a short window, especially from a process image outside the user's normal office-suite footprint.
  9. Screenshot / clipboard abuse (T1113, T1115): where available, EDR or DLP clipboard-monitoring telemetry for a script-host or PowerShell process reading clipboard contents and immediately clearing it -- the clear-after-read pattern is unusual for legitimate tooling.

Q1 · Encoded VBScript Launch via wscript.exe (Initial Stage)
CONF HIGHFP LOWCOST LOW

Looks for: wscript.exe launching a .vbs script from Desktop, Downloads, or a Temp path -- the TASK#STOMP initial-stage signature regardless of the random filename used.

// HUNT: wscript.exe launching an encoded VBScript staged in a user-writable path
// MITRE: T1059.005
// CONF: high  FP: low  COST: low | REQUIRES: Falcon process telemetry (ProcessRollup2 / SyntheticProcessRollup2)
// FALSE POSITIVES: a handful of legacy logon/admin scripts still run .vbs from Desktop in some estates -- verify the script name is high-entropy / random rather than a known internal script.
#event_simpleName=/ProcessRollup2|SyntheticProcessRollup2/

| CommandLine=/\.vbs/i

| table([ComputerName, UserName, FileName, CommandLine, ParentBaseFileName, SHA256HashData, aid])

Hardening -- Tiered & Deployable

Immediate (this week)

Restrict Windows Script Host for standard users (M1042, M1038). Block wscript.exe/cscript.exe from executing scripts located in Desktop, Downloads, and Temp for non-administrative accounts, via an AppLocker or WDAC rule, or Group Policy WSH restriction. Cited directly by Securonix/Beardslee as the top containment recommendation. Verify: Get-AppLockerPolicy -Effective | Select-Object -ExpandProperty RuleCollections shows the WSH deny rule active.

Enable ASR rule "Block execution of potentially obfuscated scripts" (M1040). CIS Microsoft Windows 11 Benchmark and the MS Security Baseline both recommend this ASR rule in Block mode. Verify: Get-MpPreference | Select-Object -ExpandProperty AttackSurfaceReductionRules_Ids includes 5beb7efe-fd9a-4556-801d-275e5ffc04cc with action Block.

Block the two confirmed C2 domains at the DNS/proxy layer (M1037). corecloudfileshare[.]xyz and attachmentsharingdrive[.]xyz only -- do not extend to irantenders[.]com (§4). Verify: a DNS sinkhole/RPZ query against both domains returns NXDOMAIN or the sinkhole address.

Near term (1-4 weeks)

Enable PowerShell Script Block Logging and Constrained Language Mode for standard users (M1042, M1045). Captures decoded content of Base64/-enc invocations (Q5, Q7, Q8) even if a future variant changes filenames. Verify: Event ID 4104 is being generated in the Microsoft-Windows-PowerShell/Operational log; $ExecutionContext.SessionState.LanguageMode returns ConstrainedLanguage for standard users.

Strip or sandbox ISO/IMG/VBS attachments at the mail gateway (M1031, M1049). Beardslee's best estimate for the delivery vector is a phishing email carrying a ZIP or ISO/IMG attachment containing the script -- this is the most likely point to stop the chain before Stage 1. Verify: send a benign test message with a .vbs-in-.iso attachment and confirm the gateway strips or detonates it.

Deploy Custom IOA detections from §9 in Detect-only mode. 14-day monitor before any promotion decision, per the single-source validation gate in §11.

Strategic (1-3 months)

Application control (WDAC) for csc.exe and the .NET compiler toolchain on non-developer endpoints (M1038). Runtime C# compilation via csc.exe (T1027.004, Q6) is rare outside build/dev hosts; a WDAC policy denying csc.exe execution fleet-wide except on a tagged developer-host allowlist closes this stage entirely. Verify: citool.exe --policy-list (or legacy Get-CIPolicy) shows the csc.exe deny rule scoped to non-developer device groups.

DLP/CASB bulk-document-egress monitoring (M1057). Addresses T1119/T1005 -- the malware's core objective -- independent of any single detection rule catching the loader stage. Verify: a DLP test policy flags a simulated bulk read/upload of 50+ Office documents from a single endpoint within a short window.
