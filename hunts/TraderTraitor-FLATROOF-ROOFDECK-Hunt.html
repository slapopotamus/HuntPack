Executive Summary

TraderTraitor, the DPRK state-sponsored Lazarus subgroup also tracked as UNC4899, PUKCHONG, Jade Sleet, and Slow Pisces, continues its Contagious-Interview playbook of posing as recruiters and hiring managers on GitHub to get developers to run attacker-controlled code. The objective is not the developer's laptop for its own sake — it is what the laptop can reach: cloud credentials, source control, and CI/CD pipelines. SentinelOne's 2026-09-18 report shows the group has moved beyond direct cryptocurrency targets (the USD 292M KelpDAO/LayerZero theft in April 2026) to a small IT-services shop with no crypto exposure at all, confirming this is now a general-purpose developer-endpoint intrusion vector, not a crypto-only campaign.

The technique that matters most defensively is the weaponized .terraform.lock.hcl file: victims clone a fake "technical assessment" repository, run terraform init, and Terraform silently downloads and executes a malicious provider binary from an attacker-controlled registry (registry.hashicorp-aws[.]com and lookalikes). This is the earliest, highest-fidelity, and most preventable point in the entire chain — before either backdoor (FLATROOF or ROOFDECK) ever touches disk. Everything downstream (Gatekeeper bypass, LaunchAgent persistence, Telegram/Nostr C2, credential theft, cloud-key abuse) is harder to catch cleanly and easier for the attacker to vary between victims.

ROOFDECK's C2 resolution is architecturally novel: instead of a hardcoded C2 address, it queries public Nostr relays for an attacker-controlled profile and reads that profile's website field as its live C2 URL — a dead-drop resolver built entirely on decentralized, difficult-to-take-down infrastructure that a defender cannot simply sinkhole.

Defender priority: gate Terraform provider installation to approved registries (Query 1 / Playbook 1) before a single review or a single automated scan. Every other control in this pack is compensating; that one is preventive. Relationship to existing coverage: FLATROOF is also tracked as macOS.Gaslight, first analysed by SentinelLABS in June 2026 and already covered by the published macOS-Gaslight-Hunt.html pack. FLATROOF itself is therefore not new. What is new in this pack, and absent from that earlier one, is the second backdoor ROOFDECK, the weaponized .terraform.lock.hcl initial-access vector, and the Nostr dead-drop C2 resolution mechanism. The two packs share no hashes and no C2 infrastructure — this is a distinct September 2026 intrusion against a non-crypto IT-services victim. Run both: use the Gaslight pack for the June 2026 FLATROOF/BONZAI sample set and Telegram C2, and this one for the Terraform delivery chain, ROOFDECK, and the current infrastructure.

Hunt Hypotheses (ordered by fidelity)

  1. H1 (high): Developer endpoints resolve DNS for attacker-registered Terraform provider registries before any backdoor lands — the earliest network-visible step. Covered by Q1.

  7. H7 (medium): A host process resolves public Nostr relay infrastructure — ROOFDECK's dead-drop C2 lookup mechanism. Covered by Q7.
  8. H8 (medium, investigate-only): terraform init executes inside a workspace whose naming matches the interview/candidate-assessment lure pattern. Covered by Q8.

Native Audit-Log Hunts

These checks require no CQL and can be run directly on a suspect endpoint (via Falcon RTR) or against a repository / CI pipeline. They cover artifacts the CQL section either cannot reach (filesystem contents, repo diffs) or should be corroborated with before triage.

  1. ROOFDECK config file: ls -la "$HOME/.config/.repl_history" — inspect contents for Nostr public keys / relay URLs / C2 hints. This path has no legitimate shell-history purpose.
  2. ROOFDECK IPC pipe: ls -la /private/tmp/.pipe-airway — should not exist on a clean host; a named pipe here is a strong artifact.
  3. FLATROOF lock file: ls $TMPDIR/tmp*.lock — review any match for owning process and creation time correlated against Q2/Q5 hits.
  4. LaunchAgent renderer-masquerade sweep: for f in ~/Library/LaunchAgents/com.*.plist; do plutil -p "$f" 2>/dev/null | grep -q -- '--type=renderer' && echo "SUSPECT: $f"; done
  5. Gatekeeper/quarantine unified-log review: log show --predicate 'eventMessage contains "quarantine"' --last 30d — cross-reference removals against Q6 process hits.
  6. Fake Apple bundle-ID sweep: log show --predicate 'process contains "SystemUpdate" or process contains "iSync" or process contains "loginwindow"' --last 30d
  7. Terraform lock-file provenance review (pre-merge, in CI or local): grep -R "hashicorp-aws\|hashicorp-terraform" **/.terraform.lock.hcl — any hit outside registry.terraform.io is a blocker, not a warning.

None of these seven checks require a Falcon macOS sensor and all seven are safe to run against a suspected-clean host as a baseline before rolling detections to prevent mode.

Alert & Triage Quick-Reference

Shared triage checklist for any Q1–Q6 hit (alert subject pattern: [CRITICAL] Detection: TraderTraitor -- <behavior> for Q1/Q2/Q3/Q4/Q5, [HIGH] for Q6):

  1. Confirm the endpoint is macOS and record aid / ComputerName / UserName from the hit.
  2. Pull the live process tree via Falcon RTR (ps aux, launchctl list) for the flagged PID/plist entry.
  3. Run Q2, Q5, and Q6 scoped to the same aid to establish full compromise scope (see Pivot A below).
  4. Hash any binary found at the three fake Apple support paths and compare against the Section 4 IOC table.
  5. Enumerate ~/Library/LaunchAgents/*.plist for --type=renderer masquerade entries — preserve, do not delete, for forensics.
  6. If confirmed, network-contain the host via Falcon RTR and proceed to the Containment Runbook (Section 14).
  7. Rotate any AWS/OVH/OpenStack/GitHub credentials reachable from the endpoint.
  8. Escalate to IR lead with the Hunt Summary Ticket (Section 16) populated.

Playbook 1 — Terraform provider registry allowlist

# Playbook 1 -- Terraform provider registry allowlist (local + CI)
# Prerequisites: Terraform >=1.7 CLI; write access to the repo's versions.tf / .terraformrc
# Reboot required: no
# Rollback: remove the provider_installation block from .terraformrc / CLI config; re-run `terraform init` to
#           restore default registry resolution (no state is modified by this control)

cat >> ~/.terraformrc <<'EOF'
provider_installation {
  network_mirror {
    url = "https://registry.terraform.io/"
    include = ["*/*"]
  }
  direct {
    exclude = ["registry.hashicorp-aws.com/*", "registry.hashicorp-aws.io/*", "registry.hashicorp-terraform.io/*"]
  }
}
EOF

# CI gate (example, add to your pipeline before `terraform init`):
