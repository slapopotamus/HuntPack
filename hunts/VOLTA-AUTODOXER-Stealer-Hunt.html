Executive Summary

VOLTA is a Windows infostealer that harvests browser credentials, cookies and payment cards, cryptocurrency wallet seed phrases, Discord, Telegram, Steam and Roblox sessions, Microsoft OAuth tokens, SSH and cloud-provider keys, saved Wi-Fi profiles and screenshots. It then uses stolen sessions to enrich the victim profile (Gmail receipt searches to confirm a home address, UberEats and DoorDash order history, a live Roblox inventory valuation), assembles the result locally as Identity_Report.txt, POSTs it to OpenRouter under a "forensic intelligence analyst" system prompt, and saves the model output as AI_Analysis.txt. Both files leave in volta_dox.zip. The executable then deletes itself.

Talos describes a builder model: the customer supplies a Telegram channel, API keys and settings, and the builder compiles a binary per order. The default model is anthropic/claude-opus-4.6, with a fallback chain to moonshotai/kimi-k2 and then google/gemini-2.5-flash when a response looks like a refusal.

Defensive angle. Every network endpoint Talos observed is a third-party service, so there is nothing to blocklist. Durable detection comes from (1) host artifacts the stealer writes, (2) an unusual process talking to openrouter.ai and rolimons.com, (3) Chrome launched with --headless by an unexpected parent, and (4) fast credential and session revocation after any hit, because the implant deletes itself and the log file may be the only evidence.

Defender priority: treat any hit as a full credential, session and wallet compromise. Preserve %APPDATA%\volta_debug.txt before reimaging, revoke tokens first, and never block openrouter.ai or rolimons.com through an IOC prevent rule: both are legitimate services used by ordinary customers.

Confidence limits: one primary source (Talos). The SHA-256 is single-sourced and ships at detect. Talos does not describe initial access, so delivery is an open gap in this pack.

Q3 · Non-Browser Process Resolving openrouter.ai (LLM API Call From the Endpoint)
CONF MEDFP MEDCOST LOW

Looks for: The AI stage POSTs the identity bundle to the OpenRouter chat completions endpoint from the victim machine itself. OpenRouter is a legitimate service, so the signal is the process, not the domain: a native binary that is not a browser or a sanctioned developer tool. Hardening, Tiered & Deployable

VOLTA is delivered malware with no CVE, so there is no patch. Hardening targets what it relies on (browser secrets, long-lived sessions, execution from user-writable paths) and shrinks the value of what it steals. Controls are anchored to MITRE mitigations from the saved ATT&CK pages plus vendor documentation.

Immediate: this week, no user-visible change
  • Keep Chrome App-Bound Encryption on. Confirm ApplicationBoundEncryptionEnabled is not 0 (Google, Chrome 127 policy). Talos says VOLTA works to bypass ABE; do not hand it a free path. M1051 (T1555.003), M1054 (T1539). Verify with playbook P1.
  • Alert on headless browser launches from non-browser parents (Q5 / IOA). Talos names controlling --headless as the way to block the ABE decryption path. Argument-level launch control needs an EDR rule; native application control does not match on command-line arguments. flag: best-practice, no formal benchmark
  • Pre-stage token revocation. Have the Entra Revoke-MgUserSignInSession procedure ready (P3). M1047 audit, M1032 multi-factor.
  • Preserve evidence. Make capturing %APPDATA%\volta_debug.txt part of the endpoint triage checklist (P4), since the executable deletes itself.
Near term: 1 to 4 weeks, pilot on a ring first
  • ASR audit then block for unproven executables. Microsoft ASR rule "Block executable files from running unless they meet a prevalence, age, or trusted list criterion" (P2). Starts in audit; randomly named per-customer builds are exactly the unproven-prevalence case. Microsoft ASR reference.
  • Shorten web and OAuth session lifetimes and require phishing-resistant MFA so stolen cookies and refresh tokens age out. M1032 (T1539), M1018 (T1555.003).
  • Restrict unsanctioned LLM API egress at the proxy for server and kiosk segments with no AI use, while keeping the Falcon IOC at detect. Note this removes only the AI step: Talos says VOLTA still runs without the LLM stage, so the theft and exfil continue. flag: best-practice, no formal benchmark
  • User training on session and credential reuse for staff who use wallets, gaming and personal accounts on work devices. M1017.
Strategic: 1 to 3 months
  • Move secrets out of browsers into a managed password manager or SSO with hardware-backed keys; Talos recommends hardware-backed credential storage. M1027 (T1555.003).
  • Device-bound sessions and conditional access (token protection, compliant-device requirement) so a stolen token fails off the original machine. M1032, M1021.
  • Separate crypto, gaming and personal accounts from corporate endpoints, and keep seed phrases off disk.
  • Default-deny application control for user-writable paths in managed fleets. flag: best-practice, no formal benchmark in the saved sources.
