Executive Summary

Attacker objective. Solar 4RAYS reports that the Belarus-aligned group it tracks as Partisan Zmiy, also known as the Cyber Partisans, held access to a Russian medical organization for about two years (earliest traces in early 2024, discovered December 2025) without any destructive action [1][2]. Solar assesses the access was kept for espionage and for trusted-relationship attacks against the organization's subsidiary medical institutions, and notes the actors reached domain controllers and central management systems [1][4]. The entry vector was not established [3].

What the intrusion looks like on a host. The actors used a trusted but unused VMware Tools installation as a hiding place. A new custom loader-scheduler, authd.exe, runs as the Windows service vmauad (display name VMware Auth Adapter) and launches other tools from fixed paths on a cron-style schedule: a GOST tunnel every Saturday 22:00 to 23:00, and, once, 480 minutes after the service starts, the Vasilek backdoor (internal version 1.5.8) and a second GOST [1]. Shortly before discovery the genuine vmtools.dll was replaced with an unsigned library and the original kept as vmtoolsd.dll [1]. Vasilek takes commands from, and returns results to, a Telegram group through the public Bot API; DNS tunnels (DNSCat2 and PartisanDNS) and a GOST plus 3proxy chain gave the actors fallback channels [1].

Highest-value defensive angle. Behavior beats indicators here: the actors rotated different tools through the same paths, bind payloads to the host name, and run on a delayed or nightly schedule. The cheapest durable detections are an Authenticode check on every executable in the VMware Tools folder (Solar says this alone would have exposed the loader, GOST and Vasilek binaries and the swapped library), the five masquerading service names, children of the loader, and a Telegram Bot API lookup from a server or an unsigned binary. Atomic indicators (twelve file hashes, nine network domains, nineteen generated domains, three IPs) all trace to Solar's appendix and ship as detect only.

Defender priority. Run Q1, Q2 and Q8 today on every Windows host and server that has VMware Tools or any unused virtualization software installed, and on domain controllers regardless. Solar's own conclusion is that Vasilek on a host almost always means a multi-tool intrusion: also hunt DNS tunnels, proxy chains, lateral movement tools and delayed destructive payloads, because this group is otherwise known for wipers [1].

Scope note. Solar's report mentions the Pryanik wiper, the Evlx event-log clearer, a FortiClient VPN decoy installer and an unrelated phishing malware named HypeAgent in other activity [2]. Those are background only; none of their indicators are in this pack.

Web hunter decisions and discrepancies

  • Publication date. The Solar page itself shows 02.10.2026 and Cyber Security News and Cyberpress covered it on 7 October 2026; The Hacker News ran its summary on 21 October 2026. Reports dated "20 or 21 October" reflect the later press coverage, not the Solar publication date.
  • Corroboration is thin. Sources 2 to 4 all derive from Solar and source 3 reprints its appendix, so the indicators have one originating source. That is why nothing ships at prevent or critical severity (Section 10).
  • Solar contradicts itself on vmtools.dll. The narrative says the replaced library is the Vasilek backdoor; the appendix labels the same hash as loading PartisanDNS. Both are preserved [1][3]. Hunt the file by path and signature, not by assumed payload.
  • The same path hosted different tools. rpctool32.exe appears with two hashes (3proxy and Vasilek) and msadcs32.dll with two PartisanDNS hashes, so a hash alone is not a complete test for a path [1].
  • Solar's ATT&CK label T1574.004 is named "Dylib Hijacking" in the matrix, which is a macOS-oriented technique; for a Windows DLL swap T1574.001 or T1574.002 may fit better. The pack carries Solar's ID and flags this as analyst inference.
  • Excluded as not part of this intrusion: four earlier-known domains Solar lists only for comparison (each differs by one leading character from an incident domain) and the other-campaign tools named in the scope note in Section 1.

Hunt Brief & Attack Chain

Hunt hypotheses (ordered by fidelity)

  1. H1, high. A service named vmauad (or one of four System32 DLL services) exists and runs a binary from the VMware Tools folder or System32 with an odd display name. Techniques T1543.003, T1036.004. Queries Q1, Q2.
  2. H2, high. Unsigned executables with the names authd, vmtoolsd32 or rpctool32 run from the VMware Tools folder, or WsusService.exe runs from UpdateServicesPackages. T1036.005. Q2, Q4.
  3. H3, high. The loader or the masquerade tools spawn children: a shell, a tunnel, a proxy. T1059.003, T1090. Q8.
  4. H4, medium. Files are written into the VMware Tools folder by something other than the installer, including the vmtools.dll swap and Vasilek self-update files. T1574.004 (as labelled by Solar), T1105. Q3.
  5. H5, high. Hosts resolve the published C2 and PartisanDNS domains; non-browser processes query the Telegram Bot API. T1071.004, T1568.002, T1102.002. Q5, Q6, Q7.
  6. H6, medium. Earlier lateral movement used WMI remote execution with output to ADMIN$, and the AppMgmt service parameters were temporarily swapped. T1047, T1021.002, T1569.002. Q9, Q10.

Native Audit-Log Hunts

7.1 Service creation (System log 7045 and Security 4697)

Get-WinEvent -FilterHashtable @{LogName='System'; Id=7045} |
  Where-Object { $_.Message -match 'vmauad|tpvmmon|aweman32|msadcs32|uplay_r164|VMware Auth Adapter|Windows Insiders Service|Windows Channels Service|Sybase Inc\. Product File|Access FT Imager Service' } |
  Select-Object TimeCreated, MachineName, Message

Solar says these creation events remained in the System log after the actors rotated files [1]. Run the same filter against forwarded logs for the longest retention you have.

7.2 Signature sweep of the VMware Tools folder (read-only)

Get-ChildItem 'C:\Program Files\VMware\VMware Tools' -Include *.exe,*.dll -Recurse -ErrorAction SilentlyContinue |
  ForEach-Object { $s = Get-AuthenticodeSignature $_.FullName
    [pscustomobject]@{ File=$_.FullName; Status=$s.Status; Signer=$s.SignerCertificate.Subject; Modified=$_.LastWriteTime; Created=$_.CreationTime } } |
  Where-Object { $_.Status -ne 'Valid' -or $_.Signer -notmatch 'VMware' }

Solar states that signature checking trusted-software folders would have exposed authd.exe, vmtoolsd32.exe, rpctool32.exe and the swapped vmtools.dll [1]. Also list vmtoolsd.dll and *.bak.

7.3 Services whose DLL or binary sits in System32 under an odd name

Get-CimInstance Win32_Service | Where-Object { $_.PathName -match 'VMware Tools\\authd|tpvmmon|aweman32|msadcs32|uplay_r164' } |
  Select-Object Name, DisplayName, PathName, StartMode, State
# Also inspect HKLM\SYSTEM\CurrentControlSet\Services\*\Parameters ServiceDll for unsigned DLLs

7.4 Timestomp and registry timeline checks

Compare file creation time with last-write time and with the installer date for VMware Tools files (Solar saw 29.05.2020 stamped on vmtoolsd32.exe) [1]. Compare the last-write time of HKLM\SYSTEM\CurrentControlSet\Services\AppMgmt with its Parameters subkey: a service key newer than its parameters is the pattern Solar used to infer the swap-and-restore [1].

7.5 SMB and WMI remote execution

Search the Microsoft-Windows-SMBServer/Security log for event ID 1015, which Solar says preserved traces of remote command execution [1]. Search for an empty C:\Windows\__<digits>.<digits> file, the leftover of wmiexec-style output.

7.6 Network, proxy and DNS

  • Resolver and proxy logs: lookups of api.telegram.org from servers and domain controllers; long-poll style requests (about 60 seconds) from non-browser user agents.
  • Solar notes the embedded TLS stack (TLSe with LibTomCrypt) makes the TLS ClientHello likely distinct from browsers and Windows components, so a JA3 or JA4 baseline can single it out [1]. No fingerprint value is published, so build your own from a known sample.
  • DNS analytics: high-volume lookups of one label across many suffixes (the vfvnfaq pattern) and tunnel-like TXT or long-label traffic.

7.7 Sysmon, if deployed

Event ID 7 (image loaded) for vmtools.dll with an invalid signature, event ID 1 for the masquerade process names, event ID 11 for file creation in the VMware Tools folder, and event ID 12 or 13 on the AppMgmt service key. Module load is the one stage the CQL queries below do not cover.
