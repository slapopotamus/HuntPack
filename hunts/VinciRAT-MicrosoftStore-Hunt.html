Executive Summary

Vinci RAT reached a victim through a trusted channel. According to eSentire's Threat Response Unit (published 2026-11-24), a user searching for a snipping tool was redirected to a fake download site that served a Microsoft-signed Store installer, Snipping-Tool.exe. That installer led to the Microsoft Store app Setup Assistant, published by "ETPS Ltd". The app is an Electron program whose main.js is obfuscated with Obfuscator.io. It derives a victim ID, pulls its configuration from its C2, watches the Downloads folder for two installer names, and runs C2-supplied PowerShell or JavaScript.

On the investigated host that access launched a PowerShell stager. The stager disables AMSI by swapping the method handle of ScanContent, hides its window, beacons over the WinHttp COM object, and registers a scheduled task that re-runs the Base64 stager every 10 minutes. The stager pulls Vinci RAT, a PowerShell RAT of roughly 800 lines: host fingerprinting, security-tool discovery, a cmd.exe remote shell, a reverse shell, file staging, and EXE, DLL, PowerShell and shellcode execution, both on disk and in memory. eSentire reports that Microsoft answered its abuse report by saying the app did not violate Store terms.

This pack hunts the behavior first, because the infrastructure is thin (three domains, one IP, seven hashes) and the installer is signed by Microsoft. It ships eleven CrowdStrike CQL queries around the PowerShell command lines, the scheduled task, the AMSI strings, the Store-app-to-PowerShell parent chain and the C2 lookups. All indicators ship as detect; nothing ships at prevent (see s2 and s10).

Defender priority: run Q3 (schtasks creating an encoded-PowerShell task), Q8 (Store app launching PowerShell) and Q5 (campaign DNS) first. A hit means treat the host as remotely controlled: isolate, preserve the scheduled task definition before deleting anything, and remember that uninstalling Setup Assistant does not remove a task that keeps re-running the stager.

Decisions taken from the sources

  • The Store installer is Microsoft-signed. Snipping-Tool.exe and its hash ship at detect. Blocking a Microsoft-signed Store stub by hash adds little (the malicious code is the downloaded app) and risks confusion with the legitimate Store.
  • api.ipify.org is not an IOC. The app queries it for the victim's external IP, but it is shared legitimate infrastructure used by countless tools. It is context only and is never blocked.
  • No scheduled-task name is claimed. eSentire names the 10-minute interval but not a task name, so Q3 matches the task action and no query or IOC here invents a name.
  • Names as the sources write them: "Vinci RAT", "Vinci Backdoor" (eSentire's label for the Electron app's behavior), "Setup Assistant" and the publisher "ETPS Ltd". The pack coins no campaign name and attributes the activity to no actor, because neither source does.
  • Related content on the page is out of scope. The report's subdomain observation (additional lure subdomains for Microsoft Teams and Roblox) is used only to justify matching the registered domain codes-team.com in Q5. No Teams or Roblox indicator is shipped.

Q1 · PowerShell run non-interactively with stdin or EncodedCommand (Setup Assistant execution shapes)
CONF MEDIUMFP MEDIUMCOST LOW

Looks for: powershell.exe launched with -NoProfile -NonInteractive and either -Command - (payload on stdin) or -EncodedCommand. eSentire documents exactly these two command lines as how the Setup Assistant backdoor runs C2-supplied PowerShell. Read the parent: a Store-installed Electron app or an unfamiliar parent is the signal. FP: Management agents, RMM tools and some installers also launch PowerShell this way. Exclude the approved parents after baselining (see TUNING in the card).
