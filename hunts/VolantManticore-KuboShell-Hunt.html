Executive Summary

Volant Manticore is a previously undocumented Iran-nexus espionage group that Check Point Research published on 2026-11-24. Check Point assesses with high confidence that it is Iran-nexus and with medium confidence that it is historically linked to Iran's Ministry of Intelligence and Security (MOIS). It also assesses with medium confidence that the group is a separate spin-off of former MuddyWater operators, not MuddyWater itself. Activity traces to September 2025; the first KuboShell backdoor was delivered in July 2026.

The group's primary target is Cyprus (telecommunications, airlines on Cyprus to Israel routes, critical infrastructure, and a likely government entity). From September 2026 it pivoted to Saudi Arabia with a healthcare focus. Delivery is by phishing: a fake CV from an AI-generated persona linking to a Catbox archive, a macro document in January 2026, and healthcare-themed ZIP archives in September 2026, one sent from a compromised private hospital mailbox. Follow-on access is by legitimate RMM tools (MeshCentral, then NetLock RMM, and N-able RMM in one archive) plus credential-harvesting sites that imitate webmail and an airline ADFS sign-in.

KuboShell is a 64-bit Windows backdoor that uses IPFS through the Pinata pinning service as its command channel. It then runs reconnaissance and downloads the Homa Framework, a three-stage PowerShell and JavaScript chain whose stage 3 is a JavaScript reimplementation of the MuddyC2Go client, talking to 185.205.187[.]109:8000.

Posture: detect only. Check Point is effectively the only technical source for this pack (The Hacker News repeats it). Anything marked prevent needs two independent technical sources, so every row in the Falcon IOC CSV ships as detect. RMM tools, Pinata, IPFS, PowerShell and ssh are legitimate software and are never prevent candidates in any case.

Defender priority: hunt for unsanctioned RMM agents and the Homa and VBA backdoor staging files first (Q5, Q16), then sweep the 69 hashes, 18 IP addresses and 23 hostnames (Q1, Q2, Q3). Credential harvesting and Fortinet VPN access are outside endpoint telemetry: review mail, ADFS and VPN logs (section 7) and reset credentials for anyone who typed them into a lookalike sign-in page.

Decisions and rejected material

  • No second technical source. The secondary article is a restatement of the primary one, not independent corroboration. This is why nothing in this pack is marked prevent.
  • Excluded source. One secondary aggregator was excluded on instruction because it misstates the research (phishing-based initial access for every case, scheduled-task persistence, UAC bypass, GitHub and Ably C2, extra victim sectors that Check Point does not support). It was not fetched, snapshotted, cited or used.
  • Related clusters are prose only. MuddyWater (including MuddyC2Go, PhonyC2 and DarkBeatC2), Nimbus Manticore (UNK_SmudgedSerpent) and the MuddyWater server at 159.198.36[.]115 are mentioned in the report as comparisons. None of their indicators is shipped here.
  • Not published, so not invented. Check Point publishes no IPFS gateway hostname, no content identifier (CID), no scheduled task name, no mutex, and does not publish the hard-coded Pinata token. None appears in this pack. Q11 uses Pinata's vendor domain family as a hunt pattern and says so.
  • Persistence is unknown. The operator sent a persist command, but the report does not say what it does. It also says the VBA backdoor has no persistence of its own. No persistence hunt is claimed.
  • Output file correction. KuboShell does not capture command output: results are uploaded only if the command itself writes to C:\Users\Public\<MAC>re.txt. The outputt2.txt file belongs to the Homa stage 3 backdoor (cmd.exe /c output).
  • Shared file hosts. The Catbox and Dropbox URLs in the report are shared SaaS hosts and are not IOC rows. Catbox is covered by a low-confidence hunt (Q18) only.
  • Victim naming. The report names the airline whose ADFS host is mirrored. This pack describes it as an airline and does not name it.
  • Prompt-injection check. No instruction-like text aimed at an AI agent was found in either fetched page.

Native Audit-Log Hunts

Several steps happen outside endpoint telemetry or in memory. These checks use native logs.

  • PowerShell script block logging (Event ID 4104): search for Add-Type with JScript, Xor-Decode, jsc35 or jsc36, WinHttp.WinHttpRequest.5.1 and a :8000/ URI. The Homa stages run in memory, so this is the strongest log for stages 1 and 2.
  • File creation (Sysmon Event ID 11 or object-access auditing): C:\Users\Public\ files whose name is a MAC address with .log, .txt or re.txt; C:\Users\Public\outputt2.txt; C:\ProgramData\UiAutomation.txt. Check Point shows the VBA backdoor saving downloaded fragments into C:\Users\Public\ under a name supplied by the C2.
  • Registry set (Sysmon Event ID 13): ...\Office\16.0\Word\Security\AccessVBOM set to 1.
  • Process creation (Sysmon Event ID 1 or Security Event ID 4688 with command-line auditing): run the Q5 to Q8, Q14 to Q17 logic. Without command-line auditing most of those queries are blind; see playbook P5.
  • Mail gateway: external mail with a ZIP that contains an executable and a document-themed name (CV, seminar, accreditation). Search for the two Proton senders named in the section 4 note, and for senders that are compromised healthcare mailboxes.
  • ADFS and Exchange / OWA sign-ins: logins that follow a click on a lookalike host (webmail-eac[.]com, federation.aegeneair[.]com, webmail.cabelenet[.]com). Look for new source addresses and impossible travel on accounts that received the lures. Reset credentials where a click is confirmed.
  • Proxy and DNS logs: every lookup of the Q3 domains and every connection to the Q2 addresses, plus Pinata and IPFS gateway traffic from hosts that are not developer machines.
  • Fortinet SSL VPN logs: the report infers, from operator test machines, that the group may use Fortinet SSL VPN to reach victim networks. Review VPN logins from hosting-provider address space and from accounts with no prior history. This is a lead, not a reported victim finding.
  • Triage lookups: check the section 4 hashes in your threat-intelligence platform by hand and record the result in the ticket.

P1 · Attack surface reduction rules, audit mode first

Prerequisites: Microsoft Defender Antivirus active and cloud protection on; Windows 10/11 or Server 2019+. Run on a pilot ring.

P2 · Office: block internet macros and keep VBA object-model access off

Prerequisites: Office 2016 or later (16.0 policy hive). Apply through Group Policy for a fleet; the registry form below is for a pilot user. Confirm the value names against the Office ADMX templates before wide use. Users who rely on internet-sourced macros will be blocked.

P3 · PowerShell script block logging

Reboot required: No

reg query "HKLM\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging" /v EnableScriptBlockLogging

Rollback: reg delete "HKLM\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging" /v EnableScriptBlockLogging /f.

P4 · UAC: automatically deny elevation requests for standard users

Prerequisites: Standard users who legitimately install software must have another route (a software center or a helpdesk). Pilot with a small ring; this is a CIS benchmark recommendation.
Reboot required: No (takes effect at next elevation request)

reg add HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System /v ConsentPromptBehaviorUser /t REG_DWORD /d 0 /f

P5 · Command-line process creation auditing

Prerequisites: Local or Group Policy edit rights. Event volume rises on busy servers; size the Security log.
Reboot required: No

reg add HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\Audit /v ProcessCreationIncludeCmdLine_Enabled /t REG_DWORD /d 1 /f

Rollback: reg delete HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\Audit /v ProcessCreationIncludeCmdLine_Enabled /f and auditpol /set /subcategory:"Process Creation" /success:disable.

P6 · Program-scoped outbound block for ports 8000 and 25498 (PowerShell and Word)

Prerequisites: Windows Defender Firewall managed locally or through Group Policy. Developers who run test servers on port 8000 reach them from PowerShell; pilot on non-developer hosts first and exempt private ranges if needed.
Reboot required: No

New-NetFirewallRule -DisplayName 'Block PowerShell outbound 8000 and 25498' -Direction Outbound -Action Block -Protocol TCP -RemotePort 8000,25498 -Program "$env:SystemRoot\System32\WindowsPowerShell\v1.0\powershell.exe"

Rollback: Remove-NetFirewallRule -DisplayName 'Block PowerShell outbound 8000 and 25498' and the Word rule. The Word path assumes a click-to-run Office 16 install; adjust it for your build.

Honest gaps

  • Persistence is unknown. The persist command is not described and the VBA backdoor has none. No scheduled task, run key or service name is published, so none is hunted.
  • IPFS command channel is hard to see. Check Point does not publish the gateway hostname, a CID or the Pinata token, and the traffic is TLS to a legitimate service. Q11 relies on the vendor domain family, not a published indicator.
  • In-memory stages. Homa stages 1 to 3 run from memory. Endpoint command-line hunts catch only the stager launch; script block logging (section 7) is the better source.
  • Text staging files are not PE files. File-write telemetry for executables does not record them. Q5 reads them from command lines instead; Sysmon Event ID 11 covers the rest.
  • Credential harvesting, mailbox compromise and Fortinet VPN use are outside endpoint telemetry (section 7).
  • Unrecovered modules. Check Point could not recover the additional modules Homa stage 3 runs, so post-exploitation behavior beyond recon is not described.
  • Single technical source. Every indicator is detect for that reason.
