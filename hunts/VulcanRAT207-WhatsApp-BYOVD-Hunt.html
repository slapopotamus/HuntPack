Executive Summary

Attacker objective: remote, interactive control of Windows endpoints with SYSTEM authority, after first blinding the endpoint security products installed on them. Morphisec (Shmuel Uzan, published 2026-10-07) traces a multi-stage intrusion that starts with a financial-document lure, reportedly delivered over WhatsApp as Statement.exe inside a ZIP, and ends in a WebSocket remote access trojan that Morphisec tracks as VulcanRAT207.A. The Hacker News ThreatsDay bulletin of the same week summarizes the report.

How it works: the loader screens the host, attempts elevation, then uses PoolParty Variant 7 to place a downloader inside the Task Scheduler service host without CreateRemoteThread. Everything that follows inherits that LocalSystem token. A deployment DLL then does three things: it installs the signed GoFly64.sys driver and sends it the process IDs of Baidu security processes (bdservicehost.exe, bduserhost.exe) so the driver kills them from ring 0; it starts the RAT directly from memory; and it writes a persistent Vulkan DLL side-loading package (vulkaninfo-64.exe, vulkan-1.dll, vulkan-1.bin) to C:\Program Files\Common Files with a SYSTEM scheduled task named USOPrivate Kit or USOPrivate to bring the RAT back.

Commodity tooling, handled accordingly: GoFly64.sys is a legitimately Authenticode-signed Chinese network-filter driver, catalogued on LOLDrivers and abused by unrelated actors. vulkaninfo-64.exe is a genuine Intel-signed Khronos build, and its hash is shared with a separate package (port 1234) that this pack does not cover. Neither is a unique marker of this campaign, so both ship detect only, matched by behavior and placement rather than by identity.

Defender angle: the durable signals are the component boundaries Morphisec recommends correlating: a Vulkan host sitting in Common Files, a USOPrivate SYSTEM task, a tp_-named driver staged under System32\drivers, and the VulkanInfo process making network connections or spawning children. The hard parts are blind to a host sensor: the PoolParty injection into Task Scheduler, the memory-resident RAT, the GoFly IOCTL itself, and the Windows Filtering Platform filters. The Coverage Map flags each as a gap.

Scope: this pack covers the Statement.exe and VulcanRAT207.A chain only. Morphisec describes a related port 1234 package leading to RomulusLoader and a different RAT as a separate follow-up article. No RomulusLoader indicator is shipped here.

Defender priority: run Q1, Q3, Q4, Q5, Q6 and Q12 over 30 days first (near-zero FP, no indicator dependency). Run Q13 for host-level correlation. Then enable the ASR rule that blocks abuse of exploited vulnerable signed drivers in audit mode (section 12, I1).

Web Hunter decisions and discrepancies

  • Delivery channel is hedged by the source. Morphisec says the lure "reportedly" arrived over WhatsApp as a ZIP attachment. This pack repeats the hedge and does not state WhatsApp delivery as confirmed.
  • The Hacker News adds no indicators. Its section is a paraphrase of Morphisec, so no IOC counts as two-source on its strength. The only item with a genuine second source is GoFly64.sys (LOLDrivers), and it is commodity tooling, so it ships hunt only.
  • The VulkanInfo host hash is shared. Morphisec states the hash is shared with the separate port 1234 package. It identifies a stock Intel-signed binary, so it is used only together with SYSTEM context (Q2) and is not imported as an IOC.
  • Unverified blocklist status. No fetched source states whether GoFly64.sys is on Microsoft's vulnerable driver blocklist. The hardening section therefore says to test it in audit mode rather than assuming coverage.
  • HVCI wording. LOLDrivers records the sample as HVCI FALSE with no sample confirmed loading despite HVCI. The pack treats that as encouraging but unproven for your fleet.
  • Related cluster excluded. The port 1234 package and RomulusLoader are explicitly out of scope; no indicator for them is shipped.
  • Page extras ignored. The Morphisec and Hacker News pages carry navigation, promotional and unrelated-news text (including a bulletin item about prompt injection in phishing emails). None of it was addressed to this agent, none asked for any action, and none was used.
  • No injected instructions. Every fetched page was scanned for text directed at an automated agent. None was found.

07

Native Audit-Log Hunts

Hunts that need no CQL. Several are the only way to see stages the Falcon sensor cannot.

N1 · Filesystem and task sweep (read-only)

Run on any suspect host or through RTR. It checks for the Vulkan trio, the staged driver, the USOPrivate task and tp_ services.

# Vulkan side-load package under Common Files
Get-ChildItem 'C:\Program Files\Common Files' -Include vulkaninfo-64.exe,vulkan-1.dll,vulkan-1.bin -Recurse -Force -ErrorAction SilentlyContinue |
  Get-FileHash -Algorithm SHA256 | Select-Object Path, Hash

# Staged driver files and tp_ driver services
Get-ChildItem "$env:WINDIR\System32\drivers" -Filter 'tp_*.tmp' -Force -ErrorAction SilentlyContinue | Select-Object FullName, Length, LastWriteTime
Get-CimInstance Win32_SystemDriver | Where-Object { $_.Name -like 'tp_*' -or $_.PathName -like '*\drivers\tp_*.tmp' } | Select-Object Name, State, StartMode, PathName

# USOPrivate scheduled task or any task running the Vulkan host
Get-ScheduledTask | Where-Object { $_.TaskName -like '*USOPrivate*' -or ($_.Actions.Execute -like '*vulkaninfo-64.exe') } |
  Select-Object TaskPath, TaskName, @{n='Run';e={$_.Actions.Execute}}, @{n='User';e={$_.Principal.UserId}}

N2 · Windows event cross-reference

  • Security 4698 (scheduled task created, needs auditing on): task name containing USOPrivate under \Microsoft\Windows or \Microsoft\Windows\AppID.
  • System 7045 (service installed): service name tp_ followed by digits, image under System32\drivers ending .tmp, type kernel driver, start type system.
  • CodeIntegrity Operational: a load or audit of GoFly64.sys or a .tmp driver image. Event 3099 only confirms that a block policy is active (Microsoft Learn).
  • Sysmon (if deployed): Event ID 6 (driver loaded) for GoFly64.sys, Event ID 1 for vulkaninfo-64.exe with a SYSTEM user, Event ID 7 (image load) of vulkan-1.dll from Common Files by vulkaninfo-64.exe, Event ID 17 or 18 for pipe <PID>_pipe.

N3 · Mutex and pipe hunt on a live host

With a handle-enumeration tool, look for the mutexes Global\Admindllhost!!! and one starting with analplug, and for a named pipe called <PID>_pipe where the number equals its owning process ID. These are runtime artifacts and are not visible in CQL.

N4 · Network hunt for TCP 8888

In firewall or NetFlow data, search for the C2 address on any port, then for long-lived TCP sessions from SYSTEM-context processes to unfamiliar public hosts on 8888 that start with an HTTP request and continue as WebSocket frames. Without TLS, an HTTP Upgrade: websocket to a bare IP is a strong signal; this is behavior drawn from the report's description and should be validated on your sensors.

N5 · Security product health check

The chain kills security processes. For each managed endpoint, alert on a security-product service or process that stopped without an administrator action, and compare it to sensor heartbeat gaps. This applies to any EDR or AV, not only the Chinese products Morphisec names.

Q1 · vulkaninfo-64.exe running from Program Files\Common Files
CONF HIGHFP LOWCOST LOW

Looks for: the signed VulkanInfo host launched from C:\Program Files\Common Files\. Morphisec reports that the deployment DLL writes vulkaninfo-64.exe there and registers a SYSTEM task that runs it so it side-loads vulkan-1.dll. VulkanInfo is a Khronos diagnostic tool normally found in a Vulkan SDK folder, not in Common Files. FP: none expected. The binary is legitimate, so this query matches the placement, never the hash alone.

Hardening: Tiered

Controls are mapped to the technique, then to a MITRE mitigation (the why) and a vendor authority (the what and where). The chain's decisive step is loading a signed vulnerable driver, so the first tier is about stopping the driver from landing and loading.

Immediate (this week, low compatibility risk)
  • I1 · ASR rule "Block abuse of exploited vulnerable signed drivers" in Audit mode first, then Block. It prevents an application from writing a vulnerable signed driver to disk, which is how the deployment DLL and the RAT stage the driver. Microsoft states the rule does not block a driver already on the system from loading. Addresses T1068. M1038 Execution Prevention, M1050 Exploit Protection. Authority: Microsoft Learn, recommended driver block rules and ASR rules reference (GUID 56a863a9-875e-4185-98a7-b882c64b5ce5; audit action type AsrVulnerableSignedDriverAudited). Playbook P1. Whether GoFly64.sys is covered by Microsoft's list was not confirmed by any fetched source, so verify in audit mode.
  • I2 · Microsoft vulnerable driver blocklist and HVCI. Microsoft states the blocklist is on by default on Windows 11 2022 and later and is enforced when memory integrity (HVCI), Smart App Control or S mode is active. Confirm it is on across the fleet, and for older builds apply the recommended block policy via App Control for Business, audit first. M1038, M1051 Update Software. Authority: Microsoft Learn driver block rules. Playbook P2. LOLDrivers records no sample of GoFly64.sys confirmed loading despite HVCI; validate on your hardware.
  • I3 · Audit scheduled task creation and service installation so a SYSTEM task such as USOPrivate and a tp_ driver service leave a trail even when the sensor is killed. M1047 Audit. Authority: MITRE T1053.005 and T1543.003 mitigation lists. best-practice, no formal benchmark cited Playbook P3.
  • I4 · Load the section 10 CSV into IOC Management as detect and run Q8 and Q10 retrospectively. Detection, not prevention, listed because it is free and immediate.
  • I5 · Alert on security-product tamper (stopped service, missing sensor heartbeat). The chain's first goal is to kill security processes. M1047 Audit. best-practice, no formal benchmark
Near term (1 to 4 weeks, pilot first)
  • N1 · ASR rule "Block executable files from running unless they meet a prevalence, age, or trusted list criterion" in audit mode, to catch the unknown freshly dropped Statement.exe and wrapper. M1038 Execution Prevention. Authority: Microsoft Learn ASR rules reference (GUID 01443614-cd74-433a-b99e-2ecdc07bfc25; requires cloud-delivered protection). Expect developer-build noise. Playbook P4.
  • N2 · Restrict chat-delivered executables on managed endpoints: block or quarantine executable and archive attachments from consumer messaging apps, or disallow the apps on corporate devices. Delivery is reported rather than confirmed, so treat this as risk reduction. M1017 User Training and M1038, per the T1204.002 context. best-practice, no formal benchmark
  • N3 · Egress control: alert on outbound connections to unfamiliar public addresses on TCP 8888 from SYSTEM-context processes, and on the published C2 address. Alert rather than block until a second source confirms the address. best-practice, no formal benchmark
  • N4 · Application control for DLL side-loading: allow-list signed binaries by path so a signed utility running from Common Files is flagged or blocked. M1038, M1044 Restrict Library Loading, M1013 Application Developer Guidance. Authority: MITRE T1574.001 mitigation list. best-practice, no CIS item cited
  • N5 · Local administrator and privileged account hygiene so that a lure run by a standard user cannot reach SYSTEM via COM auto-elevation prompts. M1026 Privileged Account Management. Authority: MITRE T1053.005 and T1055 mitigation lists.
Strategic (1 to 3 months)

Block driver loads that are not on an approved list rather than chasing individual bad drivers. M1038, M1048 Application Isolation and Sandboxing. Authority: Microsoft Learn driver block rules.   • S3 · Tamper protection and out-of-band sensor health monitoring, so a killed agent is noticed within minutes. M1047 Audit. best-practice, no formal benchmark
  • S4 · Threat intelligence for drivers: subscribe to the LOLDrivers feed and review new entries against installed drivers. M1019 Threat Intelligence Program. Authority: MITRE T1068 mitigation list.

Treat the host as fully compromised, assume the endpoint sensor may be dead or lying, and confirm host state with out-of-band tools. The RAT has keylogging, clipboard replacement and local account creation, so treat every credential typed on the host as exposed.
