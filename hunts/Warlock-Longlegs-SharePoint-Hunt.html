Executive Summary

The attacker's objective in this campaign is domain-wide ransomware detonation launched from a single exploited internet-facing SharePoint Server. Longlegs (tracked by Microsoft as Storm-2603, with older activity linked to CL-CRI-1040, CamoFei and ChamelGang) exploits on-premises SharePoint vulnerabilities, drops a webshell into the LAYOUTS directory, steals the farm's ASP.NET machine keys, and forges a validly signed __VIEWSTATE payload to get code execution inside the SharePoint application pool. From there the group pivots through living-off-the-land recon, DLL side-loading, a masquerading domain account, NetExec-driven AD enumeration, and finally a BYOVD defense-evasion stage before staging Warlock ransomware in the domain's SYSVOL share for replication to every domain controller.

Symantec's Threat Hunter Team (security.com, published 1–2 Oct 2026) documented at least four victims over the preceding two months: a water utility, a telecommunications provider, a regional government body and a university, concentrated in Portuguese- and Spanish-speaking countries across Europe, Africa and Latin America. In one intrusion the actor disabled security tooling on at least 40 hosts within about two hours, then deployed Warlock on at least 33 hosts.

The single highest-leverage defensive angle in this pack is the Visual Studio Code Insiders tunnel-as-a-service technique: it is the most distinctive persistence/C2 mechanism in the campaign, it rides on a Microsoft-signed binary and Microsoft's own relay infrastructure, and it is unlikely to be present at all on a SharePoint farm member or domain controller in most environments, making it one of the cleanest high-fidelity signals available. The BYOVD stage and the SYSVOL-staged ransomware execution are the two steps immediately before mass detonation and deserve equal priority.

Defender priority: hunt and alert on code-insiders.exe tunnel-service installs and on vulnerable-driver loads (K7RKScan / CVE-2025-1055-class) on any host that is not a known developer workstation. In the documented intrusion, the gap between the defense-evasion stage and domain-wide ransomware execution was roughly two hours, which is the entire available response window.

Hunt Brief & Attack Chain

Hunt Hypotheses

  1. H1 — Initial access/execution: SharePoint ToolShell-class exploitation drops a webshell and triggers a deserialization gadget under the SharePoint worker process. (T1190, T1505.003, T1059.001 · high confidence)
  2. H2 — Tool ingress: Follow-on payloads are pulled via msiexec from public object-storage/paste services. (T1105 · high confidence)
  3. H3 — Defense evasion via side-loading: DLL side-loading pairs are staged outside standard install directories to run without a flagged standalone binary. (T1574.002 · medium confidence)
  4. H4 — Recon & masquerade: Living-off-the-land recon runs from the SharePoint worker process, and a masquerading setup-style account is added to local Administrators. (T1087.002, T1482, T1098.007 · medium-high confidence)
  5. H5 — OOB canary beaconing: Out-of-band DNS callbacks to a Burp-Collaborator-style domain confirm RCE. (T1071.004 · medium confidence, dual-use infrastructure)
  6. H6 — Covert C2/persistence via VS Code tunneling: VS Code Insiders is installed as a Windows service to open a Microsoft-signed remote tunnel. (T1219, T1543.003, T1036 · high confidence — most distinctive signal in this campaign)
  7. H7 — Lateral movement: NetExec drives AD enumeration and credential spraying ahead of domain-wide staging. (T1087.002, T1110.003, T1021.002 · high confidence)
  8. H8 — BYOVD defense evasion → domain-wide ransomware: A vulnerable signed driver disables security tooling at kernel level, immediately followed by Warlock staged through SYSVOL/DFSR replication. (T1068, T1562.001, T1072, T1486 · high confidence)

Native Audit-Log Hunts

Non-CQL checks that close the gaps Falcon process telemetry alone cannot reach:

  • IIS / SharePoint ULS logs: search for anomalous POST requests to /_layouts/15/ or /_vti_bin/ endpoints carrying large base64 payloads or abnormal response codes, correlated to the exploitation window.
  • Windows Security Event ID 4697/4698/7045 (service installed): cross-reference against Falcon's CreateService event for the code-insiders.exe tunnel; Windows Event Forwarding is a useful independent confirmation channel where deployed.
  • SharePoint machineKey / web.config change auditing: file-integrity monitoring on every farm member's web.config, alerting on any modification timestamp outside a planned change window.
  • DNS resolver / proxy logs: lookups for *.oastify.com, *.wasabisys.com, and *.catbox.moe originating outside approved developer or security-testing source ranges.
  • AD "Restricted Groups" / local administrators drift report: any account matching an SPS*Setup / SP*PRDSetup naming pattern added outside a documented patch or farm-configuration window.
  • SYSVOL file-integrity monitoring: alert on any new, unexpected file under \SYSVOL\<domain>\scripts\ on any domain controller.

Q1 · SharePoint LAYOUTS webshell write
CONF HIGHFP LOWCOST LOW

Looks for: a PowerShell or SharePoint-worker-parented process writing an .aspx file into a LAYOUTS path via WriteAllBytes. FP: low — legitimate SharePoint solution (.wsp) deployment through stsadm/Install-SPSolution does not use ad-hoc WriteAllBytes PowerShell against the layouts path.

// HUNT: SharePoint LAYOUTS webshell write via WriteAllBytes
// MITRE: T1190, T1505.003, T1059.001
// CONF: high  FP: low  COST: low
// REQUIRES: Falcon sensor on SharePoint front-end/app servers (ProcessRollup2)
// FALSE POSITIVES: legitimate .wsp solution deployment via stsadm/Install-SPSolution does not use ad-hoc WriteAllBytes PowerShell against the layouts path
#event_simpleName = /ProcessRollup2|SyntheticProcessRollup2/
| ParentBaseFileName = /^w3wp\.exe$/i or FileName = /^powershell\.exe$/i
| CommandLine = /WriteAllBytes/i
| CommandLine = /layouts/i
| CommandLine = /\.aspx/i
| table([@timestamp, aid, ComputerName, UserName, ParentBaseFileName, FileName, CommandLine])
