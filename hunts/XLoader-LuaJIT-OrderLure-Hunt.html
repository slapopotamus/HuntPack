Executive Summary

Attacker objective: deliver XLoader, an infostealer in the FormBook lineage, through business-themed email (order, payment and quotation lures in Greek, Slovenian and English). The reported capabilities include browser and Windows Vault credential collection and cookie-record preparation. The same campaign infrastructure also delivered Agent Tesla, Remcos and XWorm.

Chain in one paragraph: a RAR or ZIP attachment holds one obfuscated JScript. Windows Script Host runs it, it tries to blank its own Zone.Identifier stream, and it writes an x86 LuaJIT-compatible interpreter and an extensionless Lua file to the user's Documents folder, then starts the interpreter hidden. The Lua loader zeroes AMSI strings, tries to disable twelve ntdll tracing and thread functions, decodes a packed PE32, and runs the XLoader core inside the LuaJIT process. The core then injects a clone of itself into a suspended SysWOW64 host through a shared section with x86 thread-context redirection. Morphisec is explicit that this is not process hollowing.

Highest-value defensive angle: the early, on-disk steps are the most reliably observable: the script host started from an extracted archive, a Documents-resident executable started by that script host, and an odd 16-letter parent creating a candidate injection host. The in-process patching and the shared-section mapping have little or no endpoint event, so they are listed as gaps rather than covered with a guessed query.

Command-and-control caveat: the sample's 16-entry endpoint list includes decoys and the report does not name the real C2. This pack ships the list as a labelled mixed list at detect/low and asserts no live C2.

Defender priority: stop the script host from running archive-delivered .js files (ASR, WSH disablement, mail-gateway script and archive controls), then alert on a script host launching an executable from Documents (Q2). Do not block the SysWOW64 host binaries: they are legitimate Windows files.

Deployable Playbooks

P1 · Disable Windows Script Host (machine-wide)

Prerequisites: confirm no business process relies on wscript.exe or cscript.exe (check Q1/Q2 hit history and login-script inventory). Pilot on one ring first.
Reboot required: no. Takes effect for new script launches.
1. Run elevated:
   reg add "HKLM\SOFTWARE\Microsoft\Windows Script Host\Settings" /v Enabled /t REG_DWORD /d 0 /f
2. Verify:
   reg query "HKLM\SOFTWARE\Microsoft\Windows Script Host\Settings" /v Enabled
Rollback: reg delete "HKLM\SOFTWARE\Microsoft\Windows Script Host\Settings" /v Enabled /f

P2 · ASR rules for script and email-delivered content (audit first)

Prerequisites: Microsoft Defender Antivirus active and real-time protection on; run in audit for at least one week before block.
Reboot required: no.
1. Audit mode (AuditMode = 2):

2. Review Defender operational events for blocked-would-have-been items, add exclusions for approved tooling.
3. Enforce (Enabled = 1):
   Set-MpPreference -AttackSurfaceReductionRules_Ids d3e037e1-3eb8-44c8-a917-57927947596d,5beb7efe-fd9a-4556-801d-275e5ffc04cc,be9ba2d9-53ea-4cdc-84e5-9b1eeee46550 -AttackSurfaceReductionRules_Actions Enabled,Enabled,Enabled
4. Verify:
   Get-MpPreference | Select-Object AttackSurfaceReductionRules_Ids, AttackSurfaceReductionRules_Actions

P3 · Exchange Online transport rule for script attachments (audit first)

Prerequisites: Exchange Online PowerShell connected with transport-rule rights; mail owner agrees to audit period.
Reboot required: no.
1. Create in audit mode:
   New-TransportRule -Name "HuntPack script attachments" -AttachmentExtensionMatchesWords "js","jse","wsf","vbs","vbe" -Quarantine $true -Mode Audit
2. After review, enforce:
   Set-TransportRule -Identity "HuntPack script attachments" -Mode Enforce
3. Verify:
   Get-TransportRule -Identity "HuntPack script attachments" | Format-List Name,Mode,State
Rollback: Remove-TransportRule -Identity "HuntPack script attachments"
Note: this rule inspects attachment extensions on the message; a script inside a RAR is only seen if your gateway unpacks archives. Check that separately.
