Executive Summary

Attacker objective. Yoba is a Windows malware chain that Check Point Research tracked for about two months and published on 2026-10-27. The operator creates GitHub repositories and GitHub Pages sites that advertise desktop apps for new AI products (lure names GPT-5.6 Sol, GPT-6 Astra and Claude Opus), ranks them in Google by what Check Point assesses as SEO poisoning, and hosts the malware as an unprotected ZIP release. Each ZIP pairs a legitimate, signed OpenAI or Anthropic Setup.exe with a malicious winmm.dll that the signed program loads (DLL sideloading). [#1] [#2]

The chain. The DLL (YobaDropper) checks that its host is named Setup.exe, skips CIS keyboard layouts (Ukrainian is not excluded), and needs administrator rights. It then writes a copy of the Windows file WMPDMC.exe and the loader (YobaLoader, saved as wmpdui.dll) into ProgramData\WMProcess and registers a SYSTEM scheduled task that starts the copy 3 minutes after boot. The loader reads the profile picture of a Telegram channel, derives a domain from the image, asks Google DNS-over-HTTPS for a signed and encrypted TXT record, and downloads the payload from Catbox. The payload observed was XMRig 6.26.0 injected into svchost.exe, mining through Tor and pausing while the user is active. [#1] [#2]

Why it matters. The loader is generic: it can run any Windows executable or PowerShell script the operator signs and sends, so the miner is only the first payload seen. Check Point advises treating a Yoba infection as a broader compromise, not a cryptominer cleanup. The signed OpenAI and Anthropic files are real vendor binaries; Check Point found no sign that OpenAI, Anthropic, ChatGPT or Claude were compromised. A valid signature vouches for one file, not for the DLL sitting next to it. [#1] [#2] [#3]

What is different from the common summary. The roughly 12.73 day delay (200,000 iterations of Sleep(5500)) runs when the host process is not named Setup.exe, which is the sandbox and standalone-run branch, not the normal path. In a real infection the dropper and the loader's first callback are separated by the time to the next reboot, because the task fires 3 minutes after boot. The pack therefore hunts the stage pairing (Q11), not a fixed 12 day gap. [#1] [#2]

Defender priority. (1) Alert on any winmm.dll outside the Windows system folders next to a Setup.exe, and on any WMPDMC.exe or wmpdui.dll outside the Windows and Media Player folders (Q2, Q3, Q5, Q6, Q12). (2) Never block on the signed OpenAI or Anthropic executables, on winmm.dll or WMPDMC.exe by name, on svchost.exe, on Telegram, Google DoH or Catbox, or on stock XMRig: all are legitimate software or services that Yoba abuses. (3) Every indicator comes from one vendor report, so everything ships as detect.

Decisions

  • No independent second source. Sources 2 to 5 all derive from source 1. A search for a second vendor analysis of Yoba returned only press coverage of the Check Point report. Under the two-independent-sources rule nothing in this pack ships as prevent or critical: every indicator is detect or hunt.
  • Legitimate software stays out of the block list. The signed OpenAI and Anthropic executables, winmm.dll, WMPDMC.exe, svchost.exe, Telegram, Google DNS-over-HTTPS, Catbox, GitHub, dedyn.io and stock XMRig are real software or services. They appear as hunt context only.
  • SHA-1 only. Check Point publishes SHA-1 hashes and no SHA-256. Falcon IOC Management does not import SHA-1, so the hashes are in their own copy block (section 10) and in Q1.
  • Names. The names Yoba, YobaDropper, YobaLoader and XMRig are Check Point's own and appear in the snapshots. No actor or cluster name is used. Check Point says the actor shows indicators of Russian origin and works mostly in UTC-4; that is its assessment, not an attribution, and the pack does not name a group.
  • Fetched content was treated as data. No instruction-like text was found in any cited snapshot.
